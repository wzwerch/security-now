# Rust and memory safety adoption

# Overview

Growing official pressure to move away from memory-unsafe code.

# Timeline

* **#744 (2019-12-10)** — A Microsoft engineer reports a positive Rust experience and Steve contrasts it with PHP's unsafe defaults. ([source](../sources/sn-0744.md))
* **#752 (2020-02-04)** — Steve predicts languages that do not hand programmers raw pointers will take over. ([source](../sources/sn-0752.md))
* **#889 (2022-09-20)** — Chrome's MiraclePtr aims to neutralise about half of use-after-free bugs. ([source](../sources/sn-0889.md))
* **#892 (2022-10-11)** — Leo says Rust in the Linux kernel is good news. ([source](../sources/sn-0892.md))
* **#894 (2022-10-25)** — Google's Rust-based KataOS on seL4 shows provably secure design. ([source](../sources/sn-0894.md))
* **#895 (2022-11-01)** — Ian Levy marks 50 years of memory safety bugs; UK funds a memory-safe processor. ([source](../sources/sn-0895.md))
* **#897 (2022-11-15)** — NSA advisory urges C#, Go, Java, Ruby, Rust or Swift over C/C++. ([source](../sources/sn-0897.md))
* **#900 (2022-12-06)** — Android 13 is the first release with mostly memory-safe new code; memory bugs fall by more than half. ([source](../sources/sn-0900.md))
* **#906 (2023-01-17)** — Chromium's Rule of Two explained; third-party Rust libraries to be supported in production. ([source](../sources/sn-0906.md))
