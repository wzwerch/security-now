# SQRL

# Summary

Occupies recurring news: OWASP tour talks, documentation completion, WordPress, PAM and .NET implementations, a Google mention and the November 30 studio presentation.

In these episodes Steve describes SQRL's server side completion, installer work, alternative identities, client-provided session login to defeat phishing, and an option asking sites to disable other account recovery.

Discussed throughout as a solution where sites hold no secrets: client-provided session via localhost defeats man-in-the-middle spoofing, optional flags can forbid account recovery, many-to-one identity mapping handles shared access, and the signed installer/updater was finished in this period. Steve was close to release by August 2017.

SQRL gives websites no secrets to keep; episodes mention its rescue code, quick-pass design, spoof-resistant dialog and WINE compatibility ahead of release.

SQRL gives websites no secrets to keep. In March 2018 Steve described its sensitive-data monitor, high-DPI scaling, Quick Pass feature, and plans for web forums and a TWiT studio launch before returning to SpinRite 6.1.

SQRL lets a user sign a server-provided one-time challenge with a per-site key derived from a master identity, so servers store only public keys and nothing replayable. In 2018 Steve was building XenForo-based SQRL forums, a generic Service Provider API, a third demo site and a managed-shared-access feature, and used news such as the MEGA extension and Facebook token breaches to argue for it.

SQRL lets a user log in by scanning or clicking a QR code, deriving a site-specific key from one master identity so sites hold no secret to steal. In these episodes Steve moved identity management into the client, ran live demos logging into pages from a phone and an iPad, noted Yubico interest, and contrasted it with FIDO.

Episode 516 walks through the protocol (HMAC-derived per-site keys, rescue code, EnScrypt, identity lock and rekeying); later episodes discuss its limits and an unspoofable design.

During late 2015 the protocol and storage format were finalized, documentation rewritten and other client authors waited; a local-app login extension was designed but deferred; recovery uses a 24-digit rescue code.

In 2016 Steve extended the identity format to hold four previous keys, used Dan Bernstein's cryptography with no secret-dependent execution paths, and noted SQRL's IP binding defeats man-in-the-middle relay. iOS and Android clients and a demo server were in progress.

Steve compares SQRL with passkeys, noting it needs no per-site key backup and also identifies the user.

Clients for Windows, iOS, Android and browsers matured through 2019 as the forums served as test site.

Introduced 424; per-site keys derived from one master key; 425 Q&A; 426 previous-key revocation and Enforce IP check; 427 identity unlock key design.

Renamed Secure Quick Reliable Login; Identity Lock protocol; syntax and semantics finalised in December 2013; Scrypt-based EnScrypt password handling; Steve writing the client in assembler; compared with FIDO's U2F.

In early 2014 Steve finished the UI design, started coding, built the entropy harvester and crowd-translated the interface into dozens of languages; he contrasts it with FIDO U2F/UAF and notes servers keep no secrets.

These episodes cover SQRL's entropy harvester, GCM storage format, translators, the hint quick re-authentication, the password strength meter, test clients including Ralf's Android client and the printable identity QR code.

Progress on the Windows client (webcam QR import), a demo login page, drop-in server libraries, and Steve's first public SQRL talk, where a FIDO architect praised it. Steve contrasts SQRL with FIDO U2F, which stores wrapped keys at websites.
