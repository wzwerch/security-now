# Summary

After catching up on news, Steve organizes the episode around four unrelated cases of security done wrong. Adobe patched a Flash zero-day used by the Pawn Storm campaign within days, and SourceDNA found that a Chinese ad SDK (Youmi) had gotten hundreds of App Store apps to call restricted iOS APIs by hiding the function names, which Apple's static screening could not catch. The four "doing it wrong" cases are: 1Password's AgileKeychain storing item names and URLs unencrypted for performance reasons; a Target store PA system that anyone could reach by phone, leading to repeated prank broadcasts; chip-and-PIN cards whose PIN check is separate from data retrieval so a thin shim can answer "yes" to any PIN; and Sandboxie support telling users to disable Windows updates after a Patch Tuesday kernel change broke the product. Steve also explains why he likes pfSense routers, plus SpinRite testimonials, movie and book comments, and a SQRL status update.

# Key points

- Flash: after the October patch, a new Flash zero-day used in spearphishing (attributed to the Pawn Storm campaign by Trend Micro) was fixed by Adobe within days; Chrome and IE update Flash automatically, Firefox users should check manually.
- Youmi SDK on iOS: restricted APIs were called via strings obfuscated at runtime, evading Apple's scan for forbidden names. Behaviors grew from reading the frontmost app to enumerating installed apps, device serials and the Apple ID. Apple removed several hundred apps and had earlier hardened the serial-number API. Steve and Leo argue protected calls should enforce privilege checks at runtime and that App Store vetting cannot be relied upon.
- 1Password's AgileKeychain/1PasswordAnywhere: item titles and URLs are stored unencrypted, so anyone who can fetch the keychain folder (and some people had it indexed by Google) sees sites and sometimes reusable reset links. AgileBits said it was by design for search performance; Steve notes a fully encrypted format existed since 2012 but was not default, and says he will not use the product.
- Target: store PA systems were reachable as a phone extension, which outsiders could be transferred to; explicit audio was played at least four times since April, once causing an evacuation. Steve compares it to attaching an internal network directly to the internet.
- Chip-and-PIN: the card only confirms whether the PIN is right and the terminal reads data separately, so a thin overlay on a stolen card's contacts can fake PIN verification. Steve says a better design would use the PIN to derive a decryption key with delay against brute force.
- Sandboxie: it hooks kernel-level API calls; an October Windows kernel patch broke it and support suggested turning off automatic updates and disabling Flash protected mode. Steve calls this the wrong answer; Leo notes Windows 10 upgrades force updates.
- Western Digital drive encryption (My Passport) was reported by researchers as weak; deferred to next week.
- pfSense: free FreeBSD-based router firewall with flexible NAT, bandwidth control and OpenVPN; Steve runs it on a Soekris board with an OpenVPN tunnel to GRC and recommends it to power users, with pre-built hardware also sold by the project.
- Slow computers: drives that silently retry bad reads cause slowdowns; SpinRite often restores speed (several listener reports).
- SQRL: storage format and protocol are final; corporations are asking to use it internally since it can coexist with traditional login.
