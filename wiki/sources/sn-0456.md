# Summary

Steve opens with a news potpourri. Mozilla decided to support DRM-protected HTML5 video in Firefox through an Adobe-supplied decryption plugin fetched on demand, running inside an open-source, inspectable sandbox; Steve sees this as an unavoidable consequence of the commercialisation of the web. China reportedly banned Windows 8 on government computers, apparently in reaction to the end of Windows XP support. He comments on the hype around the Swiss end-to-end encrypted mail service ProtonMail (encryption is easy, but metadata and authentication remain weak links) and on Ladar Levison's account of the Lavabit case, including the argument that machine inspection is not a search. A teenage researcher showed that two-factor codes delivered by voice call can be diverted into an unprotected voicemail box: Facebook and LinkedIn disabled the voice option, Google dismissed it as a telco problem, and Yahoo did not respond. Steve then deflates headlines about a smartphone "quantum random number generator" (camera pixel noise is a plentiful entropy source) and a "breakthrough" on discrete logarithms (it only affects small-characteristic fields, as Bruce Schneier confirmed). The main topic is how SQRL gathers entropy on a client with no trusted source: it continuously pours many unpredictable system values, Windows cryptographic random data, RdRand output and the RDTSC time-stamp counter into a streaming SHA-512 hash and finalises it only when a 512-bit random value is needed. Steve also shows that a 256-bit random key collision is vanishingly improbable.

# Key points

- Mozilla will ship DRM video support via an Adobe plugin downloaded on the fly; the sandbox around it is open source, unlike in commercial browsers. The DMCA discourages research into flaws in such plugins.
- China's central procurement centre banned Windows 8 on government PCs; Steve guesses it is a reaction to losing XP updates and that Linux may follow.
- ProtonMail got "NSA-proof" headlines; Steve notes end-to-end encryption is not hard but metadata leakage and weak authentication remain; offline encryption (AxCrypt) on air-gapped machines is the truly secure route.
- Ladar Levison (Lavabit) summarised that the government argued automated inspection of data is not a Fourth Amendment search and that users had no privacy expectation, all decided in a secret court.
- Voicemail attack on second factors: calling the victim to keep the line busy sends the voice-delivered code to voicemail, which often has no or default PIN. Needs the password and phone number first, but defeats the point of a second factor.
- Vendor responses differed: Facebook and LinkedIn paused voice codes pending interactive prompts, Google refused to treat it as its bug, Yahoo was silent after 14 days. Advice: disable the voice fallback.
- Leo notes Google application-specific passwords are a bigger weakness since they bypass the second factor and are reusable until revoked.
- Smartphone camera pixels are analogue noise sources; researchers measured about 1.25 Gbit/s of entropy. Useful for servers, not needed by phones, and needs post-processing.
- A new algorithm solving discrete logarithms in small-characteristic fields was misreported as a crypto break; it has no cryptanalytic application unless generalised.
- Syncthing, an open-source, open-protocol, certificate-authenticated sync tool, is recommended over closed BitTorrent Sync; Leo mentions the Transporter appliance.
- Collision odds for random 256-bit keys among a billion users are about 10^-60, absurdly smaller than other risks.
- Threats to entropy: swapped memory, hibernation, DMA, cold-boot attacks, and an attacker hooking the OS random API to feed predictable values.
- Intel RdRand design: on-chip noise seeds an AES counter generator behind a FIFO; Steve distrusts the software equivalent because exposed state lets an attacker run the cipher backwards.
- SQRL needs entropy only for identity creation (256-bit master key, 80-bit rescue code, 128-bit nonce) and password-encryption salt; the login protocol itself consumes none.
- SQRL's harvester streams system timers, process and thread statistics, mouse position, OS crypto RNG, RdRand and RDTSC (unobservable chaotic CPU timing) into SHA-512 at least 50 times a second and on UI messages, finalising only when needed.
