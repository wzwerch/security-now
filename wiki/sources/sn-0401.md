# Summary

This Q&A episode opens with the news. Adam Gowdiak of Security Explorations reported another complete Java sandbox bypass, though under the new Java rules it needs the user to accept a warning dialog. Steve uses it to discuss sandboxing: Adobe's PDF sandbox effectively ended PDF exploit waves, while Java is far too large to host safely in a browser. A German data-protection commissioner complained that Google's maximum fine of 145,000 euros for the Street View WiFi data collection was too small, which Steve calls absurd since the collection was accidental. Roughly 32 Google Play apps from four developers were updated months after release to harvest phone data and install an SMS-fraud trojan. Microsoft and Twitter are adding two-factor authentication, and Steve celebrates that Microsoft's authenticator follows the open time-based one-time password standard (RFC 6238), so one app works for Google, Facebook, LastPass and others. He explains a 1Password design flaw found by the oclHashcat author that cut brute-force cost by only a factor of two to four, and apologizes for under-explaining PPTP, which can be cracked via a 200-dollar cloud service because it rests on 56-bit DES, whereas OpenVPN clients exist for iOS. After a sci-fi movie review, a battery research summary and a SpinRite story, he answers questions about the Nest thermostat on home WiFi, EV certificates versus fingerprints, running 16-bit programs on 64-bit Windows 7, lost bitcoins, and the delayed Butterfly Labs mining hardware.

# Key points

- Adam Gowdiak found a new full Java sandbox bypass; exploitation in a browser still requires the user to accept the new security warning, showing the value of Oracle's signed-applet prompt.
- Adobe's sandbox in Reader and Acrobat made PDF exploits largely disappear, showing sandboxing can work; Steve argues Java in browsers is too complex to secure and banks are dropping it.
- Hamburg's data commissioner said the 145,000 euro maximum fine for Google's accidental Street View WiFi data capture was too low a deterrent; Steve points out the data collection was a code-reuse accident.
- Malware authors submitted 32 apps from four developers to Google Play, waited months, then pushed updates that phoned home every four hours with phone number and IMEI and could fetch the AlphaSMS premium-SMS trojan; up to nine million downloads.
- Microsoft adds two-factor login for Microsoft accounts and Twitter was hiring for multifactor expertise. RFC 6238 time-based one-time passwords are shared across Google, Facebook, Amazon Web Services, Dropbox, LastPass, Steam and others, so one authenticator app suffices.
- Real-time interception or man-in-the-middle of a one-time code remains possible, but stolen passwords alone no longer suffice.
- 1Password flaw: its PBKDF2/SHA-1 setup needed 256 bits but SHA-1 gives 160, so a password check required less work than assumed; the effect was only one or two bits of strength. Steve says users need not worry; oclHashcat's author was adding AES on GPUs for TrueCrypt cracking and tested on 1Password first.
- TrueCrypt is only as strong as its password, as the Brazilian case showed, where even the FBI could not open a drive.
- PPTP: based on NT4-era MS-CHAP and 56-bit DES, crackable via Moxie Marlinspike's CloudCracker service for about 200 dollars within a day; fine against casual snooping on open WiFi but not for secrets. An OpenVPN client for iOS exists.
- Listener feedback on proXPN was mostly positive; some complained about upsell nags in the free tier. Opera gets praise from listeners too.
- Nest thermostat question: Steve advises taking such devices offline if features are unused, or placing them on a guest/visitor WiFi network, because a compromised device holding your WiFi password exposes your network; smart meters were already shown to have poor security.
- Fingerprint tool limitation: a man-in-the-middle proxy could alter displayed fingerprints, but extended validation certificates in Firefox, Opera and Chrome cannot be forged by an intercepting proxy; Internet Explorer's EV handling is broken because Microsoft allows enterprise certificates to show green.
- Running 16-bit programs on 64-bit Windows 7: use the XP-mode style virtualization with a 32-bit guest so apps appear on the host desktop.
- Lost bitcoins are gone forever, like burned cash, but coins divide into tiny units, so Steve expects the market to cope; Butterfly Labs, which moved from FPGA to ASIC mining boxes, was months late with 35,000 backorders, and Steve thinks it is overextended rather than a scam.
- Steve explains a Nature Communications battery paper using nanoporous interdigitated electrodes with supercapacitor-like charge rates but poor cycle life, suited to implants and sensors.

# Other segments

- Review of the film Oblivion and a chat about the coming summer of sci-fi movies, and Netflix's House of Cards economics.
- SpinRite listener story: a laptop of an 85-year-old woman was recovered after four weeks of running.
- Steve recalls delaying SpinRite 3 because DOS 6 disk compression broke compatibility.
- Leo sets his mother up with LastPass and Skype; discussion of landlines and SMS pricing.
