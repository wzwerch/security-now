# Summary

Steve reports that Microsoft quietly shipped "Super Duper Secure Mode" in Edge 96: when enabled in the privacy settings it disables JIT compilation in the V8 engine and turns on hardware exploit mitigations, which should remove a large share of historical browser bugs at little visible performance cost. Check Point reverse-engineered MediaTek's custom audio DSP firmware, found flaws that let a malicious app capture audio on phones using about 37% of the world's handset chips, and published enough detail that unpatched, off-brand devices are at risk. HP researchers described RATDispenser, a JavaScript dropper delivered via double-extension email attachments (low antivirus detection), prompting a reminder never to open email attachments. The Windows Installer privilege-escalation flaw whose "fix" only broke the researcher's proof of concept is now exploited in the wild (CVE-2021-41379 variant). After listener feedback and SpinRite progress, Steve returns to last week's IETF 127/8 proposal and, having read the IPv4 Unicast Extensions Project case by John Gilmore, softens his view: with a ten-year horizon, unlocking about 419 million bogon addresses may be reasonable.

# Key points

- Edge "Super Duper Secure Mode" (Edge 96, off by default; Balanced or Strict at edge://settings/privacy): disables JIT, enables Intel CET and later Arbitrary Code Guard; Microsoft says roughly 45% of V8 vulnerabilities involved JIT. Steve runs Strict and invites reports of breakage.
- MediaTek: Check Point found heap overflow and array-index validation flaws in the audio DSP/APU firmware; a malicious app could send crafted messages through the audio driver and record call and app audio. MediaTek chips are in about 37% of phones (Xiaomi, Oppo, Realme, Vivo among others); fixes were released in October and December 2021 but unmaintained phones will not get them. Steve recommends mainstream, supported phones.
- RATDispenser (HP Wolf Security): a JavaScript loader mailed as something like a double-extension ".txt.js" file, decodes itself, writes a VBScript and fetches or drops one of eight RAT families (including STRRAT, AdWind, Formbook, Remcos, Panda Stealer, GuLoader, Ratty); about 11% antivirus detection; probable malware-as-a-service. Mitigations: block script attachments at mail gateways, change the default handler for .js, disable Windows Script Host. HP's own research site briefly served an expired TLS certificate.
- Windows Installer elevation of privilege (CVE-2021-41379 variant): Naceri published a new proof of concept after Microsoft's November patch only blocked the original demo; Cisco Talos observed it exploited in the wild, Kevin Beaumont confirmed it works on Windows 10 21H2 and Windows 11, and even 0patch deemed a micropatch risky. December Patch Tuesday was two weeks away.
- IPv4 special-use blocks (bogons): 0/8, 10/8, 127/8, 169.254/16, 172.16/12, 192.168/16, 224/4 multicast, 240/4 reserved, small TEST-NET and benchmarking ranges. The IPv4 Unicast Extensions Project argues for making 240/4, 0/8, parts of 127/8 and unused multicast usable, adding about 419 million addresses; Linux, Android, macOS, iOS and Solaris already accept 240/4 since 2008, Windows is the laggard. Gilmore proposes natural upgrade cycles plus the existing "de-bogonizing" test practice (as Cloudflare did with 1.1.1.1); Steve now sees it as plausible on a long timescale.
- Listener items: Windows Server updates breaking Exchange certificates, ongoing network printing failures (fix expected 14 December), JavaScript in Excel, and the observation that the IETF draft's authors belong to the unicast extensions project.
