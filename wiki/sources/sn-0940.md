# Summary

After catching Leo up on the previous week's two big stories (LastPass vault cracking and the UK's softened encryption clause), Steve answers listener questions. He explains how a hardware security module such as the USB token holding GRC's code-signing key works: the host hashes the code, the HSM signs the hash internally, and the private key can never be read out, which is the point he made about Microsoft's lost signing key. He then lays out secure-erase guidance: a single overwrite pass plus the drive's secure-erase command suffices for SSDs, two passes of random noise plus secure erase is plenty for modern hard drives, and self-encrypting drives can be erased by replacing their key. Other items include a Verizon impersonation scam, shell checksum tools, browser profiles, a California inquiry into connected-car privacy, a clock showing the 2038 Unix time rollover, and Steve's decision to move his listener communication from Twitter to email lists after Elon Musk's paywall comments. The main topic uses a library administrator's question about pseudonymizing patron records to show how using only a few bits of a cryptographic hash creates deliberate, controllable collisions, with the birthday paradox used to size the token length.

# Key points

- LastPass: attackers can see plaintext email addresses and iteration counts in stolen vaults, so they target early adopters with low counts who are likely to hold crypto; about $35 million has been stolen. The UK Online Safety Bill's "technically feasible and accredited" clause gives encrypted messaging providers an escape from scanning.
- Hardware security modules (HSMs) contain a small crypto computer and offer no command to read a key; GRC's DigiCert-issued key sits in such a token. Code signing hashes the file with SHA-256, signs the hash with the private key and attaches a certificate chain, so verifiers confirm both authorship and that no bit changed. The overhead concern about scaling HSMs is acknowledged but dedicated accelerators exist.
- A Verizon-impersonation caller tricked a long-time listener; Steve repeats the rule to hang up and call back using a known number, since the human factor is the weakest link.
- Shell extensions that add a checksum tab (HashCheck, OpenHashTab, 7-Zip's menu entry) make hashing files quick; the old HashCheck lacks SHA-256 and is open source for anyone to update.
- Chrome and Edge profiles (and Firefox's about:profiles) give separate identities, cookies and extensions; Steve suggests a minimal profile for banking.
- SSDs: electrostatic storage leaves no remnant data, so extra overwrites add nothing and only wear; the real issue is data stranded by the flash translation layer, which only the drive's secure-erase command reaches. Steve suggests one overwrite pass plus secure erase.
- Hard drives: modern encoding (whitening and heavy error correction) means data recovery after a single overwrite is not realistic; multi-pass wiping dates from MFM/RLL days. GRC's planned erasure product would write random noise twice, then use the secure-erase command, or replace the key on self-encrypting drives, at roughly 0.25 TB per hour.
- The California Privacy Protection Agency announced a review of connected-vehicle data practices, echoing the previous week's Mozilla car privacy report.
- A listener-provided 32-bit Unix time "clock" (via grc.sc/2038) shows the four bytes of the timestamp as hands; the signed 32-bit value goes negative in January 2038.
- Elon Musk said Twitter ad revenue fell 60 percent and floated putting the service behind a paywall; Steve pays $8 a month for TweetDeck access but plans to replace Twitter with email lists (one for Security Now) including a new anti-spam inbound mechanism, since most listeners do not use social media.
- Hash truncation: every bit of a strong hash is independent and unbiased, so any subset of bits gives an evenly distributed bin number; this allows pseudonymized tokens whose collision rate can be tuned. For about 5,000 patrons, 24 bits (four printable characters of six bits each) give roughly a 52.5 percent chance that some two patrons collide, enough resolution for statistics while keeping individual histories deniable. Using a modulus instead of power-of-two bits gives intermediate bin counts.
- The birthday paradox (50 percent collision chance for 23 people across 365 days) governs overall collisions, while privacy against a targeted individual depends on the lower chance that someone shares that person's bin.
