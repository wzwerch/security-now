# Summary

Steve begins with signs that Android 16 will gain an Advanced Protection Mode similar to Apple's Lockdown Mode (blocking sideloading, disabling 2G, enabling Memory Tagging Extension, forced reboot after three idle days). He notes Chrome 135 and Firefox 137 features, an Apple update that re-enabled automatic updates, his new iPhone 16 Pro in light of tariff worries, and Microsoft's hotpatching for Windows 11 Enterprise and Education that cuts required reboots from twelve to four a year. He criticises Oracle for continuing to deny a cloud breach that evidence from Kevin Beaumont and BleepingComputer contradicts, reports a third Treasury office breach (the OCC, nearly two years of email interception), and an Apple versus UK tribunal ruling that the hearing must eventually be public. Further items: Mozilla's Thundermail and Thunderbird Pro, April Patch Tuesday, an academic survey of PLC security, research on LLM package hallucinations enabling "slopsquatting", WordPress plugin vulnerabilities, and Quarkslab's PHP audit. The main topic is the W3C Device Bound Session Credentials (DBSC) protocol, which ties short-lived session cookies to an unexportable TPM-backed key.

# Key points

- Android Advanced Protection Mode (AAPM): found in Android 16 betas; reportedly blocks sideloading, disables 2G, enables MTE, reboots after three days idle, and offers an API so apps can harden themselves (for example a browser disabling its JIT).
- Firefox 137 introduces tab groups (progressive rollout), an address-bar calculator, a unified search button and PDF link detection; Chrome 135 ships DBSC.
- Apple 18.4/15.4 releases re-enabled automatic updates; Steve thinks asking would have been polite but sees possible security reasons (malware disabling updates).
- Tariffs: Steve bought an iPhone 16 Pro and had already bought new GRC servers (Supermicro; a Ubiquiti router for static NAT), and expects semiconductor tariffs to raise device prices.
- Windows hotpatching: no-reboot security updates for Windows 11 Enterprise 24H2 x64 via Intune and Autopatch, with baseline months in January, April, July and October; Steve notes 0patch has offered in-memory patching for years.
- Oracle: threat actor rose87168 claimed a breach of Oracle Cloud login servers; Oracle denied it, then reportedly confirmed to customers only verbally and recast the affected systems as "Oracle Classic"; separate Oracle Health breach faces a class action. Steve calls it a model of how not to handle a breach and notes a listener's question about SEC disclosure.
- U.S. Treasury OCC breach since June 2023: about 100 staff mailboxes and over 150,000 emails; earlier OFAC and CFIUS intrusions were attributed to China-backed Silk Typhoon; Steve worries China may "weaponize" collected data.
- Apple versus UK: the Investigatory Powers Tribunal rejected secrecy for the hearing; Steve expects at most a UK-only disabling of Advanced Data Protection.
- Mozilla's Thundermail (mail, calendar, contacts, bring-your-own-domain), Thunderbird Send, Appointment and Assist (privacy-preserving AI); initially paid tiers, open source, and not part of the free Thunderbird app.
- Meta extended teen-account protections to Facebook and Messenger.
- April Patch Tuesday: 126 fixes including a Common Log File System elevation-of-privilege zero-day exploited by RansomExx; Google fixed two Android zero-days including a Cellebrite-style exploit used against journalists in Serbia.
- PLC security systematization (133 papers): built-in access controls and encryption are mostly weak; disabling unused protocols and monitoring are the best defenses.
- Package hallucination study: across 16 code LLMs and 576,000 samples, 19.7% of recommended packages did not exist (open source models 21.7%, commercial 5.2%; GPT-4 Turbo best at 3.59%); 43% of hallucinated names repeated in all re-runs, which makes "slopsquatting" (registering hallucinated names) practical.
- WordPress: over 8,000 vulnerabilities disclosed last year (about a quarter unpatched), but only five in core; the danger is plugins.
- PHP audit by Quarkslab (funded by the Sovereign Tech Fund via OSTIF): 2 high, 6 medium, 9 low and 10 informative findings with four CVEs; two issues redacted pending complex fixes, so an important PHP update is likely.
- DBSC: cookies were invented by Lou Montulli at Netscape in 1994 for MCI; DBSC binds a session to a per-session key held in the TPM, and the browser uses a refresh endpoint to prove key possession and receive short-lived ordinary cookies. Existing site code keeps seeing cookies, so only sign-in and the refresh endpoint change. Chrome measured TPM availability at about 60% of Windows users with about 200 ms average signing time. Privacy rules include per-session keys, clearing with site data and no cross-site leakage; an enterprise extension DBSC(E) adds device key chaining. It limits long-lived cookie theft but not live access from malware on the device.
