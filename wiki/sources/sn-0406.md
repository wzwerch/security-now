# Summary

Steve first discusses the widely shared Ars Technica article on how professional crackers attacked a leaked list of unsalted, un-iterated MD5 password hashes using oclHashcat: word lists, appended digits, exhaustive short passwords, word combinations, and Markov-model guessing fed by the passwords already cracked. He says the lesson is that site hashing matters, but that long random passwords, which his Password Haystacks idea encourages, and a manager such as LastPass (client-side encrypted, iterated PBKDF2) remain the answer. Amazon joined the OAuth 2.0 login providers, and Steve predicts look-alike phishing sites will abuse these buttons. Google announced it will move its certificates to 2048-bit keys and warned developers not to hard-code leaf or root certificates, and to support subject alternative names and Server Name Indication. A listener's SpinRite rescue of a failing multilevel-cell SSD in a Dell laptop is shared. The main topic is Off the Record (OTR), by Ian Goldberg and colleagues, used by the Cryptocat browser plugin and available in clients such as Pidgin and XChat. OTR gives confidentiality and authentication during a chat plus perfect forward secrecy and deniability, which signed PGP email lacks, via ephemeral Diffie-Hellman keys, a MAC derived from the session key, and deliberate publication of old MAC keys so a transcript proves nothing.

# Key points

- Ars Technica piece: crackers ran word lists and rule-based guesses against unsalted MD5, cracking even a 16-character password like a keyboard-walk pattern; results from easy passwords were used in a Markov model to guess the rest. Takeaways: sites must use salted, slow hashes; users should use long random passwords; a long padded password beats a short complex one.
- LastPass encrypts client-side with PBKDF2 (adjustable iterations), so the service never sees plaintext passwords; Leo praises its password-reuse audit.
- Amazon added OAuth 2.0 login; Steve warns that fake "login with Amazon" pages will appear, so check the URL and look for the EV indicator. Amazon already supports one-time-password two-factor for its web services.
- Google's pre-announcement of 2048-bit certificates: clients must validate the full chain, carry a current root store, support subject alternative names and SNI, and must not pin to a leaf or specific root, or assume one CA. Google has a signing capability under a major root and mints its own certificates.
- SNI lets the client name the host in the first TLS message so a server hosting many sites on one IP can choose the right certificate.
- Linkbot Kickstarter modular robot mention.
- SpinRite Level 2 on a year-old consumer SSD with MLC cells found around a dozen unrecoverable sectors and let the laptop boot normally again; Steve explains multilevel cell voltage thresholds and why they wear.
- OTR background: PGP-style signed email gives a permanent, provable record, so a seized key reveals past messages and proves authorship; chat should resemble a private spoken conversation.
- OTR design: ephemeral Diffie-Hellman exchanges each message so past messages stay secret after key compromise (perfect forward secrecy); long-term keys are used only for authentication, not signing; the encryption key is hashed to a MAC key shared by both sides, so either party could have forged a message (deniability); retired MAC keys are published in the next message.
- Cryptocat is a free browser plugin (Chrome, Firefox, Safari) and Mac app with open source and audited code, with a multi-party chat variant and mobile clients coming; fingerprints must be exchanged out of band to confirm identity.
- OTR is also available as plugins for Pidgin, XChat, Irssi and works with Jabber/XMPP clients.
