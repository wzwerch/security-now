# Summary

Steve is recovered from his cold. News: TeslaCrypt is a new file-encrypting ransomware with a slick payment page, asking about 1.5 bitcoin, decrypting one sample file as proof, and targeting game saves, tax and finance files and attached drives. Leo recommends Marc Goodman's book "Future Crimes." Yahoo announced optional password-free login that sends a one-time code by SMS; Steve says it replaces "something you know" with "something you are sent," is weaker than multifactor authentication, and differs from SQRL's challenge-response. A Finnish researcher obtained a certificate for Microsoft's live.fi domain from Comodo by creating a hostmaster mailbox alias, showing how weak email-based domain validation and revocation are; Steve notes Chrome's blocklist and Microsoft's optional auto-revocation updater. The InstantCryptor developers fixed their file encryption by appending a plain SHA-256 of the plaintext before AES-CBC, which is still malleable; a crypto expert advises encrypt-then-HMAC and using only constructions proven secure. Steve also mentions the Large Hadron Collider restarting at 13 TeV. In Q&A: credit freezes versus LifeLock, why HTTP/2 left encryption optional, using SQRL for several accounts at one site, more RowHammer detail (cache flush instruction, ECC memory protects, Linux restricting pagemap), a dubious anti-keylogger product, the need for a data-blocking "USB power condom" for USB-C, why TPMs are still the best local secret store, whether proxies break TLS, and whether SQRL can resist database tampering. Episode 500 is announced for next week.

# Key points

- TeslaCrypt: new code (not CryptoLocker) with professional design, a working barcode, payment by Bitcoin or prepaid cards, proof-of-decryption for one file, and targeting of game files (Call of Duty, World of Warcraft, Minecraft and others), Steam configuration, tax and Quicken data, and network and cloud drives.
- Crime-as-business: Marc Goodman's "Future Crimes" describes criminals run like startups; his advice is updating software and not running as administrator.
- Yahoo on-demand passwords: an SMS code sent to a registered phone with just a username; malware and wiretaps can capture SMS, an attacker or authority with the phone gets in, and SMS password recovery is similarly weak. SQRL instead proves possession of a key via a server challenge, with a password hint cached only in RAM.
- Live.fi certificate: any CA could have issued it because domain validation by email to admin, administrator, hostmaster, postmaster or webmaster is weak; mail providers must block those aliases, CAs (Comodo now the largest issuer) vary in which addresses they accept, and revocation is poor. Chrome's CRLSet blocked it; Windows 8 and later have automatic revoked-certificate updates, available for Vista and 7 as an optional update. Extended validation certificates were not involved.
- InstantCryptor: after being told to authenticate, the vendor encrypted plaintext plus an unkeyed SHA-256 hash; Taylor Hornby (Defuse Security) notes this hash-then-encrypt scheme is forgeable and does not meet IND-CCA2 security. The right design is encrypt first, then add a keyed HMAC with a separate key, verify before decrypting, and do not invent ad hoc crypto.
- LHC restart at 13 TeV; axion mentioned as a dark matter candidate.
- SpinRite will support GPT and UEFI so it can run on modern drives over 2.2 TB and Macs.
- Credit freezes: bureaus operate independently, so freeze all three; Leo uses LifeLock, which he says works through fraud analytics, though earlier regulatory actions restrict its marketing.
- HTTP/2: encryption was not made mandatory in the standard because of ISP and carrier interests in caching and supercookies; Steve says the web is going encrypted anyway.
- SQRL multiple accounts: the client adds an "Account" suffix typed by the user into the hash to derive an unlimited number of per-site identities; separate people on a shared computer use separate SQRL identities. Steve contrasts SQRL with FIDO, where servers keep credentials.
- RowHammer follow-up: Linux submitted a change to hide page maps from unprivileged processes; the attack needs the x86 cache flush instruction to bypass caches; ECC memory prevents it and parity memory partly helps; Google could induce errors on about half of the laptops tested.
- Zemana AntiLogger claims to stop keyloggers, SSL interception and fake CAs; Steve says no product can prevent all of any attack class.
- USB-C and BadUSB: a USB-C "power condom" adapter that passes only power lines would block data attacks from untrusted chargers; a Type-A version already exists.
- TPM: still the best available protected store for secrets because it never exports keys and is built to destroy them on tampering, even though hardware can be physically attacked.
- TLS interception requires the browser to trust a certificate authority, so ISPs cannot break TLS unless users install their certificate; HSTS does not prevent a trusted proxy.
- SQRL cannot defend against an attacker who can alter a site's account database, just as no authentication system can.
