# Summary

Steve starts with a mitigation for Razer-style privilege escalation: a Windows setting (DisableCoInstallers under the device installer registry key, found by CERT's Will Dormann) that stops automatic download and execution of device installers, at the cost of convenience. He reconsiders "Internet anonymity" after ProtonMail handed Swiss authorities an IP address in a criminal case involving a climate-activist group and removed its "anonymous email" marketing claim. Apple has paused its CSAM plans, and Leo clarifies the neural-hash and voucher design. Other items: BrakTooth, a family of Bluetooth Classic stack flaws affecting 1,400+ product listings, and Rapid7's report of two unpatched flaws in the Fortress S03 alarm that allow remote disarming. Listener feedback covers Google Voice numbers for SMS fallbacks, Tailscale success and assembly-language books. The main segment explains why a hardware root of trust is needed and compares TPM 1.2 and 2.0: 2.0 adds SHA-256 and elliptic curves, algorithm agility and better authorization, but Windows 10 features mostly work on 1.2, only four of 14 listed features need 2.0, and Windows 11 adds no new TPM-dependent feature, so Steve calls the requirement arbitrary.

# Key points

- DisableCoInstallers (REG_DWORD = 1) prevents Windows from running vendor co-installers for newly connected devices; useful where users cannot be trusted but may cause confusing "nothing happens" behaviour.
- ProtonMail: complied with a legally binding Swiss order (Youth for Climate) to supply IP address and device information; the homepage "Anonymous Email" line changed to "Your Data, Your Rules". Steve suggests routing access via Tor; Leo notes email is inherently not anonymous and the "no IP logs" claim was misleading.
- Apple paused CSAM Detection for additional input. Leo explains that only NCMEC-derived hashes (not images) are on devices, matches produce vouchers, and about 30 are needed before human review; Steve speculates the design could enable end-to-end encrypted iCloud.
- BrakTooth: 16 new vulnerabilities, 20 CVEs, found by fuzzing 13 chipsets from 11 vendors; ranges from crashes to code execution on some IoT; short range limits risk; underscores the weakness of closed stacks.
- Fortress S03 alarm: unauthenticated API (CVE-2021-39276) exposing the IMEI/serial for an email address and allowing disarm, plus replayable RF commands (CVE-2021-39277); unpatched after 90+ days when Rapid7 disclosed.
- Reader tips: Google Voice (protected with a security key) as the number given for SMS fallback; Tailscale review praising ease after failed WireGuard attempts; Michael Abrash's assembly books recommended.
- TPM background: Trusted Computing Group standard; 1.2 from 2005, 2.0 from 2014 as an API rather than an implementation; Intel PTT and AMD fTPM provide 2.0 inside the CPU or chipset; features include sealing, PCR measurements, attestation, secure storage and NVRAM.
- 1.2 versus 2.0: 2.0 adds SHA-256/HMAC-256, elliptic curve algorithms, algorithm agility, enhanced authorization, quick key loading, non-brittle PCRs and named resources. Of 14 Microsoft-listed features, Device Encryption, System Guard, Autopilot and SecureBIO need 2.0; BitLocker, Secure Boot, Windows Hello, Credential Guard and others work on 1.2. Steve urges Microsoft to use whichever TPM is present instead of blocking Windows 11.
