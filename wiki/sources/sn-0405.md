# Summary

Steve opens with Jonathan Mayer's announcement that Firefox 22 would block third-party cookies by default, in the style of Safari (a third-party origin may set cookies only if it already has one), noting that Mozilla's CTO then delayed it by a cycle. Steve thinks the advertising ecosystem would survive and explains that IE alone tags a cookie's first-party context. He restates that Skype chat links are fetched by Microsoft's servers, adds that the Justice Department only obtained call records for Associated Press reporters, not content, and previews next week's topic, the Cryptocat secure chat system. He mocks the headlines about an 18-year-old's supercapacitor, reports Marks and Spencer contactless terminals charging cards that were in a purse rather than the card presented, and shares that an NSA research guide, "Untangling the Web", recommends ShieldsUP and Security Now. The listener questions cover secure-flag cookies and X-Frame-Options on GRC, enterprise SSL interception boxes and why they are only a threat when a trusted CA certificate has been installed, adware that hyperlinks random words, the iptables-versus-ipchains correction, the huge size of the 168-bit BitTorrent Sync key space, how carrier-grade NAT logging will need port numbers, why application whitelisting does not replace patching, banks blocking SSL Labs scans, and Twitter adding SMS-based two-step login.

# Key points

- Firefox 22 was to block third-party cookies unless the third party already had one set, a relaxed Safari policy; Mozilla's CTO delayed it a cycle. Chrome allows all cookies and IE relies on P3P compact policies. Steve argues blocking costs nothing important; Google Analytics still works since it runs as first-party script.
- Cookie handling bugs exist in every browser (Steve's earlier cookie forensics research); only IE tracked the first-party context of cookies.
- Skype chat links are visited by Microsoft servers (confirmed by Heise and Ars Technica); Steve stresses the capability to read messages exists regardless of purpose, and Leo notes the request origin is unclear.
- The Justice Department obtained telephone call records, not call content, from Associated Press reporters.
- Marks and Spencer contactless payment terminals took payment from a card in a purse a foot away instead of the card presented; Steve says radio is too imprecise to be tied to payment.
- The "18-year-old's supercapacitor" headlines overstated novelty; Steve is waiting for a real automotive-grade storage breakthrough.
- NSA's declassified internet research guide praised ShieldsUP and Security Now and named both hosts.
- GRC should mark cookies Secure; Steve sets X-Frame-Options to same origin to prevent framing of GRC pages. His e-commerce system uses no cookies.
- SSL interception appliances only work if the client trusts the vendor's CA, typically pushed by corporate IT via Active Directory or Group Policy; an unmanaged laptop shows certificate warnings. Steve wants employees to know their HTTPS traffic is being decrypted.
- Intrusive in-text hyperlink ads or pop-ups seen by a listener are site-served JavaScript or malware on the user's computer; test by visiting GRC or TWiT.
- Modern Linux firewalling uses iptables (not ipchains); iptables can redirect several listening ports such as 80 to an OpenVPN port to get out of restrictive networks.
- 2^168 is about 3.7 x 10^50; the key search for BitTorrent Sync is not brute-forceable because it is network-bound, and collision is negligible; the protocol spec is still awaited.
- Carrier-grade NAT: an ISP must log public port ranges as well as IP addresses for copyright enforcement; Windows uses client ports 1024 to about 6024 and TIME-WAIT holds closed ports.
- Application whitelisting (default deny) is excellent but orthogonal to patching: whitelisted Flash, Reader and Java still need prompt updates.
- Two Canadian banks, TD and CIBC, blocked SSL Labs scans rather than fix SSL 2.0 support; Steve notes he keeps a similar opt-out list for ShieldsUP.
- Twitter introduced SMS-code two-step login, not time-based authenticator support yet.
- SpinRite does not take weeks normally; a long run depends on drive damage and BIOS reset time.
