# Summary

Steve opens with two browser privacy wins: Chrome 90 (mid-April 2021) will try HTTPS first for schemeless URLs typed in the omnibox, and Firefox 86 adds Total Cookie Protection, which confines each third-party cookie to the site where it was received. He then covers the SolarWinds hearing, where the former CEO blamed an intern's "solarwinds123" password posted on GitHub while the current CEO said it was in use from 2017. CISA rated a Rockwell Automation PLC flaw (CVE-2021-22681) 10 out of 10 because a single shared key protects Logix controllers. VMware vCenter servers (CVE-2021-21972) were being mass-scanned within a day of the patch, with six public exploits circulating. Steve shares a SpinRite debugging story about an AMD Phenom II quirk, and Leo reports breaking news of seven Exchange Server zero-days used by a China-linked actor. The main topic is CNAME cloaking: trackers persuade sites to alias a first-party subdomain to the tracker's domain so that blocklists and third-party cookie limits no longer apply and the site's own cookies, including login cookies, leak to the tracker. Researchers found it on 10,474 sites, about one in ten of the top 10,000, and Steve calls for it to be shut down, noting legislation may be needed.

# Key points

- Chrome 90 will default schemeless omnibox entries to HTTPS and fall back to HTTP; a flag lets Canary, dev and beta users test it, with a small Chrome 89 experiment first. About 83 percent of sites now use HTTPS, credited to Chrome and Let's Encrypt.
- Firefox 86 Total Cookie Protection (ETP Strict Mode) partitions the cookie namespace per site: third-party cookies still work but are not shared across sites, defeating cross-site tracking without a binary block.
- SolarWinds: former CEO Kevin Thompson blamed an intern for the weak password; current CEO Sudhakar Ramakrishna said it was in use by 2017; researcher Vinoth Kumar found it exposed and it was changed only in November 2019. Other theories include credential stuffing and compromised third-party software; forensics may never settle it.
- CVE-2021-22681 (Rockwell Automation Logix PLCs, CVSS 10): a hard-coded shared key lets an attacker mimic an engineering workstation and change PLC code or configuration; CISA says it needs low skill. Steve criticises putting such controllers on IP networks.
- VMware vCenter CVE-2021-21972 (CVSS 9.8): unauthenticated file upload and remote code execution via the default vRealize Operations plugin on port 443; BinaryEdge found about 15,000 exposed servers and Shodan about 6,700. Steve urges prompt patching and a direct line to front-line vendors.
- SpinRite 6.1 bug: a block-copy and then a plain move from high memory hung on a Gigabyte board with an AMD Phenom II when run from USB; switching from the DS to the FS segment register fixed it and helped a second user. Steve also swapped a SHA hash for the tiny FNV hash to save space.
- Breaking: Microsoft released patches for seven Exchange Server remote code execution flaws exploited by a Chinese state-linked group; the risk is extremely high.
- Criteo emailed site operators asking them to add a CNAME so tracking would "adapt to the evolution of browsers", warning of lost sales if they did not.
- CNAME cloaking (PETS 2021 paper): a site's subdomain is a CNAME to a tracker, so the browser treats it as same-site, bypasses hostname blocklists, and sends the site's cookies to the tracker; 13 tracker providers identified, with Pardot (Salesforce) first at 5,993 sites and Adobe Experience Cloud second.
- 95 percent of CNAME-tracking sites leaked cookie data such as names, emails or session cookies; researchers verified impersonation with leaked tokens. Criteo also used it specifically against Safari.
- Defences: uBlock Origin on Firefox resolves CNAME chains through the browser DNS API and blocks matches; Chromium extensions lack that API, so protection is partial. DNS-level filters such as NextDNS can also catch CNAME trackers.
