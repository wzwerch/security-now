# Summary

Steve opens with Log4j: CISA says it sees widespread scanning and low-level abuse such as cryptominers but no confirmed compromise of federal agencies, expects a long-tail remediation affecting hundreds of millions of devices, and Steve reads this as attackers banking footholds for later. A new critical bug in the H2 database engine (CVE-2021-42392, fixed in 2.0.206) shares Log4Shell's JNDI remote class loading root cause. The US FTC blogged that failing to remediate Log4j can lead to legal action, citing the Equifax settlement, while acknowledging that volunteer open-source maintainers are under-resourced. Chrome 97.0.4692.71 fixed 37 flaws with no zero-days, Brave's monthly users doubled to about 50 million, and WordPress 5.8.3 fixed two high-severity SQL injections, a stored cross-site scripting issue and an object-injection bug. Steve explains Microsoft Pluton as a TPM-equivalent security processor built into the CPU die by Intel, AMD and Qualcomm so that bus sniffing and physical attacks on external TPMs are no longer possible. The main topic is the research by Claroty's Team82 and Snyk on 16 URL parsing libraries: they disagree on schemeless URLs, extra slashes, backslashes, encoded data and scheme mix-ups, which yields SSRF, XSS, open redirect, filter bypass and denial-of-service bugs, eight with CVEs. Steve shows that Log4j's first JNDI fix failed for exactly this reason, because one parser validated the host and another fetched it.

# Key points

- CISA: no confirmed federal compromises; scanning, cryptominers and foreign government targets (for example Belgium's defence ministry) reported; end-of-life systems and shipping delays slow agency patching, with some predicting months.
- H2 database engine (CVE-2021-42392, versions 1.1.100 through 2.0.204, fixed in 2.0.206) is embedded in about 6,800 Maven artifacts including Spring Boot, Play Framework and JHipster; JFrog published a Log4j remediation resource page.
- FTC warning of 4 January 2022: duty to mitigate known vulnerabilities under the FTC Act and Gramm-Leach-Bliley; pointed to Equifax (700 million dollar settlement) while recognising open-source volunteers' resource limits.
- Chrome 97.0.4692.71 fixed 37 issues including a critical use-after-free in the storage component; 24 externally reported.
- Brave went from 24.1 to 50.2 million monthly users in 2021 and 15.5 million daily users; Leo is wary of its crypto ties.
- WordPress 5.8.3: CVE-2022-21661 and CVE-2022-21664 (SQL injection via WP_Query and WP_Meta_Query), CVE-2022-21662 (stored XSS via post slugs, CVSS 8.0), CVE-2022-21663 (object injection requiring admin). Auto-update recommended.
- Pluton: Microsoft-designed on-die TPM equivalent in future Intel, AMD and Qualcomm CPUs; keys such as BitLocker's never leave the silicon, which also hampers Xbox homebrew hacking.
- URL parsing study: 16 libraries (Python urllib, urllib3, rfc3986, httptools; curl; Wget; Chrome; .NET Uri; Java URL and URI; PHP parse_url; Node url and url-parse; Go net/url; Ruby URI; Perl URI) produce different hosts and paths for the same input.
- Five confusion classes: missing scheme, irregular slash counts, backslash versus slash, URL-encoded data, scheme mix-ups. Root causes: use of multiple parsers in one program and incompatible specifications (RFC 3986 versus the browser-led WHATWG "living" URL standard, which treats backslash as slash).
- Python's requests library mixes urllib3's regex-based authority parsing (backslash terminates the host) with urllib's urlsplit, creating a real differential parsing hazard; a Ruby gem called Clearance had an open-redirect flaw (CVE-2021-23435) from the same cause.
- Chromium deliberately accepts malformed slash and backslash forms; Leo and Steve argue regex is the wrong tool and developers should not mix parser libraries.
- Log4j link: its first fix used Java's URI class to check the allow-listed host, but the JNDI fetch parsed a crafted `127.0.0.1#.evilhost` style value differently, so the allow list was bypassed (CVE-2021-45046). Steve notes the root cause remained processing a URL found in log text.
