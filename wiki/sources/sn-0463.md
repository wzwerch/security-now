# Summary

Fr. Robert Ballecer again replaces Leo. The pair start with an Incapsula report that about 61 percent of web traffic is bots (about 31 percent malicious), and Steve explains how SpinRite helps SSDs: drives rely on error correction and hide weak cells, so SpinRite's low-level reads force the drive to rewrite weakening sectors and restore speed. July Patch Tuesday brought two critical fixes (Internet Explorer with 24 vulnerabilities, and a Windows Journal flaw) plus three important ones. Microsoft's court-ordered seizure of 22 No-IP dynamic-DNS domains in order to disrupt botnets broke service for millions of innocent users for several days because its filtering could not cope; Ballecer and Steve see good intent but poor execution and a conflict-of-interest problem. Oracle's Java support position for Windows XP is muddled. A Kickstarter smart LED bulb (LIFX) used a single static AES key in all bulbs, letting an attacker recover users' WiFi passwords from mesh traffic after reading the firmware through JTAG; Steve says IoT devices belong on their own network and an IoT security protocol standard is needed. Google blocked, via Chrome's CRLSet, unauthorized Google certificates minted by an intermediate CA of an Indian authority trusted only by Windows. Q&A covers hosting providers, the dead XP "POSReady" registry trick (Microsoft now blocks it), and EFF Open WiFi's terms-of-service, interception, DNS and bandwidth-limiting questions.

# Key points

- Incapsula study of 1.45 billion visits: over 61 percent bot traffic, roughly 31 percent malicious (DDoS, amplification and unknown "other" bots), spam share dropped.
- SSDs behave like dense DRAM-style charge storage; SpinRite Level 2 makes the drive stop silently relying on error correction and rewrite weak sectors, which restored Samsung SSD speeds.
- Steve plans SpinRite 6.1 as a free update, then a ground-up SpinRite 7 with file-system awareness; SpinRite works on BitLocker or TrueCrypt disks because it only needs the partition table.
- July Patch Tuesday: IE cumulative update fixing 24 vulnerabilities, Windows Journal remote code execution, and elevation bugs in On-Screen Keyboard, AFD and DirectShow. Steve repeats advice to run as a standard user and to avoid IE as a main browser.
- Microsoft seized 22 No-IP domains by court order to hit botnets of two named operators; its own DNS filtering failed, taking down millions of legitimate hostnames for up to four days; the domains were returned.
- Oracle said Windows XP would not get Java 8 support but Java 7 updates would continue; Steve and Ballecer read it as a soft end-of-life like TrueCrypt's.
- LIFX bulbs shared one hard-coded AES key and exposed the WiFi password; the vendor fixed it quickly. Takeaway: segregate IoT devices on a guest or separate network, and the industry needs a standard secure setup protocol.
- Google found certificates for Google subdomains issued through an intermediate of an Indian CA (trusted only in Windows) and pushed a CRLSet entry; Steve says only IE on Windows remained exposed until Microsoft acted.
- Steve says the corporate-style intermediate CA is dangerous because it can sign any site transparently.
- Comparison pages on Wikipedia already cover online backup services, so Steve will focus the cloud storage series on deep analysis of crypto and key management.
- Correction: Silent Circle was founded by Phil Zimmermann (not Moxie Marlinspike).
- SQRL: Ralf's Android client and test server work; Steve's Windows client searches three identity locations (user documents, program folder, working directory).
- Microsoft closed the POSReady registry trick for XP with the July updates after about three months; Steve hosts a small .reg file to test.
- EFF Open WiFi: still need ISP terms-of-service changes; open hotspots must be treated as hostile (use HTTPS); the firmware has a bandwidth limiter giving the owner priority; Ballecer notes RF and Ethernet collision limits.
