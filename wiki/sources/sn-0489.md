# Summary

After the New Year's Eve studio marathon, Steve covers the news. Thunderstrike is a Thunderbolt DMA attack that rewrites a Mac's firmware and replaces the public key used to verify updates, so it cannot be removed, though it needs physical access. A 2012-era trick resurfaced in which scripts can read the HSTS cache by probing subdomains, creating a "supercookie" that survives incognito mode; major browsers flush HSTS when cookies are cleared, while Safari offers no way to clear it. The in-flight Wi-Fi provider Gogo was caught presenting a forged wildcard Google certificate to intercept YouTube, which Steve criticizes since blocking would be simpler and users should not be trained to click through certificate warnings. He also notes CryptoWall 2.0 continues the CryptoLocker model and stresses backups. GRC is back to an A at SSL Labs after rebooting the server to disable SSLv3, while keeping a SHA-1 certificate until end of 2016. Listener questions cover SQRL and cross-site tracking, whether POODLE-vulnerable banks are risky, whether hardware tokens would have limited Sony, why GRC runs on Windows, TrueCrypt backdoor rumors, why HTTPS with SPDY can beat plain HTTP, a StartSSL free-certificate refusal triggered by the word "money" in a domain, a university IT director's four malware-free years with AppLocker, and why ignored FireEye alerts are less clear-cut negligence than they look. Next week Steve will explain how the Enigma machine works.

# Key points

- Thunderstrike: Thunderbolt (like FireWire, PCI Express and ExpressCard) gives peripherals direct memory access, so a malicious device can reflash Mac firmware and change the firmware-signing key; Apple was patching and can restrict Thunderbolt memory ranges. Physical access is required.
- HSTS supercookie: a site's script can query many subdomains over HTTP to read back which ones the browser upgrades, building a persistent identifier that crosses private browsing; Chrome, Firefox and Opera clear HSTS state with cookies, while Safari on iOS offers no way and iCloud syncs it. Steve judges it mostly theoretical.
- Gogo in-flight Internet: a Google employee on Chrome saw a forged wildcard Google certificate (Chrome pins Google certificates). The company claimed to be limiting YouTube streaming, which Steve says does not justify decrypting traffic and risks teaching users to accept bad certificates.
- Leo notes that corporate proxies also swap certificates (his mother saw a hospital's), but those use a certificate the organization has installed on its machines.
- CryptoWall 2.0 is a CryptoLocker successor spread by phishing, malicious links and documents; current antivirus and backups are the defenses.
- GRC TLS: SSLv3 disabled, SHA-1 certificate valid only to the end of 2016 so Chrome's SHA-1 penalties do not trigger, grade back to A; the cipher list at bit.ly/grcciphers was updated and fits within the registry's string length limit.
- SQRL and tracking: SQRL creates a unique identity per site, but that does not stop tracking by cookies or by an email address the user supplies; it merely avoids reusing one identity everywhere.
- POODLE: a server is vulnerable if it still allows SSLv3; real exploitation needs script in the browser, a man in the middle and thousands of requests per byte, so the risk is low, but a bank leaving it on shows poor attention to security.
- Sony remediation: Steve proposes tiered, hierarchical security with stricter authentication such as hardware tokens for executives holding the crown jewels, protected mail servers for the inner circle, and less reliance on retained email, though regulations such as Sarbanes-Oxley require retention.
- Steve uses IIS only for historical reasons; his custom GRC code hooks into it, but he would choose FreeBSD today.
- A consultant's claim that TrueCrypt is backdoored is unsupported; the software is unmaintained, an audit is ongoing, and Steve prefers it to vendor disk encryption that might be compelled to include backdoors.
- httpvshttps.com shows HTTPS with SPDY loading many small images up to 80 percent faster than HTTP, because SPDY (the basis of HTTP/2) removes request overhead; Internet Explorer does not support it.
- StartSSL refused a free certificate for a domain containing "money," treating it as a financial institution.
- AppLocker experience from a university IT director: roughly 3 to 5 malware cleanups per week before, none in four years across 400-plus machines after, using publisher-signature rules plus a few path rules for write-protected folders; it requires Group Policy and Enterprise-class Windows licensing.
- A listener points out that large firms like Target receive thousands of FireEye alerts a month ("trivial true positives"), so ignoring any one is understandable; Steve agrees the problem is nuanced, noting Sony's security team was only a handful of people.
