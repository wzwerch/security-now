# Summary

Steve opens with Microsoft's response to the Recall backlash: ahead of the 18 June Copilot+ PC launch, Recall will be off by default, require Windows Hello enrolment and proof of presence, use just-in-time decryption and an encrypted search index. Steve and Kevin Beaumont both remain sceptical, since Windows itself is full of flaws and Defender was slow against an infostealer in last week's demonstration. Other news covers a leak of The New York Times' roughly 270 GB of source code after a GitHub token was left in a public paste, Apple's new Passwords app announced at WWDC, and DJI cutting US flight-data sync. A SlashData survey shows 59% of developers use AI tools, and a Berkeley professor argues human developers remain central for novel work. The Linux kernel project, now a CVE Numbering Authority, has issued thousands of CVEs for ordinary bug fixes, which Steve calls an abuse of the system. Listener feedback includes detailed field reports on Passkey support quirks and the industry rule that code-signing keys must live in hardware. The main story is Microsoft's own write-up of a honeypot built on the abandoned, dangling code.microsoft.com subdomain, which gathered threat intelligence until it was exposed in April 2024.

# Key points

- Microsoft's Recall update: opt-in at setup (off by default), Windows Hello enrolment required, proof of presence to view the timeline, just-in-time decryption via Windows Hello Enhanced Sign-in Security, encrypted search index; Copilot+ PCs are Secured-core with Pluton enabled. Steve sees this as shifting blame to users, and Beaumont still advises not enabling it.
- Steve speculates Recall is a training corpus for a personal local assistant and hints he may write a free utility to guarantee Recall is not running.
- Google's ChromeOS "Memory" idea is described as similar to Recall.
- The New York Times: about 270 GB / 5,000 repositories of source code leaked on the dark web after an employee exposed a private GitHub access token in a public code paste; Steve fears AI-driven bots hunting such mistakes.
- Apple announced a standalone Passwords app (iOS 18, macOS Sequoia, visionOS 2) with Passkey management and a built-in one-time-password authenticator; Leo explains the "Sherlocked" idiom. Cross-platform users will stay with their current managers.
- DJI disables syncing of US drone flight data ahead of a Senate debate on the Countering CCP Drones Act.
- SlashData's Developer Nation survey (10,000+ developers): 59% use AI in their workflow, 42% use chatbots for coding answers; JavaScript leads with 25.2 million developers, then Python 18.2M and Java 17.7M.
- Berkeley's computing college saw first-year applications rise 48%; teaching professor John DeNero expects humans to remain central because generative AI mostly replicates previously written code.
- Linux kernel CNA (since February 2024) issued over 1,100 CVEs in May alone, assigning CVEs to nearly every bug fix, refusing CVEs for end-of-life kernels and for unpatched flaws; critics (Bradley Spengler, GrapheneOS, others) say it creates noise while NIST's NVD is already backlogged.
- GRC email: registration now also accepts the From-header address, which ended false rejections; securitynow@grc.com is for podcast feedback only and mass mailing had not started.
- Listener recommendation: Hover as domain registrar (Steve's long-time favourite); ADAMnetworks "Don't Talk to Strangers" mentioned again.
- Passkey field report: eBay, PayPal and Lowes allow only a single Passkey; Amazon, LinkedIn, Kayak and Adobe do not allow naming keys; LinkedIn caps at five; AWS accepts only FIDO1/U2F keys; Token2 keys need a six-digit PIN. Steve's advice: use hardware keys only for the highest-value sites and a cross-platform manager such as Bitwarden otherwise.
- Code signing: since 1 June 2023 industry rules require standard code-signing keys on FIPS 140 Level 2 / Common Criteria EAL4+ hardware, so small teams can no longer share a key file; Steve expects shared code-signing servers (and notes a rekeying option for a second dongle).
- code.microsoft.com: after Microsoft shut down the Azure App Service behind it (mid-2021), the dangling subdomain was briefly used for malware command-and-control, then reclaimed by MSTIC and pointed at a custom C# honeypot simulating 300+ vulnerabilities and 30+ protocols. It tracked Log4Shell and ProxyLogon exploitation until traffic exploded in April 2024 (160,000 requests/day, mostly CVE-2018-16283 WeChat plugin probes), leading Microsoft to retire it on 26 April. Steve calls the ability to hijack a Microsoft subdomain an architectural failure.
