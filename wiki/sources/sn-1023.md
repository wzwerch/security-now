# Summary

Steve starts with the empty C:\inetpub directory that appeared on all Windows machines after April's Patch Tuesday. Microsoft created it as part of the fix for CVE-2025-21204, a Windows Process Activation elevation-of-privilege bug, told users not to delete it, and offered no explanation; its suggested recovery of installing IIS leaves the folder behind, so a simple recreate would be less heavy. Kevin Beaumont then showed that creating a junction from C:\inetpub to another path blocks all future Windows updates for any user, and Microsoft rated this only moderate. Silent Push reported that North Korean "Contagious Interview" operators set up fake U.S. crypto companies (Blocknovas, Softglide, Angeloper Agency) to infect job seekers with BeaverTail, InvisibleFerret and OtterCookie. CERT/CC described the "Inception" systemic jailbreak that works across ChatGPT, Claude, Copilot, DeepSeek, Gemini, Grok, Meta AI and Mistral. Steve explains new SSD unpowered-retention tests as charge leakage that a rewrite fixes. Listener feedback covers Windows Sandbox limits, SpinRite going public domain eventually, Fail2Ban, geoblocking versus ACME multi-perspective validation, "Trust this computer" cookies and Backblaze short-seller allegations. The main topic is how the Chinese group MirrorFace and others abuse Windows Sandbox to run malware invisibly, and how to disable or block it.

# Key points

- inetpub: empty system-owned folder created by the April 2025 update (CVE-2025-21204); do not delete it; reinstalling then removing IIS via Windows Features recreates it (Steve verified IIS removal leaves it in place). Steve suspects the pre-creation with system ownership blocks a symlink attack and that a hidden attribute might suffice.
- Beaumont's finding: a non-admin user can make C:\inetpub a junction and thereby make Windows security updates fail or roll back; MSRC closed it as moderate and suggested EDR vendors add detection.
- Silent Push: front companies registered in New Mexico and New York used AI-generated employee photos, GitHub, job boards and freelancer sites; victims get malware that can carry into their current employers.
- Inception jailbreak: nested fictional scenarios; second variant asks the model to describe how it should not reply, then pivots to normal prompts; low severity individually but systemic and usable as a proxy to hide actor activity.
- SSD retention: a small test with 128 GB SATA SSDs left unpowered two years showed hundreds of ECC recoveries on a fresh drive and corrupted files plus slow reads on a heavily worn drive; Steve attributes this to electron leakage, worsened by wear and heat, says the drives are not failing, and recommends periodic full rewrites (for example SpinRite Level 3) and cool storage; he criticises the test design (file system rather than raw media).
- Windows Sandbox is a container-style clone of the host OS, so a compromised host or kernel hooks carry into it; it is not as isolated as a full virtual machine. Windows 10X ideas could not use it.
- Steve states he intends to release all his source code, including SpinRite, into the public domain when his commercial interest ends.
- Fail2Ban: a listener sees hundreds to thousands of banned IPs daily on SSH; Steve uses Bitvise SSH Server restricted to U.S. IPs, key-only authentication and permanent blacklisting after one failure.
- Geoblocking plus ACME: Let's Encrypt multi-perspective validation broke renewal for a site blocking foreign countries; Steve suggests blocking port 443 outside the U.S. while allowing port 80 only for the /.well-known/acme-challenge path.
- "Trust this computer" simply decides whether the login cookie is persistent (with an expiration) or session-only and lost when the browser closes.
- Backblaze: an unverified short-seller report (Morpheus Research) alleged problems; Backblaze denies it and calls it market manipulation; the show reports it without corroboration.
- Windows Sandbox abuse: MirrorFace (APT10 / Earth Kasha) enables the feature, starts it via Task Scheduler under another account so no window appears, shares a folder via a .wsb file and runs malware where Defender is not available; the host sees no logging of file access from inside. Since Windows 11 the wsb.exe command can run it in the background without a .wsb file and its data now persists until stopped. Earlier red-team writeups (Lloyd Davies, 2020) and ransomware gangs using VirtualBox/VMware used the same idea.
- Mitigations: leave CPU virtualization (VT-x) disabled in firmware if no VMs are used; otherwise block WindowsSandbox.exe and wsb.exe with AppLocker. The attacker already needs admin access on the machine.
