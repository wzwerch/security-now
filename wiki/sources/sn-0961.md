# Summary

The show opens by dissecting how a hypothetical example from a Fortinet interviewee (a botnet of three million toothbrushes attacking a Swiss firm) became a worldwide false news story; Fortinet later said it was an illustration lost in translation, and the toothbrushes only have Bluetooth. Steve then reports VulnCheck's finding that of roughly 241,000 apparent Confluence servers on Shodan only about 4,200 are real; the rest are honeypots, so naive counts mislead. Listener questions cover accessing a home network while travelling (overlay networks such as Tailscale, Nebula and ZeroTier instead of an open VPN port), a design for passwordless email-link login, Facebook warning about old passwords, whether iOS browser freedom will create a Chrome monoculture, why UPnP cannot be fixed by CISA's manual-override idea, and a real-world example (Fox News) of the sign-up wall Steve predicted last week. The main topic is the new-old attack in which an attacker with physical access sniffs the BitLocker key as it passes between a discrete TPM chip and the CPU; Steve explains how to check TPM type and how to add a startup PIN.

# Key points

- Toothbrush botnet hoax: originated from a Swiss newspaper interview with Fortinet's Swiss head about a hypothetical; dozens of outlets repeated it; Fortinet clarified that it was not based on its research, and Graham Cluley criticised the slow correction. Leo apologises for relaying it.
- VulnCheck: Shodan queries for the X-Confluence-Request-Time header return 241,702 hosts; adding JSESSIONID cookie, login-page text and filtering identical session values leaves about 4,187. About 236,000 are honeypots, so exposed-host statistics must be treated critically.
- Remote home access while travelling: overlay networks (Tailscale, Nebula, ZeroTier; formerly Hamachi) avoid opening a router port; a Raspberry Pi at home can anchor it. Steve cites Michael Horowitz's RouterSecurity.org for router capabilities.
- Passwords as "login acceleration": because every site has a forgot-password email loop, email control is the real security. An emailed one-time login link with an unpredictable, expiring, single-use token is as secure as passwords; Steve sketches generating the token from a persistent counter encrypted with a server secret key, kept in a self-pruning pending list.
- Facebook's "you entered an old password" prompt is judged useful and not a security weakness, since sites already keep previous password hashes.
- Browser monoculture worry: Steve thinks open standards and the realities of the web make Chrome-only sites unlikely; Apple only opens engines in the EU.
- UPnP: enabled by default on all routers, unauthenticated by design, so CISA's physical-confirmation recommendation cannot realistically cover it; Steve and Leo advise turning it off.
- Sign-up walls (follow-up to "unintended consequences"): foxnews.com and PCGamer now ask only for an email address to read content, tying a first-party cookie to the visitor and sharing it with partners under a "financial incentive" notice. Steve recommends a throwaway email address; Leo notes it still acts as a fingerprint. Throwaway-password reuse is warned against.
- Phone batteries: Steve keeps devices plugged in; lithium cells prefer staying near full.
- Self-hosted email: Steve runs his own mail server with SPF, DKIM and DMARC on a leased block of commercial IPs; Leo advises most people to use a provider such as Fastmail.
- BitLocker with a discrete TPM: a Raspberry Pi-style probe on the TPM-to-CPU bus can capture the decryption key at boot (demonstrated by "StackSmashing"; an old class of attack). Firmware TPMs (fTPM, Intel/AMD/Pluton) are not exposed to this bus attack, though some AMD fTPMs have been defeated with hours of physical access. Check Windows Security, Device Security, Security Processor Details. Defence: enable additional startup authentication via Group Policy and add a TPMAndPIN protector with a strong PIN. Steve: "BitLocker yes, PIN yes"; Leo would use VeraCrypt for better security.
