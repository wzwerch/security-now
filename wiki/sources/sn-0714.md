# Summary

Steve opens with a WhatsApp flaw: a buffer overflow in the VoIP stack let an attacker run code on Android, iOS and Windows Phone devices just by sending crafted call packets, even if the call was never answered. It was used to install NSO Group's Pegasus spyware, and WhatsApp shipped fixes. From Google I/O he highlights Chrome's plan to treat cookies with no SameSite attribute as Lax (two versions out), which silences passive third-party tracking requests unless sites explicitly mark cookies SameSite=None. Chrome is also promising anti-fingerprinting work and a fix for sites that hijack the Back button. A Linux kernel flaw in the RDS protocol (use-after-free, patched before kernel 5.0.8) is hard to exploit but dangerous for Internet-facing servers. Intel's ZombieLoad microarchitectural data-sampling attack came out of embargo that morning, with microcode already shipping in Patch Tuesday. Steve mentions finishing Controlled Folder Access support in his SQRL client and turning back toward SpinRite. The main segment praises Android Q: updateable OS modules (Project Mainline), mandatory storage encryption using Adiantum, TLS 1.3 by default, a sandboxed software-codec service, and expanded BiometricPrompt.

# Key points

- WhatsApp VoIP buffer overflow: remote code execution without answering the call; exploited to deliver Pegasus (NSO Group); about 1.5 billion installs, fixed via server-side mitigation and new client releases; mainly a targeted-attack risk.
- Chrome cookie change: "Incrementally Better Cookies" draft (Mike West) argues requests should not carry state cross-site by default nor over insecure channels. Cookies lacking a SameSite attribute will default to Lax instead of None, forcing trackers to say SameSite=None explicitly.
- Chrome also plans to restrict passive and active browser fingerprinting (details unknown); Tor's Firefox build is the mature precedent.
- Chrome will mark history entries created without user interaction so the Back button cannot be abused by script-pushed pages.
- Linux kernel before 5.0.8 has a remotely reachable RDS use-after-free; rated high severity but low exploitability; Steve expects future miner campaigns against unpatched servers.
- ZombieLoad: cross-thread leak affecting Intel CPUs since 2011, positioned between Meltdown and Spectre in difficulty; can leak browser history, keys and secrets across VM boundaries; microcode patched in that day's Windows 10 update, disabling hyper-threading is the fallback.
- SQRL client now whitelists itself with Windows Controlled Folder Access (anti-ransomware feature, off by default, noisy when enabled); remaining work is the SQRL features/implementation document.
- Android Q Project Mainline: 14 core OS modules (media codecs, DNS resolver, Conscrypt, etc.) become updateable without reboot, but only on devices that ship with Q.
- Android Q requires encryption of user data on all newly launched devices, made feasible by Adiantum; TLS 1.3 enabled by default.
- Platform hardening: sanitizers, shadow call stack, execute-only memory; software codecs moved into a constrained sandbox because media was about a third of vulnerabilities (Bluetooth second, then kernel and NFC).
- BiometricPrompt gains implicit versus explicit flows and a BiometricManager capability check; Electronic ID support is teased for later.
