# Summary

Steve clarifies that Apple's WWDC passkey session described iCloud Keychain sync within the Apple ecosystem and AirDrop sharing, but said nothing about syncing with Android or Windows or exporting keys. He frames FIDO2/passkeys as a strong replacement for usernames and passwords, whereas SQRL was a complete authentication system (for example one-time invitation tokens for guest access and revocable shared access); the real transformation will be WebAuthn support on web servers, which will take years. He notes LastPass and 1Password plan passkey support, recommends a free streamed Offensive Security PEN-200 course, and mentions the accidental Windows 11 22H2 offer to unsupported PCs. Listener feedback covers PKI-based improvements to the NSW digital licence and the puzzle of why double encryption is far stronger than it seems. The main segment explains the PACMAN attack from MIT CSAIL: speculative execution used as a PAC oracle to brute-force ARM Pointer Authentication codes on Apple M1 without crashes. It is not a standalone exploit; it only helps an attacker who already has a memory corruption bug, and Steve suggests Apple could shrink the address space to lengthen the PAC.

# Key points

- Passkey sharing per Apple: iCloud Keychain sync across the user's Apple devices, AirDrop to hand a passkey to another person (equivalent to sharing a password); no cross-platform sync or export announced. A third-party password manager is the likely route to portability.
- FIDO vs SQRL: FIDO generates random key pairs per site; SQRL derived them deterministically from one master key. SQRL also covered guest access, lockout resistance and enterprise sharing. Steve says SQRL development has been handed to others and he is back on SpinRite.
- WebAuthn (W3C, 2019) provides the server-side protocol; adoption needs server plugins and may be slow because sites gain little, unlike OAuth social login. WebAuthn optionally supports Curve25519, so deterministic keys might later work. YubiKeys hold only about 25 credentials.
- Offensive Security streams its PEN-200 (OSCP preparation) course on Twitch free of charge from June 22, 2022.
- Surfshark followed ExpressVPN out of India.
- Microsoft accidentally offered Windows 11 22H2 to unsupported PCs via Release Preview; it was a bug and could be rolled back.
- A PKI expert suggests the digital licence certificate sign a timestamped QR payload so verifiers can accept codes valid for 30 to 120 seconds, defeating copied QR codes.
- Cookie banners debate: ePrivacy rules predated GDPR, but GDPR enforcement made banners ubiquitous; Leo argues first-party preference cookies should not need banners. Firefox announced default blocking of cross-site third-party cookies.
- Puzzle for next week: why double encryption with two keys is much stronger than "twice as long" brute force (answer teased: not 2 but 2^256 times stronger, since the meet-in-the-middle idea is not the point here as stated).
- PACMAN (MIT): Pointer Authentication in ARMv8.3 stores a small MAC (PAC, about 16 bits on macOS 12.2.1) in unused high pointer bits; a wrong guess crashes the process. PACMAN speculatively executes verify-then-transmit gadgets so wrong guesses leave only microarchitectural traces, giving a crash-free PAC oracle usable across privilege levels, from user space against the kernel.
- Limits: needs an existing memory bug, no physical access, leaves no logs, not seen in the wild; Apple says no immediate risk. Hardware mechanism cannot be patched, but bugs can. Steve suggests fewer address bits (for example 36 for 64 GB) would leave 28 PAC bits.
