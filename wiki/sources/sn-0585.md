# Summary

Steve first answers last week's puzzler: compressing before encrypting leaks information through length, as seen in the CRIME and BEAST-era attacks on compressed HTTPS and in new UNC Chapel Hill research that reconstructs speech from the packet sizes of encrypted VoIP. He then covers the November Patch Tuesday (which fixed last week's Google-disclosed zero-day), Squarespace adopting Let's Encrypt, the LessPass deterministic password generator, and LastPass making mobile sync free. A German formal analysis of OAuth 2.0 found four real attacks in the protocol, and a Hong Kong team found that 41 percent of OAuth-enabled Android apps they tested skipped essential validation. Other items: an insurer's plan to price policies from Facebook posts (blocked by Facebook), the UK GCHQ's anti-spoofing push, CAIDA's Spoofer tool for testing whether your network can send forged-source packets, Microsoft's update-restart settings and the retirement of EMET, a Gmail verification-bounce flaw, and MySQL patching. The episode closes with the AtomBombing technique, which uses legitimate Windows global atom table behaviour to get code into other processes without any bug to patch.

# Key points

- Compress-then-encrypt leakage: because compressed length depends on content, observers can infer secrets (CRIME/BEAST on HTTPS headers) or even spoken words from VoIP packet sizes; mitigations are blocking/grouping the audio or random padding at a bandwidth cost.
- Windows Patch Tuesday for November included the fix for the win32k zero-day disclosed by Google the week before; Steve urges installing it.
- Squarespace added free HTTPS via Let's Encrypt for all sites; Chrome is planning to label non-HTTPS pages "Not Secure" in early 2017.
- LessPass is a hash-based deterministic password generator (site, login, master password plus per-site formatting options and a counter). Steve finds it burdensome because sites' password rules differ and the user must remember per-site settings; this was also the obstacle for SQRL-style derived passwords.
- LastPass moved mobile-device sync from the paid tier to the free tier; premium and enterprise tiers remain.
- OAuth 2.0: researchers produced the first formal security analysis, found four attacks in the protocol also affecting OpenID Connect, proposed fixes and proved the fixed version secure. Steve's concerns: complexity, three-party design and privacy leakage to the identity provider.
- OAuth in apps: of 600 popular Android apps examined, 182 offered OAuth sign-in and 41 percent of those failed to validate provider data (signatures, linkage), letting an attacker log in as another user.
- UK insurer Admiral planned to score first-time drivers via Facebook posts; Facebook blocked it under its platform policy against using data for eligibility decisions.
- GCHQ's NCSC wants UK ISPs to change BGP/SS7-era practice and block spoofing; Steve calls it encouraging but limited since modern DDoS botnets do not need spoofing and neighbour-address spoofing survives egress filtering.
- CAIDA Spoofer: free client for Windows, macOS and Linux that tests whether a network lets forged source addresses out; early data suggest about 75 percent of announced IP space blocks spoofing. Steve's pfSense router blocked spoofed traffic at the NAT, so he could not contribute meaningful test data.
- Microsoft documented Group Policy and MDM settings for update restarts (active hours, deadline of two to 14 days) and announced EMET end of life, since Windows 10 as a service can integrate such mitigations.
- Gmail flaw: when linking a secondary address, a verification email that bounced returned the verification code to the sender, letting an attacker claim an address they did not own.
- MySQL: researcher published proofs of concept for two flaws after Oracle did not patch within 40 days; MariaDB and Percona had patched; Steve urges updating.
- Errata: replacing hostnames with IP addresses (last week's DNS-outage idea) fails for HTTPS because certificates and SNI depend on the hostname.
- AtomBombing (enSilo, Tal Lieberman): attacker code stored via the global atom table is pulled into a victim process through a short return-oriented-programming chain, bypassing process isolation with no bug exploited. Microsoft cannot remove the feature without breaking applications; defence is heuristic detection by security software. It requires an attacker already running locally.
- IoT remarks: Steve suggests consumer IoT may only be safe if routed through responsible hubs such as Apple or Google; a listener's fridge lost calendar sync after Google changed an API.
- SpinRite orientation question: modern rotary-actuator drives are balanced and orientation-independent, but run SpinRite in the orientation the drive will be used.
