# Summary

Steve first debunks the widely reported "Microsoft leaked its Secure Boot golden key" story: researchers actually found that the supplemental boot policies added in the Windows 10 Anniversary Update can be used to fool older boot managers that do not know to check them; no key was leaked and it is unrelated to the FBI backdoor debate, though it is a real, hard-to-fix error. He and Leo discuss Facebook's escalating contest with Adblock Plus, and a listener case where Avast's TLS-interception certificate (whose private key had leaked) let an attacker hijack a Facebook session. A University-level USENIX paper showed that a change made to TCP, implemented in Linux 3.6 and later and thus in most Android devices, allows an off-path attacker to infer connections and sequence numbers. Microsoft will move Windows 7 and 8.1 to cumulative monthly updates and will support Skylake PCs through the normal end of life. Steve covers the SSLKEYLOGFILE trick for decrypting browser TLS in Wireshark, a three-dumb-routers write-up, side effects of the registry fix for the SMB credential leak (block ports 137-139 and 445 at the router instead), the DiskFiltration acoustic exfiltration research, and how a server's IPMI interface was the source of his stray ARP traffic. He closes with an explanation of Intel/Micron 3D XPoint.

# Key points

- Secure Boot "golden key": Windows 10 1607 supplemental policies (meant for developer test signing) can be replayed against pre-update boot managers; mitigation requires updating boot managers across the installed base; headlines from several outlets were wrong and the researchers' FBI rant was a red herring.
- Adblock Plus vs Facebook: blocking is a cat-and-mouse game because the browser decides what to fetch; Steve thinks Facebook cannot win short of serving pre-rendered images.
- Avast case: a user saw Facebook's certificate issued by Avast, whose interception root key had been exposed; Steve says corporate TLS proxies can be justified but desktop antivirus doing it increases attack surface; the fix is uninstalling the product and removing its root certificate.
- TCP side channel (USENIX Security paper): an off-path attacker who knows two IP addresses can infer a live connection and its sequence numbers in roughly a minute with high success, enabling disruption, injection into unencrypted flows and degrading Tor anonymity; patches were available, with Android updates expected in September. Another reason to use HTTPS everywhere.
- Traffic-confirmation of pirated streams by UK surveillance vans is plausible by correlating packet-size patterns, as with Tor confirmation attacks.
- Windows Update: from October 2016 Windows 7 and 8.1 get a single cumulative monthly rollup, reducing user choice (for example the Get Windows 10 update); Microsoft reversed its plan to cut security support for Skylake machines early.
- SSLKEYLOGFILE: Firefox and Chrome can log TLS session secrets so Wireshark can decrypt developers' own traffic; Mozilla kept the feature after debate.
- Three dumb routers: PC Perspective published a clear write-up; Steve invites similar guides for EdgeRouter and pfSense.
- SMB credential leak follow-up: the NTLM-restriction registry setting breaks LAN file sharing and Remote Desktop credentials; better to block ports 137-139 and 445 at the border router; pfSense's UPnP/NAT-PMP service can be restricted to named devices.
- DiskFiltration: malware varies hard-drive head movement to send data acoustically to a nearby microphone at roughly 180 bits per minute, enough for keys from an air-gapped machine.
- IPMI: unexplained gratuitous ARPs on his Level 3 servers came from the Intelligent Platform Management Interface on the primary NIC; switching to the second NIC stopped it.
- Safely formatting an untrusted USB stick: use a Chromebook or a Linux tool without mounting; BadUSB firmware tampering would remain.
- USB explainer link; a former Twitter engineer's remark that there is no Internet of Things, only many unpatched small computers.
- 3D XPoint (Intel/Micron): non-volatile, byte-addressable, roughly 1000 times faster and more durable than NAND and denser than DRAM, first chip 128 Gb; Steve sees it blurring memory and storage.
