# Summary

The planned PGP episode is displaced by news. Steve first covers Firefox 23, which silently removed the visible JavaScript on/off switch (re-enabling script for those who had disabled it), blocks active mixed content while allowing passive mixed content, and again did not block third-party cookies by default, although he points to his cookie checking page and to the option of keeping third-party cookies only until the browser closes. Twitter's new two-factor system is explained in detail: instead of the shared-secret time-based codes used elsewhere, the Twitter mobile app holds a 2048-bit private key and signs a server challenge, and a hash-chain scheme modelled on S/KEY provides single-use backup codes. Steve recounts NSA director Keith Alexander being heckled at Black Hat and the report that the FISA court itself found some collection unlawful in 2011, then dismisses the "Chrome shows saved passwords" story as a non-flaw since anyone with access to a logged-in account can already see them. He summarizes an iSEC Partners talk warning about progress in factoring and urging a move toward elliptic curve crypto, held back by BlackBerry-held patents. The two main topics are the arrest of the Freedom Hosting operator, after which Tor hidden service pages injected JavaScript exploiting a Firefox 17 ESR flaw to phone home with the visitor's IP, hostname and MAC address, and the BREACH attack, which uses HTTP response compression to recover secrets from HTTPS pages in seconds.

# Key points

- Firefox 23 removed the UI setting for disabling JavaScript (silently turning it back on), arguing NoScript is the proper route; Steve still advises keeping script off by default because malicious ads and injected scripts are a main infection path.
- Firefox did not block third-party cookies by default; Mozilla planned a whitelist/blacklist approach through a Stanford-led Cookie Clearing House. Steve recommends accepting them but discarding at browser exit.
- Firefox 23 blocks active mixed content (scripts) on HTTPS pages without a prompt and shows a half-filled shield, while images still load.
- Twitter's two-factor authentication: a per-device RSA key pair, 2048-bit, where the server only holds the public key and sends a random challenge to be signed, so Twitter cannot impersonate users; SMS remained an option. Steve regrets that standard OATH time-based tokens were not offered.
- Twitter's backup code uses a chain of 10,000 SHA-256 hashes of a random seed. The server stores the 10,000th value and the user receives the 9,999th as a 12-character Base32 code, so each use walks one step back along the chain (Northwestern's 1996 S/KEY idea).
- Keith Alexander's Black Hat keynote met with heckling; ABC reported that the FISA court's own 2011 finding of unconstitutionality was classified and suppressed. Steve points to an Ars Technica piece on how Section 215 language was subtly altered.
- The Chrome "plaintext password" story: Chrome's Show button reveals saved passwords to anyone using the logged-in session; Chrome's lead said a master password would give false security. Steve says physical access to an unlocked account means total access, and recommends locking the machine.
- iSEC Partners' Black Hat talk: RSA and Diffie-Hellman (1976-77) are three decades old and recent factoring advances in edge cases suggest preparing a move to ECC; ECC keys are far shorter for the same strength (about 512-bit ECC versus 16,000-bit RSA for 256-bit symmetric strength) but are patent-encumbered by BlackBerry. Google was retiring 1024-bit keys and Wikimedia was moving to HTTPS everywhere.
- The New York Times: other federal agencies complained about being refused NSA data access.
- Freedom Hosting, a Tor hidden-service host, was taken over after its operator Eric Marques was arrested in Ireland on child pornography charges; the sites showed a maintenance message and served an iframe with JavaScript targeting a Firefox flaw fixed in June but unpatched in the Tor Browser Bundle's Firefox 17 ESR. The Windows-only shellcode sent hostname and MAC address to a server in a Verizon Business block in Virginia, then cleaned up; Steve distinguishes it from the FBI's larger CIPAV tool and notes courts ruled such minimal identification does not need a warrant. Tor Mail users were collateral damage.
- The same incident showed the cost of Tor Browser having re-enabled JavaScript by default.
- BREACH (Black Hat 2013): a successor to CRIME that exploits HTTP response compression, which nearly all sites use, to infer secrets such as session tokens and CSRF values from encrypted responses by observing size changes after injecting guesses. Mitigations: disable HTTP compression, separate secrets from user input, mask or randomize secrets per response, add random padding to headers.

# Other segments

- Steve finished Peter F. Hamilton's Void trilogy and recommends Fallen Dragon and the Commonwealth books; brief comments on the films Elysium, Oblivion and The Hobbit extended edition.
- SpinRite 6.1: Steve built a high-resolution timing base (about 323 picosecond resolution) to satisfy ATA timing delays reliably across machines; the upgrade stays free for SpinRite 6 owners.
