# Summary

Steve spent the week writing InSpectre, a small Windows freeware utility that probes the processor and the OS and explains in plain English whether a system is vulnerable to Meltdown and Spectre, whether hardware and microcode support exists, and whether the current configuration carries an avoidable performance cost; it can toggle the Meltdown mitigation and the program reached roughly 20,000 downloads in a day. The news section covers Intel AMT's BIOS extension, which can be taken over by someone with brief physical access because the default password is never changed; Microsoft's Skype announcing Signal-protocol encryption and why that does not make Skype itself trustworthy; a UK data protection amendment that protects researchers who re-identify anonymized data only if "intentional or reckless"; and Mozilla's proposal that all new web features require secure contexts, further winding down plain HTTP. Early Meltdown exploitation progress from researchers is noted, and Google's Retpoline technique, a compiler-level fix for Spectre variant 2 with negligible cost, is explained. Steve closes with microcode loading (Linux can load Intel microcode at boot, Windows cannot yet), PCID/INVPCID recovering Meltdown performance on newer chips, and advice on whether to disable the Meltdown mitigation.

# Key points

- InSpectre reads CPUID and model-specific registers, understands AMD (never vulnerable to Meltdown), and flags the performance penalty on older chips or pre-Fall Creators Update Windows 10; some antivirus flagged an early build because of its registry handling, which Steve obfuscated.
- Steve's assessment: Meltdown is the easiest to exploit but no in-the-wild exploitation is known; for typical users with a noticeable slowdown, disabling the mitigation temporarily is a defensible personal choice, but he expects exploitation and says listeners will hear when it appears.
- Windows 7, 8.1 and pre-Fall Creators Update Windows 10 get the costly flush-based Meltdown mitigation even on new CPUs; Steve criticizes Microsoft for not backporting the PCID-based approach.
- Retpoline: replaces indirect jumps/returns in compiled code so prediction cannot be steered; released to the public domain, available in GCC; Microsoft added a compiler switch for the LFENCE-based variant. It protects only recompiled code, not malicious programs.
- Spectre variant 2 otherwise needs a microcode update delivered through BIOS vendors; most older PCs, phones and IoT devices will never get one. Linux can load Intel microcode data at boot, while VMware's driver loads too late to help Windows.
- Intel AMT: default BIOS-extension password "admin" is rarely changed; physical access at boot lets an attacker enable network access, bypassing BIOS password, TPM and BitLocker on the local network. Advice: set a strong AMT password or disable it.
- Skype with Signal: end-to-end encryption strength is real, but Skype is closed source and endpoints and legal-order features remain the weak link.
- UK law change: re-identification offence limited to intentional or reckless acts, helping researchers.
- Secure Contexts Everywhere: Mozilla proposal that new web platform features require HTTPS; powerful APIs (Bluetooth etc.) should not be reachable from man-in-the-middle content.
- Public researchers tweeted about efficient Meltdown reads of non-cached data and withheld releases.
