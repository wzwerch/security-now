# Summary

Steve doubts that PRISM could involve custom interfaces into every company's back end and argues upstream taps are far more plausible. July's Patch Tuesday brought seven bundles fixing 34 flaws, with eight TrueType font flaws allowing code execution just by visiting a web page, plus 17 critical Internet Explorer fixes and Adobe Flash and Shockwave updates. The most-tweeted item is the Cryptocat group-chat flaw: its JavaScript random digit generator mishandled the range (accepting 251 values and dividing by 25), skewing randomness, and the group-chat key handling was weak; the bug was found by a researcher in a harsh blog post, was patched in version 2.1, and never affected one-to-one OTR chat or the SSL layer. Steve also mentions the Hemlis secure messenger crowdfunding, Android's "master key" signature-bypass flaw discovered by Bluebox, a Dropbox two-factor bypass using a dot-variant email, and reports that Google and others pay Adblock Plus to show acceptable ads. SpinRite 6.1 work includes its own extended memory manager and handling of the A20 line, with a keyboard-controller bug that rebooted a couple of machines. The main topic: in classic SSL, one RSA key both authenticates the server and protects the session key, so an adversary who records traffic and later obtains the private key (possibly via a request for expired keys) can decrypt everything. Perfect forward secrecy, using ephemeral Diffie-Hellman (DHE or the cheaper ECDHE) cipher suites, avoids that, but Microsoft servers offer no suitable RC4-plus-DHE suite and BEAST concerns push RC4-RSA to the top of the list.

# Key points

- Steve argues a custom connection into every company's disparate back end would be huge engineering that is hard to keep secret, whereas fiber taps are simple; slides now mention both "upstream" and PRISM collection.
- July Patch Tuesday: seven bundles, 34 vulnerabilities, six bundles critical; TrueType font parsing flaws (eight) let a web page's font execute code; IE fixed 17 critical issues; Krebs suggests removing Shockwave.
- Cryptocat group chat bug: a random-digit routine discarded bytes above 250 but accepted 0 to 250, giving 251 values divided by 25, which produced non-uniform output; JavaScript lacks integers and crypto code needs randomness testing (such as DieHard tests); the bug was patched quickly, one-to-one OTR was never affected and group chat also ran over SSL. Open source did lead to discovery, though slowly after a bounty was announced.
- Steve notes Intel chips since Sandy Bridge have a hardware random number generator and explains entropy pools and reseeding of PRNGs.
- Hemlis, a Swedish secure messenger project from a Pirate Bay cofounder, was raising money; Leo notes that it is not open source.
- An Android flaw (Bluebox Security) lets apps be modified without breaking their signature on some 900 million devices; Google patched the Play Store and Samsung issued a fix; details were due at Black Hat.
- France is added to the list of governments conducting large-scale electronic surveillance; Snowden was offered asylum by Venezuela, Nicaragua and Bolivia, and Bolivia's president's plane was forced to divert.
- Dropbox two-factor bypass: attacker creates a second account with a dot-variant of the victim's email, enables two-factor on it, then uses that account's recovery code at the real account's "lost my phone" prompt.
- Google and others reportedly pay Adblock Plus to allow their ads; the default "acceptable ads" setting can be turned off.
- SpinRite 6.1: own extended memory manager that finds a 32 MB buffer, A20 gate enabling via the keyboard controller, a bug where writing the reset bit rebooted some machines, and PCI enumeration working.
- Classic TLS handshake: client hello with cipher suites, server picks the strongest common suite and returns its certificate; with RSA key exchange the client encrypts the session secret with the server's public key, so the private key both authenticates and protects past traffic.
- Threat: an adversary recording encrypted traffic can later compel the private key, even just old, expired keys.
- Cipher suites are tuples of key exchange, cipher, key length and MAC; DHE and ECDHE give forward secrecy because the long-term key only authenticates; DHE is about three times costlier, ECDHE much cheaper (Adam Langley's optimizations); about a third of Firefox and Chrome traffic already uses PFS.
- GRC cannot offer PFS well because Windows Server 2008 has no DHE suite with RC4, and RC4 is needed to avoid BEAST; TLS 1.1 and 1.2 are immune to BEAST but servers do not pick suites by protocol version.
- Steve wishes browsers would indicate when a connection has forward secrecy; OTR has forward secrecy by design.
