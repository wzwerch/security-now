# Summary

Apple Pay went live the day before, but the show turns to POODLE, the SSL 3.0 weakness disclosed that week. Steve first covers FBI director James Comey's first policy speech complaining that default encryption on Apple and Google devices (and encrypted disks) blocks justice and hinting at a legislative fix; Matthew Green replies that law enforcement has more data access than ever. Yubico and Google announced support for FIDO U2F: a cheap 18-dollar Security Key plus new Neo tokens, and Steve contrasts the FIDO work with his own lightweight, hardware-independent SQRL. The main topic explains POODLE: an active attacker positioned in the connection can force browsers to fall back from TLS to SSL 3.0 by simulating failure, and since SSL 3.0's CBC mode checks padding after decryption and before authentication, a padding oracle lets the attacker recover one byte of plaintext (such as a session cookie) at a time using hundreds of induced requests. Steve reviews RC4's startup bias and CBC padding, notes Moxie Marlinspike's rule to authenticate before doing anything else, and explains the real fix: TLS Fallback SCSV, a signalling cipher suite value that lets servers reject fraudulent downgrades, already in OpenSSL. He argues the attack is impractical because it requires both a man in the middle and attacker script running in the victim's browser against the target site, which would already allow easier side-channel leaks, and says GRC is unaffected because it uses no login cookies.

# Key points

- Comey told the Brookings Institution that locked phones and encrypted drives can deny justice and that the post-Snowden pendulum may have swung too far, hinting at legislation; Matthew Green says law enforcement still has far more data than in the 1980s.
- Steve notes encryption protects people from foreign governments and criminals too (for example the Chinese interception of iCloud logins reported earlier).
- Google and Yubico: the 18-dollar Security Key supports only FIDO U2F; the Neo models also support one-time passwords, JavaCard and NFC. Steve describes the FIDO alliance specifications as one lightweight (U2F) and one heavyweight, and says SQRL is simpler and not tied to hardware.
- GRC's SpinRite purchases are monitored with a custom UDP status system that plays a sound per licence; four-licence site licences were returning.
- POODLE background: SSL versus TLS naming and versions; clients retry with older protocols when servers hang up on newer ones, which an active man in the middle can exploit to force SSL 3.0.
- SSL 3.0 offers RC4 (biased early output, considered broken) or CBC block ciphers with padding; SSL authenticates then encrypts, so receivers must decrypt before verifying the MAC, violating Moxie Marlinspike's principle.
- A padding oracle lets an attacker who can modify ciphertext blocks learn one plaintext byte per few hundred probes, so extracting a long cookie takes thousands of requests that must be generated by malicious script in the victim's browser; the attacker must also be an active man in the middle.
- The fix is TLS Fallback SCSV: clients include a pseudo cipher suite value signalling that they know TLS; a server that sees it in an SSL 3.0 hello knows a downgrade is occurring and refuses. OpenSSL added support immediately; other platforms would follow. Disabling SSL 3.0 also removes the exposure.
- Steve argues the attack is bogus in practice: an attacker able to run script in the victim's browser already could exfiltrate cookies through request-length side channels even over TLS 1.2.
- GRC is not vulnerable because it keeps no session cookies or server-side state and uses encrypted blobs passed back to the user; Steve will keep SSL 3.0 enabled until servers support the fallback signal.
