# Summary

With Father Robert Ballecer filling in for Leo, Steve first calls the Palantir "hack" a misleading headline: Palantir paid a red team and deliberately gave it an initial foothold, and the leaked report showed how easily a large organically grown network can be taken over after a phishing click. Positive Technologies demonstrated SS7-based interception of one-time codes to take over social accounts, reinforcing Steve's preference for time-based authenticator codes over SMS. A Reddit user who returned a Netgear Arlo camera set kept receiving the new owner's camera feed because device registrations were not cleared. GoToMyPC forced password resets after what turned out to be password reuse, and a widely shared story about the Intel Management Engine (a separate ARC-based processor with its own network access, signed firmware and no user-off switch) concerned Steve. The main topic is Intel's Control-Flow Enforcement Technology: ENDBRANCH makes legitimate jump and call targets explicit so return-oriented programming gadgets cannot be entered mid-function, and a hardware shadow stack stores return addresses separately so a corrupted return address is detected and the process is terminated. The change is backward compatible, since ENDBRANCH is a no-op on older chips, but needs OS support.

# Key points

- Palantir: reported "breach" was a commissioned red-team exercise that simulated a phishing click; value lies in fixing found weaknesses; the leak of the report was the real issue; Padre notes pivoting inside networks is hard to stop and cites transparency about failures.
- Positive Technologies showed SS7 interception of SMS codes to reset Facebook, WhatsApp and other accounts; SMS is "something you blab," not something you have; time-based tokens exchange a secret once over TLS.
- SQRL is described as having the smallest "trust radius" because servers hold no secrets.
- Netgear Arlo: cameras could be registered by serial number to a new account without removing the earlier owner; Netgear promised a fix within weeks; IoT security often rests on guessable identifiers like MAC or serial labels.
- Steve recalls ShieldsUP! originating from scanning neighbouring IPs and finding exposed C: drives; ISPs now block NetBIOS ports.
- GoToMyPC announced a "very sophisticated" attack but later said it was credential reuse from other leaks; all users had to reset passwords.
- Intel Management Engine (ME/AMT) runs on a separate ARC RISC core with firmware signed by Intel, direct memory and network-interface access (sometimes active when the PC is off) and no user disable; concerns are auditability and eventual reverse engineering; mitigation is physical unplugging or an external firewall; Padre explains the enterprise out-of-band management rationale.
- CET ENDBRANCH: calls and jumps must land on the ENDBRANCH instruction, enforced by a small state machine in the pipeline; defeats ROP gadgets that jump into the middle of existing code; harmless on older CPUs.
- CET shadow stack: call pushes the return address on both the normal and a hidden stack; return compares them and faults on mismatch, defeating stack buffer overflows that overwrite return addresses; hardware speed, no performance penalty, but OS and driver support is required.
- Background: earlier defences were the NX bit (DEP) and ASLR, whose limited randomisation granularity still allows guessing or probing.
- A listener helped Intel's Steve Fintel use SN-211 to explain ROP to management; CET was planned for Atom before Core.
