# Summary

Steve opens with news of his marriage, then revisits several earlier topics. Chrome is about to block outbound browser connections to TCP port 10080 (Firefox already does), part of the ongoing browser response to NAT Slipstreaming; developers using that port will need to move services or use an override. The EFF launched "Am I FLoCed", a test page for Google's FLoC origin trial (about 0.5% of Chrome users), and Steve explains the SimHash idea behind FLoC and argues the EFF should say "profiling" rather than "tracking". The PHP project's git server compromise is now explained: a legacy HTTPS push path with password authentication, backed by an old master.php.net user database on obsolete software, bypassed gitolite entirely; PHP rebuilt that system and moved the main repository to GitHub. Cisco said it will not patch critical remote-code-execution flaws (CVE-2021-1459, CVSS 9.8) in four end-of-life small-business routers. The "failure to patch" segment traces FortiGate SSL VPN path traversal (patched May 2019, still exploited by APT29 in 2020 and by Cring ransomware in 2021). The bulk of the episode is a walk through Spring 2021 Pwn2Own: about $1.21M paid out, with Exchange, Teams, Zoom, Safari, Chrome/Edge, Windows 10, Ubuntu and Parallels all broken. Steve's recurring conclusion is that remote management should stay off the internet, with a single hardened SSH entry point instead.

# Key points

- Chrome will block outbound port 10080 (ERR_UNSAFE_PORT); Firefox did so in Nov 2020 and offers the `network.security.ports.banned.override` preference. The port is used by Amanda backup and VMware vCenter; the exact abuse motive was unclear. Advice: move any browser-facing service off 10080.
- Port blocking exists because NAT Slipstreaming abuses router application-layer gateways; browsers keep adding abuse-prone ports to their block lists.
- EFF's amifloced.org tests whether Chrome is in the FLoC origin trial (0.5% of users in several countries, possibly up to 5%); the only opt-out is disabling third-party cookies or using another browser; sites can opt out via a Permissions-Policy header (`interest-cohort=()`).
- FLoC uses a SimHash (similar inputs give similar outputs) of a week of browsing; Steve sees it as profiling rather than tracking, and notes the cohort-size arithmetic did not quite add up.
- PHP git compromise: attacker pushed commits via HTTPS/Apache Digest authentication against the master.php.net database (old OS and PHP, MD5 passwords), skipping gitolite; fixes were a new system with PHP 8, parameterised queries, bcrypt, password resets, and moving the repo to GitHub.
- Cisco RV110W, RV130, RV130W and RV215W (CVE-2021-1459, unauthenticated RCE as root through the web management interface) are end-of-life and will not be patched; Cisco recommends migrating to RV132W/RV160/RV160W.
- Steve's recommended remote-access model: disable all remote management, expose only one hardened SSH server (key plus password plus time-based factor, non-default port, IP filtering if possible), then administer from inside.
- FortiOS SSL VPN path traversal (CVE-2018-13379) was fixed in 2019 and publicised by DEVCORE at Black Hat 2019; roughly 480,000 FortiGate and 50,000 Pulse Secure servers were exposed. A hidden "magic string" password-change backdoor was also disclosed.
- APT29 (Cozy Bear) used unpatched Fortinet SSL VPNs against COVID-19 vaccine research in 2020; Kaspersky reported Cring ransomware (AES plus a large RSA key) entering industrial firms in Europe via the same flaw, then using Mimikatz and Cobalt Strike.
- Pwn2Own Spring 2021 (virtual): $1.21M of $1.5M awarded across 23 teams; successes included Safari, Exchange (authentication bypass plus privilege escalation by DEVCORE), Microsoft Teams, Zoom Messenger (zero-click, three-bug chain by Computest), Chrome/Edge, Windows 10 local privilege escalations, Ubuntu Desktop and Parallels guest-to-host escapes. Nobody targeted the Tesla.
- Several entries counted only as partial wins because the bug was already known; Alisa Esage was the first woman to compete as an independent researcher. Steve and Leo think duplicate-bug penalties are unfair.
- Zoom pushed a server-side fix on April 9 for the Zoom Chat attack and promised deeper mitigations; attack required an accepted external contact or same-organisation account.
- Steve's takeaway: the same classes of mistakes (web management interfaces, secret strings in firmware, unpatched legacy systems) keep recurring, and Pwn2Own shows how much unknown vulnerability remains.
