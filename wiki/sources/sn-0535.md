# Summary

The lead story is Dell shipping PCs with a self-signed root certificate (eDellRoot) installed by a support tool, together with its private key, so anyone could impersonate any HTTPS site to Dell users; Steve calls it as serious as Lenovo's Superfish and points to test sites, a certificate-store audit tool and Dell's removal tool, noting Firefox is unaffected because it uses its own certificate store. Next, researchers' Black Hat talk on LastPass found no breach but showed that local malware can use the convenience features of a logged-in password manager, plus smaller design weaknesses that LastPass fixed quickly; Steve explains hardening options and contrasts SQRL's no-cloud design. He also covers Windows 10's update silently removing certain user-installed apps, and a Manhattan District Attorney report urging Congress to require smartphone makers to keep data accessible under warrant, which he finds proportional and Leo thinks is overreach. Other items: Let's Encrypt beta invitations, a retraction about wildcard certificates and SNI, SpinRite on SSDs, Amazon proactively resetting passwords found in breach lists, and what to do about Diffie-Hellman cipher settings in browsers.

# Key points

- Dell eDellRoot: a root CA certificate valid until 2039 with no usage restrictions, identical on all affected machines, with the private key recoverable; installed by Dell Foundation Services to give support the service tag. Chrome, IE and Edge use the Windows certificate store and were exposed; Firefox was not. Removing the certificate alone is undone by the service, so stop and disable the service or run Dell's fix. Test sites exist to check vulnerability.
- Steve notes AV and debugging tools also install local root certificates, which is more acceptable when generated per machine; a shared key is the real failure. Leo jokes about trusting small utilities from unknown authors.
- LastPass research: no hack, but with a logged-in browser a local attacker or malware can reach the vault; a disabled one-time password used for account recovery could be re-enabled locally; a server-injected custom JavaScript helper could theoretically be abused by a malicious or compelled insider; the Firefox preferences file holds encrypted credentials that users sometimes post publicly; ECB mode was used for some data. LastPass fixed most issues within days. Recommendations: use two-factor, country and Tor restrictions, avoid storing the master password, consider disabling convenience features.
- SQRL contrast: no third party, a one-time written rescue code in place of recovery; Steve says a local-app login extension to SQRL was worked out but deferred to a later version.
- Rank-your-threats lesson: convenience tradeoffs in password managers are far smaller risks than password reuse.
- Windows 10 November update removed some user-installed apps (for example hardware monitors and AMD control software) without asking; Steve sees Windows becoming a managed service and notes reduced Microsoft testing.
- Manhattan DA report (about 42 pages): proposes a federal statute requiring OS designers to keep devices accessible via warrant, argues full-disk encryption by default (Apple and Google, 2014) hinders prosecution, and lists open Fifth Amendment questions such as compelled unlocking versus disclosing a passcode. Steve says it does not demand mass key escrow or traffic decryption and could be acceptable, but both hosts recognise the slippery slope and that users of third-party tools like Threema would remain protected.
- Let's Encrypt is quietly sending beta invitations.
- Errata: wildcard certificates do not require SNI; SNI is needed only to choose among multiple certificates on one IP.
- SpinRite on SSDs: dense multi-level-cell flash relies on error correction, so SpinRite's deep reads help; version 6.1 will become SSD-aware by skipping seeks.
- Amazon emailed a listener that it had reset his password after finding his credentials in an unrelated list; Steve praises the approach and the absence of a link in the message but warns phishers may imitate it.
- Diffie-Hellman: listeners should not manually disable DHE ciphers because it may remove forward secrecy for some sites; browsers will deprecate finite-field DH once servers support elliptic-curve DHE.
