# Summary

A light news week led into a long listener Q&A. Steve discussed a second state bill, this time in California, to require that smartphones sold from 2017 be decryptable by the manufacturer, justified by human trafficking. He again floated a compromise in which unlocking would need a court order, physical access to the phone, and a random per-device key held by the maker, rather than any algorithmic backdoor. The Dutch Consumers Association sued Samsung because most of its phones in the market had received no Android updates for two years, and Steve saw this as the predictable result of treating phones as sell-and-forget devices. He explained Google's Brotli compression (a new "br" content encoding about 17 to 25 percent better than gzip, HTTPS-only), and the CrashSafari pages that abuse the HTML5 history API with a tight loop to exhaust memory and crash browsers or even iOS. Firefox 44 also arrived with push-notification support, RC4 removal, an Equifax root removal and Brotli. Listener questions covered backdoors in telecom products, nesting a travel VPN with a corporate VPN, verifying a VPN is active, why two-factor (including push-approval apps and hardware keys) cannot defeat a live relay attack, multi-name certificates, using netstat to inspect connections, content filtering, and using a second router for IoT isolation.

# Key points

- California bill by an Assembly member would require phones sold from 1 Jan 2017 to be unlockable by the maker; Steve's compromise is court order plus physical access plus per-device random keys in a vault, so that no remote or algorithmic key exists.
- Dutch Consumers Association sues Samsung: reportedly 82 percent of Samsung phones examined had no updates to the latest Android in two years; it wants updates for two years from purchase, tied to the EU two-year warranty.
- Brotli: Google's open compression format, descended from Zopfli (which stayed deflate-compatible); new Accept-Encoding token "br"; already used in the WOFF2 web font format; browsers will only use it over HTTPS.
- CrashSafari/CrashChrome: a short script floods the history API (cheap to call, expensive to process), exhausting memory; not a security flaw but an annoyance, and spreading via shortened links, so users should be careful clicking.
- Firefox 44 supports web push notifications (already in Chrome), dropped RC4, removed the Equifax 1024-bit root, added Brotli and a built-in JSON viewer; Chrome 48 had also dropped RC4.
- A former telecom developer's note: companies add backdoors for supposedly good reasons. Steve's advice: assume they exist, put your own simple NAT router behind an ISP-supplied one, and have enterprises contractually require no undocumented remote access.
- VPN inside a VPN works (prefer UDP-based tunnels to avoid retransmission conflicts); to check a VPN is active, compare the public IP seen with and without it and optionally do a reverse DNS lookup.
- Two-factor cannot stop a live man-in-the-middle relay: the attacker forwards the password and then the fresh code (or an approve-this-login push) to the real site. Hardware keys have the same weakness; SQRL binds the requesting IP into its token so the server can detect a mismatch.
- A certificate may list many Subject Alternative Names, so one certificate can cover many unrelated domains; Steve dislikes it for broad reuse and expects Let's Encrypt to reduce the need.
- netstat (for example with options showing owning process) is a useful inventory of outbound connections; unexplained persistent connections deserve investigation, and a clean reboot gives a baseline.
- On government content filtering: Steve is sceptical it can work, since the Internet was not designed for censorship and HTTPS inspection harms privacy.
- IoT isolation: instead of relying on a router's guest network features, plug an older WiFi router's WAN port into the main router and use it as a separate IoT network.
