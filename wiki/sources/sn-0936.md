# Summary

Steve opens year 19 of the show with thanks for the reaction to his decision to continue past episode 999. News covers SUSE's plan to delist and be bought by the private-equity firm EQT, a Google Android 14 code path for satellite SOS messaging, and an alleged defective-SSD problem with SanDisk Extreme and WD My Passport portable drives, for which Steve offers an explanation based on multi-level-cell flash behavior. An Adalytics report says YouTube still lets personalized ads and tracking reach "made for kids" channels, the AnonFiles host shut down and took 8Base ransomware loot with it, and two cryptography disclosures (TSSHOCK and BitForge) show flaws in threshold-signature multi-party crypto wallets. Further items are Google's quantum-resistant OpenSK FIDO2 key, Chrome's safety-check notifications for removed extensions, Chrome's move toward HTTPS-First and automatic HTTP-to-HTTPS upgrades, and a WinRAR update. After listener feedback on Topics, the GPL and email aliases, the main topic is Windows Secure Time Seeding, a heuristic that sets the system clock from data in TLS handshakes and has been jumping server clocks by days to over a century since 2016. Steve's conclusion is that heuristics need sanity checks and that admins should disable the feature.

# Key points

- SUSE (maker of the openSUSE ecosystem) announced it would leave the Frankfurt exchange to be taken private by EQT; Steve warns that private-equity ownership usually means cost cutting and change for users of the open distribution.
- Android 14 code contains a demo-flagged satellite SOS feature similar to Apple's; it would need matching radio hardware.
- SanDisk Extreme and Extreme Pro portable SSDs (and the WD My Passport 4TB) were reported to lose data and become unmountable even after a May firmware fix, prompting a lawsuit against Western Digital; Steve speculates the failures at about half-full may relate to controllers converting data from fewer to more bits per cell.
- Adalytics found advertising cookies and personalized ads on YouTube "made for kids" channels as of July 2023 despite YouTube's 2019 promise, prompting US senators to seek a COPPA inquiry.
- AnonFiles shut down citing abuse, which destroyed data the 8Base ransomware group had stored there.
- CertiK linked a Canadian group that hijacks Discord servers to phish crypto wallets to named individuals; Steve reiterates that crypto remains immature and risky.
- Verichains' TSSHOCK (Black Hat) found three flaws in threshold ECDSA implementations used by multi-party wallets such as Binance, Zengo, Multichain, THORChain and ING; Fireblocks' BitForge found zero-days in the GG-18, GG-20 and Lindell 17 protocols affecting Coinbase WaaS and Zengo, both after 90-day coordinated disclosure; Fireblocks cites nearly $500 million stolen in the first half of 2023.
- Google released an experimental OpenSK security-key firmware with a hybrid ECC plus Dilithium signature scheme developed with ETH Zurich; public-key crypto (as used by passkeys) is what quantum computers threaten, not symmetric crypto.
- Chrome 116 carries a safety-check feature, on by default in Chrome 117, that notifies users when an installed extension is removed from the Web Store as malware, for policy violations or by its developer.
- Google's "Towards HTTPS by default" post notes over 90 percent of Chrome navigations are HTTPS; Chrome 115 experiments with automatically upgrading http:// links to https:// with fallback, as a step toward an HTTPS-First mode. Steve argues plain-HTTP reference sites without logins do not need it.
- WinRAR 6.23 fixed code-execution flaws; WinRAR has no built-in update check.
- uBlock Origin blocks the Topics API by default via a Permissions-Policy header rule; Steve notes Topics returns a website only topics it already associates with that site, so a first-party site learns nothing new, unlike advertisers across sites.
- Listener clarifications: the JPMorgan "consecutive characters" rule probably meant sequential characters; the GPL only requires source offers on distribution; choosing an email forwarding provider is a reliance decision and users should migrate quickly on a shutdown notice.
- Windows Secure Time Seeding (introduced 2016, default on in Windows 10 and later and Windows Server) derives time from the ServerUnixTime field and OCSP validity data in TLS handshakes, combining them into a "Secure Time Seed High Confidence" value. Because OpenSSL since 2014 fills that field with random data, rare alignments of noise appear to make Windows jump its clock (reported jumps of 55 days, 17 or 31 hours, and one to the year 2159), breaking database servers and a Norwegian operator's phone-number routing.
- Microsoft support told reporters the only recommendation is to disable the feature where reliable NTP exists; a senior Microsoft escalation engineer had publicly advised disabling it on domain controllers; HD Moore speculated a logic bug and a possible server-side-request-forgery angle.
- Mitigation Steve gives: set the registry value UtilizeSslTimeData under the W32Time Config key to 0 and rely on NTP. He argues the heuristic lacked sanity checks (certificate validity, Windows Update timestamps, file times).
- Steve describes SpinRite 6.1's own heuristic "universal smart driver" that probes IDE, ATA and AHCI hardware at startup, now tested by about 759 testers.
