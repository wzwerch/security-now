# Summary

Leo returns from vacation, and Steve recaps SQRL: a 256-bit master identity key (reduced from 512 since the prior episode) is combined with a site's domain to derive a per-site key pair, so each site sees only an anonymous public key and a signature over its login URL, with no shared secret and no third party. In one week the grc.sqrl newsgroup had over 1,100 posts, many developers were building Android, iOS, Drupal and WordPress implementations, the W3C had made contact, and Steve plans to write a Windows reference client and a protocol "implementation details" page. In the news, October Patch Tuesday brought eight bulletins fixing 26 flaws, including IE memory corruption bugs already exploited, and a New Yorker article described how Lavabit's founder fought a demand for the service's SSL private keys, offered a targeted tap for a fee, was fined daily, and finally handed over keys printed in tiny type before closing; Steve notes the NSA could have obtained the keys through FISA and decrypted all traffic passively. In the Q&A Steve covers desktop clients using an sqrl:// handler, the app password and Scrypt costs, why the domain is part of the key, evil-site session hijacking, server nonce quality, anonymity versus spam, and key collision odds, which for a 256-bit key are astronomically small.

# Key points

- SQRL basics restated: the master key never leaves the device; HMAC of the domain gives a per-site private key; the public key is the site-specific identity; signing the QR code URL proves ownership. Desktop use works by clicking the QR code as an sqrl link handled by an installed client, so no phone camera is needed, and a separate app rather than a browser plug-in shares one client across browsers.
- Revocation is the cost of dropping third parties: a lost key cannot be cancelled by an intermediary, which Steve accepts because third parties can be compelled; backups of the master key are exported as a password-protected QR or printout.
- Usability question: the master key is protected by a memory-hard Scrypt derivation costing about one second per unlock attempt, with ideas such as asking for only a few characters of the password after a recent full unlock. Authorities can compel a fingerprint more readily than a password.
- Domain binding: the key is tied to the DNS name, so a changed domain means re-linking by scanning the old site's code. DNS spoofing is considered well studied.
- Phishing: the app shows the domain in the code; additionally the site can return a logged-in link to the app rather than logging in the session that displayed the code, cutting a relaying evil site out of the loop.
- Nonce quality on the server need not be strong, only non-repeating; the client adds its own nonce to prevent replay even against a poor server.
- Anonymous identities do not stop spam or require anonymity; sites can still add email confirmation or CAPTCHAs on top.
- Collision math: with 2^256 possible keys and seven billion users the chance of any collision is about 1 in 4.7 times 10^57 (a thread in the newsgroup also joked about a light-travel-limited "ball of people").
- Randomness: the reference approach mixes platform entropy with camera noise captured while the user waves the phone, to avoid reliance on a suspect random generator.
- Lavabit: the court demanded the private SSL key (covering all 400,000 users); the owner offered a limited tap for 3,500 dollars, was sanctioned 1,000 then 5,000 dollars per day, supplied the key as 11 pages of four-point text, then closed and wiped his servers. Steve considers this evidence that SSL keys are being compelled and that smaller operators resist differently than shareholder-owned firms.
- October Patch Tuesday: 26 vulnerabilities (17 remote code execution), nine IE flaws including the previously fixed-by-shim zero-day, plus font kernel driver, .NET, SharePoint, Office and Silverlight bugs; Microsoft rated three bulletins most urgent.
- Duo-style push approval and Evernote's two-factor option were mentioned as other authentication trends.
