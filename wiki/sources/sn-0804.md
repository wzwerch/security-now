# Summary

Google announced that Chrome 90 (mid-April 2021) will stop trusting Spanish certificate authority Camerfirma after a string of 26 compliance incidents since 2017, including undisclosed unconstrained sub-CAs, mis-issued certificates with over-long validity and too little entropy. Steve then covers urgent news in open-source security: Tavis Ormandy found an easily exploitable heap overflow in libgcrypt 1.9.0 (GnuPG's crypto library) fixed within hours by 1.9.1, and Qualys disclosed the ten-year-old "Baron Samedit" heap overflow in sudo (CVE-2021-3156). ESET reported Operation NightScout, in which BigNox's NoxPlayer update mechanism delivered trojanized updates to a handful of targets in Taiwan, Hong Kong and Sri Lanka; Steve uses it to argue that users now need local malware surveillance because update channels are trusted. Google Project Zero reverse engineered Apple's iOS 14 iMessage defences (the sandboxed Swift BlastDoor service, re-randomized shared cache, and exponential restart throttling). Steve shares a SpinRite architecture decision: finish 6.1 first, then port the existing 16-bit code to a 32-bit real-time OS that can boot via BIOS or UEFI. The episode ends with NAT Slipstreaming 2.0 from Armis, which uses H.323 call forwarding and WebRTC TURN to open NAT pinholes to any internal host.

# Key points

- Camerfirma distrust: failure to disclose unconstrained sub-CAs (DigiSign, MULTICERT), mis-issued certificates (over 825-day validity, 63 bits of entropy instead of 64, wrong extensions), and slow revocation; Steve notes CAs are privileged and behaviour rules exist for a reason, and predicts other browsers will follow. Leo and Steve also discuss DigiCert validation versus Let's Encrypt automation.
- Libgcrypt 1.9.0 (released January 19, 2021) contained a heap buffer overflow triggerable simply by decrypting attacker data before any signature check; developers urged "stop using 1.9.0" and shipped 1.9.1 within hours. Cryptographer Filippo Valsorda suggested it came from C memory safety issues possibly tied to timing-attack mitigation. Steve's moral: leave tested code alone and prefer memory-safe languages.
- NoxPlayer (BigNox) update channel abused in a targeted surveillance operation, dropping Gh0st RAT and Poison Ivy RAT; ESET saw only 5 of 100,000+ users get malicious updates; BigNox denied being affected. Steve argues for local endpoint monitoring (Windows Defender) given auto-updating software like Notepad++.
- Apple iOS 14 iMessage hardening per Project Zero's Samuel Gross: BlastDoor sandboxed Swift service parsing untrusted data, shared-cache ASLR re-randomization when crashes are observed, and exponential throttling of service restarts up to about 20 minutes.
- sudo heap overflow CVE-2021-3156 (Baron Samedit), present since July 2011 in versions 1.8.2 to 1.8.31p2 and 1.9.0 to 1.9.5p1; any local unprivileged user could become root in default configurations (verified on Ubuntu, Debian, Fedora). Update immediately; useful for lateral movement.
- SpinRite roadmap: ends reliance on BIOS and 16-bit DOS by later porting to the OnTime RTOS32 environment, which supports both BIOS and UEFI boot, after 6.1 ships.
- NAT Slipstreaming 2.0 (Armis): H.323 ALG call forwarding via one packet to TCP port 1720 opens a pinhole to any internal IP and port; WebRTC TURN bypassed the browsers' restricted-port lists. Browsers (Chrome 87, Edge 87, Safari 14.0.3, Firefox 85) now block HTTP/HTTPS/FTP to ports 69, 137, 161, 1719, 1720, 1723 and 6566. Armis found 97% of URGENT/11-vulnerable industrial controllers unpatched a year later. Advice: disable unneeded router ALG passthroughs (SIP, H.323, FTP, etc.) and test with ShieldsUP!.
