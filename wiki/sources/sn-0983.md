# Summary

Steve first answers listeners who asked whether CDNs can be used safely after Polyfill.io: yes, using Subresource Integrity (an integrity= hash on script and link tags, easy to generate at srihash.org), which Polyfill.io could never support because it generated different code per browser. He then discusses the June 2024 BlackSuit ransomware attack on CDK Global, a dealer-management SaaS used by about 15,000 US car dealerships, which was reported to have paid roughly a $25 million ransom; three listeners wrote in about its effect. He notes that irs.gov still uses an Entrust certificate valid to 26 October 2024, reassures a listener who saw one Polyfill-related DNS lookup, and shares a long listener argument that Microsoft's record with Windows 10, OneDrive and Edge shows it will eventually force Recall on users. GRC's weekly email reached 6,471 subscribers, with about 80 bounces caused by an antivirus false positive on the picture thumbnail. The main topic is the Snowflake incident, in which stolen single-factor customer credentials (largely from infostealers) were used against around 350 customer tenants, including Ticketmaster and AT&T; Steve questions how so many credentials were obtained and notes Snowflake's legal takedowns of researchers' write-ups.

# Key points

- Subresource Integrity: add integrity="sha384-..." (or sha256/sha512) with the base64 hash of the exact library version; the browser refuses the file if its hash differs. Works with any CDN as long as content is static and version-pinned. Polyfill.io served browser-specific code and so could not use it.
- CDK Global: a Russia-linked ransomware attack disabled the dealer management system for about 15,000 dealerships for roughly two weeks; CNN reported about 387 bitcoin (about $25 million) paid to BlackSuit affiliates on 21 June, and CDK began restoring service a week later. An industry writer blamed private-equity cost cutting and untested backups; Steve says dependence on a single provider grows silently as manual skills fade and expects dealers to stay with CDK. Class-action suits were already filed.
- irs.gov: Entrust-issued certificate with a not-after date of 26 October 2024, so renewal before the Chrome cut-off is a visible test of who signs it.
- Polyfill aftermath: one listener's phone made a single lookup of cdn.staticfile.org; Steve judges the chance of receiving the targeted malicious script tiny and says the script ran only in the browser page context rather than exploiting the OS, so no reinstall is needed.
- Listener "Bud" argues Microsoft has repeatedly pushed or silently re-enabled settings (forced Windows 10 upgrades, OneDrive folder backup, Edge prompts) and will do the same with Recall to monetise AI via advertising; Steve says it is hard to argue and repeats that he will release a Recall blocker if needed.
- GRC email: 6,471 subscribers; ClamAV false positives on the embedded JPEG made about 80 messages bounce.
- Snowflake: Snowflake blames customers for lacking MFA and says an ex-employee's demo account (not behind Okta or MFA) was accessed with credentials from infostealers. Roughly 350 or more customers lost data, including Ticketmaster/Live Nation (claimed 560 million customers), Advance Auto Parts, Santander, LendingTree and AT&T (call and text metadata of about 110 million customers from 2022, never deleted). Hudson Rock's write-up claimed a Snowflake employee's credentials were used; Snowflake pushed legal takedowns of it and its archive copy. Kevin Beaumont and Mandiant describe infostealers on personal machines synced with work browsers as the entry path and recommend mandatory MFA and log review; the attacker client string was an offensive name Steve found distasteful.
- Steve's takeaways: cloud providers should enforce MFA and secure defaults; "your provider will throw you under the bus"; long-lived data should be deleted when no longer needed.
