# Summary

A news-heavy episode with no single dominant story. AMD released Spectre variant 2 microcode for chips since the 2011 Bulldozer line, and Steve plans to extend InSpectre to detect it; the separate Ryzenfall-family flaws remain unpatched. Russia blocked Telegram, and in doing so its blunt IP blacklist (about 15.8 million addresses in Amazon and Google cloud ranges) broke many unrelated services. Drupalgeddon2 exploitation began exactly as predicted, and Drupal warned that sites already patched by someone else may be compromised. Akamai reported UPnProxy, where millions of routers with UPnP exposed on the WAN are chained into proxy networks; Steve points to GRC's ShieldsUP! UPnP test. Microsoft quietly dropped its AV-registry-key condition for delivering Windows updates. Other items: Chrome will cap HTTP cookie lifetimes, vendors misreport Android patch levels, old JavaScript SecureRandom weakens old bitcoin keys, IIS 6 WebDAV is being exploited for coin mining, and a casino was breached via a smart aquarium thermometer.

# Key points

- AMD published Spectre v2 microcode for Bulldozer and later; Microsoft says it is delivered via Windows 10 1709 updates. Ryzenfall, Masterkey, Fallout and Chimera remain to be addressed. InSpectre release 8 already shows whether Intel microcode exists for a chip.
- Telegram: Russia blocked huge cloud IP ranges after Telegram shifted addresses into AWS and Google space, causing collateral outages; regulators also asked Apple, Google, APK Mirror and VPN providers to cut Telegram off. Government officials themselves use Telegram; the Foreign Ministry planned a move to Viber.
- Drupalgeddon2: unauthenticated remote code execution via Form API AJAX input handling in Drupal 6, 7 and 8; proof-of-concepts appeared on GitHub within a day of the patch; Drupal's PSA says unpatched sites since April 11 may be compromised and that updating does not remove backdoors; attackers sometimes apply the patch themselves to lock out rivals. Crypto mining is the common payload.
- Firefox can enable TLS 1.3 by raising security.tls.version.max in about:config; SSL Labs "test your browser" verifies it. Chrome already supports 1.3.
- UPnProxy (Akamai): over 4.8 million routers expose UPnP on the WAN; attackers rewrite NAT mappings to bounce traffic through them. Many ASUS and some Ubiquiti models were listed. Fix: disable WAN-side UPnP, update firmware, test with ShieldsUP!. The WAN exposure test was originally covered in earlier episodes.
- Microsoft reversed its January policy of withholding updates unless an AV-set registry key was present; updates now flow regardless.
- Chrome 70 (October 2018) will ignore cookie expirations longer than one year on HTTP connections, with plans to shrink further; Steve is uneasy about breaking the standard but sees the HTTPS-push rationale.
- Security Research Labs found Android OEMs setting patch-level dates without installing all patches: Google, Sony, Samsung had 0-1 missing, HTC/Huawei/LG/Motorola 3-4, TCL and ZTE 4 or more. Google's Project Treble separates OEM code to ease updates.
- Early browser JavaScript SecureRandom gave only about 48 bits of entropy; combined with GPU/ASIC power and higher bitcoin value, old browser-generated wallets deserve migration to new addresses.
- IIS 6 (about 11% of IIS installs, roughly 600,000 exposed per Shodan) with WebDAV has an old buffer overflow now used to install Electroneum miners; SharePoint portal setups often enable WebDAV.
- WhatsApp photo of a hand without fingerprints helped confirm police suspicions in a drug case (11 convictions); Steve compares it to confirming suspicions about Tor endpoints.
- A casino lost 10 GB including its high-roller database through an internet-connected aquarium thermometer (reported by Darktrace); lesson is IoT network segmentation using isolated guest networks.
- The IRS e-filing system went down on tax day with a message calling it a planned outage.
