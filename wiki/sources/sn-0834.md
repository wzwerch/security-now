# Summary

Steve corrects last week's advice: the free, federally mandated option is a credit freeze, whereas a lock is a bureau's own (sometimes paid) product, and a fourth bureau, Innovis, should also be frozen. The Wall Street Journal had chatted with the T-Mobile attacker, identified as John Binns in Turkey, who claimed to have entered through an exposed router and moved into a data centre with over 100 servers holding unencrypted records; Steve criticises T-Mobile's data hygiene and repeated breaches. He covers the Windows 11 compatibility muddle (TPM 2.0 and CPU lists, with Microsoft saying unsupported machines can still install from an ISO), and ProxyToken, a further Exchange authentication bypass that Microsoft fixed in July after more than three months. He clarifies that much of Tailscale's client code is open source and reports reviewers' accusations that Crucial, Western Digital and Samsung silently swapped SSD components after reviews. After a SpinRite 6.1 progress update about moving from writing to debugging in assembler, the main segment shows how a four-digit carrier account PIN can let an attacker port a victim's number and cascade into email and password-manager takeover; Steve changed his own PIN and removed SMS recovery from his password manager.

# Key points

- Credit freeze (free, by law since 2018) blocks creditor queries; temporary lifts and per-creditor allowances exist; add Innovis to Experian, Equifax and TransUnion. Steve concedes he mixed up freeze and lock in the previous episode.
- T-Mobile: attacker said he found an exposed router while scanning the company's address space in July and reached a Washington data centre; dark-web monitor Unit 221B alerted T-Mobile; T-Mobile hired Mandiant and KPMG and faces class action; Steve notes data was unencrypted, old customer and prospect records were retained, and this was the sixth breach in a few years.
- Windows 11: Microsoft kept the TPM 2.0 rule but added older Intel CPUs to the list; Windows Update shows a "can run Windows 11" status with vague timing. Steve sees no technical basis for the strictness; Leo suggests security and hardware-sales motives.
- ProxyToken: a non-empty SecurityToken cookie caused Exchange front-end to skip authentication for back-end requests, and error responses leaked a control panel canary, allowing mailbox rule changes such as silent forwarding. Reported through ZDI in April, patched in July, details published late August.
- Tailscale: client daemon and CLI are open source on GitHub, while the Windows, macOS and iOS GUI wrappers are not.
- SSD bait-and-switch: Crucial P2 (TLC to QLC), WD Blue SN550 (performance drop when cache fills) and Samsung 970 EVO Plus (different controller and flash) were reported by Tom's Hardware, ExtremeTech and Expreview; WD promised new model numbers when specifications change. Chip shortages are a suggested but undisclosed cause.
- SpinRite 6.1: a long untested coding stretch followed by debugging; uses "flat real mode" via the old 286 descriptor-cache behaviour; debugger constraints and conventional-memory exhaustion; plans native USB and NVMe support after leaving DOS.
- Cellular account takeover: the carrier PIN is often the only secret needed to move a number to a new SIM or phone (identifiers ICCID, IMEI and IMSI explained). Steve recommends a long random PIN, carrier port-out/account takeover protection, turning off SMS-based account recovery where possible, and using hardware tokens or app-based two-factor authentication.
