# Summary

In a quiet news week Steve reports on the academic project that examined how exploitable the NSA-promoted Dual EC DRBG random generator was inside real TLS libraries. Cryptographers replaced the standard elliptic-curve constants with ones they controlled to emulate a backdoor, and found RSA's BSAFE (C and Java) particularly easy to exploit, partly because of a non-standard TLS "Extended Random" extension co-authored at the NSA's request that hands the client more of the generator's output; OpenSSL's Dual EC code turned out to be broken and off by default. He also rebuts a Computerworld column claiming Google's always-HTTPS Gmail is a mistake, mentions the cloud-storage price war (Amazon and Microsoft followed Google) and Mozilla's sponsored new-tab tiles, and criticizes XP end-of-support fearmongering. The Q&A covers iPhone configuration profiles for pushing long WiFi passwords, whether the NSA can compel or run certificate authorities, why a small provider's self-signed certificate scales poorly, how SQRL handles shared family accounts with named identities, how iMessage differs from Threema (hidden versus visible public-key management), Turkey's DNS-redirect blocking of Twitter, a list of safe cryptographic libraries (NaCl, libsodium, SJCL) and LibreOffice versus OpenOffice. Steve also describes how SQRL picks the largest font that fits translated strings, and the language count has reached about 52.

# Key points

- Dual EC study: researchers showed Dual EC works as a practical backdoor if the curve constants are chosen by an attacker; BSAFE's C version caches generator output and exposes long random strings, drastically speeding an attack; BSAFE servers could be fingerprinted; Dual EC was the BSAFE default, illustrating "the tyranny of the default".
- TLS "Extended Random": an IETF draft with an NSA author, implemented in BSAFE, lets a client request longer random values and thereby gain more state of the server's generator; the study found it speeds recovery of keys by a very large factor.
- OpenSSL's Dual EC implementation had a bug that kept it from running, so real exposure there is unlikely.
- Computerworld's argument that forced HTTPS for Gmail slows things down is wrong in Steve's view: only the handshake costs time, and connections resume.
- A listener's iPhone configuration profile (built with Apple's configuration utility) can install a hard-to-type WiFi password on visitors' phones.
- Cloud storage pricing: Amazon and Microsoft cut prices after Google; Steve promises an updated trust-no-one cloud storage review.
- Mozilla's Mitchell Baker defended sponsored tiles on Firefox's new tab page; Steve is sympathetic because Mozilla's search-revenue deal with Google ends in December 2014.
- Windows XP: a blogger who runs XP in a virtual machine only for offline Office and games shows the end of patches matters little there; Steve repeats that the internet-facing apps (browser, Flash, Java) are what need updates.
- Pono high-resolution audio player (Kickstarter) and the BlackBerry design-patent injunction against the Typo iPhone keyboard are discussed.
- Certificate authorities: Steve thinks the NSA could easily obtain a valid certificate for targeted man-in-the-middle attacks from some trusted CA, though mass use would risk detection (Chrome pins Google certificates and flags spoofing). GRC's certificate fingerprint service lets users compare certificates.
- Trusting a small provider's own certificate downloaded from its site is acceptable if the channel is secure, but does not scale, which is why browsers pre-trust certificate authorities.
- SQRL can hold several named identities, including a shared Family identity, chosen in a pop-up at login time.
- Threema vs iMessage: both use public-key directories, but Threema lets users verify keys in person (three green dots) while iMessage hides which keys exist, so Apple could silently add a device key; Steve also notes iCloud Keychain syncing can be switched off in settings.
- Turkey blocked Twitter by intercepting DNS queries, even those aimed at Google's 8.8.8.8, because DNS is unauthenticated UDP; DNSSEC exists but adoption is slow.
- Crypto libraries: NaCl (Daniel Bernstein's misuse-resistant design) and its portable derivative libsodium, which SQRL's client uses with Curve25519, plus Stanford's JavaScript Crypto Library.
- EMET on XP only helps DEP, not ASLR, because ASLR arrived with Vista.
- LibreOffice is preferred since Oracle let OpenOffice stagnate.

# Other segments

- SQRL: about 52 languages; the client scales font size to the longest translated string; a SpinRite story about a MacBook Pro with a Windows partition used to run SpinRite.
- Leo and Steve joke about April Fools' Day and the sponsor-free Q&A format.
