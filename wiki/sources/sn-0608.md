# Summary

This news-and-feedback episode covers a JavaScript attack that infers Android PINs from motion and orientation sensor streams, research showing partial-fingerprint phone readers can be matched by synthetic "MasterPrints," and a long-standing remote flaw in the Linux kernel's UDP receive path when the MSG_PEEK flag is used. Steve explains how to disable Google's search-result click tracking with uBlock Origin, discusses the Shadow Brokers' latest NSA Windows exploit dump (most already fixed by the March update), and describes the punycode homograph problem that still affected Firefox. Four years after ShieldsUP began testing for it, DefenseCode published full details of the Intel-derived UPnP remote root bug that affected many routers. Other items include a Princeton paper on visually muting rather than blocking ads, whether hiding a WiFi SSID helps, a Burger King ad that triggered Google Home devices, prime numbers in Conway's Life, and Steve's long praise for the Frontiers Saga. Listener follow-ups from the previous privacy episode cover email addresses as identifiers, TorrentFreak's VPN questionnaire, OAuth sign-in tracking, SNI leakage, and VPN leak testing with Whoer.net.

# Key points

- PINlogger.js (Newcastle University): web pages can read device motion and orientation sensors without any permission on Android browsers, and a neural network recovered 4-digit PINs from a set of 50 with about 83 percent success on the first try and 99 percent by the third. Some browsers allow inactive tabs, even with the screen locked in Safari, to read sensors. Steve advises using a scrambled keypad, and expects permission prompts like geolocation.
- MasterPrint (NYU and Michigan State): because phone sensors store multiple partial fingerprint templates, synthetic partial prints could match a large share of users (up to 65 percent in simulation). Steve asks listeners to test whether others' fingers unlock their phones.
- Linux UDP kernel flaw: all kernels before 4.5 mishandle UDP packets read with the MSG_PEEK flag, giving potential remote code execution without privileges or user interaction. Google patched Android in its April bulletin, but many embedded and non-Google devices will stay vulnerable; no concrete exploit was known yet.
- Google rewrites search result links with JavaScript to log clicks; a Safari extension (DirectLinks) or disabling scripts for www.google.com in uBlock Origin returns real links.
- Shadow Brokers released further NSA tools (EternalBlue, EternalRomance, EternalSynergy, EskimoRoll, EmeraldThread, EducatedScholar, EclipsedWing, others). Microsoft said all were fixed, the worst in the March MS17-010 update and others in 2008 to 2014, so patched machines are safe.
- Punycode phishing: a lookalike domain registered in punycode could display as apple.com in Firefox with a valid certificate. Chrome 59 fixed it; Edge, IE and Safari were not affected; Firefox users can set `network.IDN_show_punycode` to true.
- Motherboard piece noting government hacking tools keep leaking; Steve argues this undermines proposals for universal backdoors and favors company-by-company court-ordered compliance.
- DefenseCode published the full 2013 UPnP vulnerability paper (a sample implementation shipped in router firmware); ShieldsUP had found 51,854 exposed routers so far. Steve repeats: disable UPnP on the WAN side and update firmware.
- Princeton and Stanford researchers (including Jonathan Mayer) described an ad-blocker that overlays detected ads with a translucent label rather than blocking them, to avoid anti-adblock detection.
- Hiding a WiFi SSID gives little security: clients broadcast the names of networks they have joined, and anyone sniffing traffic sees the SSID of an active network; it also breaks auto-connect convenience.
- Burger King's TV ad deliberately triggered Google Home devices to read a Whopper description; Google blocked it.
- Prime numbers can be generated in Conway's Game of Life by a gun that emulates the Sieve of Eratosthenes.
- Follow-ups: email addresses link accounts across sites; TorrentFreak's annual VPN logging questionnaire; blocking third-party cookies can break some login flows (allow per site in uBlock Origin); ISP carrier-grade NAT would slightly weaken IP tracking; OAuth providers see where you sign in; SNI exposes site names even with DNSCrypt; Whoer.net tests VPN and WebRTC leaks, and WebRTC can be disabled in Firefox via `media.peerconnection.enabled`.
