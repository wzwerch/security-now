# Summary

Research from Confiant shows that half of major desktop browsers still allow zero-click downloads from cross-origin iframes, and Chrome only blocked them from sandboxed iframes in version 83. Google plans to penalize sites that abuse notification permissions starting with Chrome 84. BleepingComputer found that more than 380 domains use the ThreatMetrix fraud script that probes local ports, with banks and retailers among those observed. Facebook will require ID checks for rapidly viral posters, the ACLU sued Clearview AI under Illinois's biometric privacy law, and strings in Google Messages hint at end-to-end encrypted RCS. StrandHogg 2.0 is a stealthier Android task-hijacking flaw fixed only in Android 10, OpenSSH will disable SHA-1-based ssh-rsa signatures, and a new USB fuzzer found 26 bugs across operating systems. Steve reports finishing his USB boot-media preparation tool. The main topic is Zoom's published four-phase plan for true end-to-end encryption.

# Key points

- Drive-by downloads: JavaScript can create and click a hidden link to force a file download; Confiant found Chrome 83 blocks this only inside sandboxed cross-origin iframes (earlier versions did not), Firefox and Brave prompt, Safari stalls, and Android warns for APK files. Compromised first-party sites bypass any iframe protections, so Steve favors always prompting for downloads.
- Chrome 84 (mid-July) will warn about and from August block sites that trick users into notification permission or send phishing/malware-style notifications; sites get 30 days' notice via Search Console; resource-heavy ads will also be limited.
- ThreatMetrix reaches sites through CNAME-cloaked hostnames under online-metrix.net; BleepingComputer saw local port scans on sites including Citibank, TD Bank, Ameriprise, Chick-fil-A, Equifax IQ Connect, Sky and others (often only at login or checkout). Only Firefox with uBlock Origin blocked them; Chromium extensions cannot unmask CNAMEs, and Brave allowed the scans.
- Facebook will verify identities of people with a pattern of inauthentic behavior whose posts go viral in the US; unverified posts get reduced distribution. Steve views this as a reasonable accountability tradeoff.
- ACLU v. Clearview AI (Illinois BIPA): Clearview's database of billions of faceprints and its search app are alleged to violate consent requirements; the suit seeks deletion of Illinois residents' faceprints. Steve notes Firefox flagged a fingerprinter on the ACLU's own site.
- Google Messages 6.2 contains strings about end-to-end encrypted RCS, with fallbacks to unencrypted SMS/MMS requiring user choice.
- StrandHogg 2.0 (CVE-2020-0096, Promon): reflection-based task hijacking lets a malicious app impersonate any app, steal credentials and escalate permissions with no manifest traces; fixed in Android 10, so most devices stay exposed. Warning signs include redundant login prompts and permission dialogs lacking an app name.
- OpenSSH announced it will disable ssh-rsa (SHA-1) signatures by default because chosen-prefix collisions cost under $50,000; legacy embedded SSH servers complicate this.
- USBFuzz (to be shown at USENIX Security) found one FreeBSD, three macOS, four Windows and 18 Linux bugs (mostly memory bugs); researchers submitted patches for Linux.
- SpinRite: Steve finished a Windows tool that rebuilds any USB drive into bootable media with his own partition and file system code, to be reused for SpinTest, SpinRite and Beyond Recall.
- Zoom's E2EE paper (Zoom, Keybase alumni, Matthew Green, Alex Stamos, Lea Kissner): as of 30 May the per-meeting key creates per-stream AES-GCM keys, but Zoom servers still hold the meeting key, so it is not true end-to-end. Plan: Phase 1 client public-key management with key agreement (server must become active to attack); Phase 2 identity binding via single sign-on or tracked contact keys; Phase 3 a transparency tree (like Certificate Transparency/Keybase) plus in-meeting upgrade to E2EE; Phase 4 device-signing and real-time warnings. Curve25519/Ed25519 with a P-384 fallback for FIPS. Limits: no dial-in phones, cloud recording or legacy rooms in E2EE meetings; no timeline given.
