# Summary

Steve starts by explaining that the viral video of a robot arm ticking the "I'm not a robot" box proves nothing, since the checkbox was offered because the laptop already had a long reputation with Google. He then reports that Cisco's WebEx extension problem affected Firefox and Internet Explorer builds too (Edge on Windows 10 was spared). A Trustwave researcher's account of a Netgear router password disclosure bug shows how many models were affected and how Netgear's disclosure handling began to improve through a bug-bounty platform. Other items: Gmail will block .js attachments from mid-February, a hotel hit by ransomware that left guests unable to re-enter rooms moving back to mechanical keys, browser vendors' complaints about third-party antivirus, a CSS trick that hides extra commands inside text you copy and paste into a terminal, follow-ups on password complexity, and a SQRL status update about managed shared access. The main topic is a master's thesis surveying 20 laser printers and multifunction devices, all of which had at least one exploitable weakness, often through complex page-description language interpreters.

# Key points

- Robot arm and reCAPTCHA: the stunt only worked because Google already trusted the machine and user; a real bot would not be offered the checkbox.
- Cisco WebEx: the advisory expanded to extensions for Chrome, Firefox and Internet Explorer on Windows, tied to a design flaw in an API response parser; no workaround beyond updating, though Edge on Windows 10 was unaffected. Steve repeats advice to remove unused extensions.
- Netgear: a researcher stumbled on an unauthenticated page that revealed the admin password, then found a second flaw where the first call to a recovery page leaks credentials; over 10,000 exposed devices were seen and possibly far more. Netgear patched part of 31 listed models over nine months and joined Bugcrowd. Steve now considers remote administration unsafe on this router family.
- Gmail: attachments ending in .js are blocked starting 13 February 2017, in addition to other executable types and password-protected archives; Google suggests cloud links instead.
- Hotel ransomware: an Austrian hotel paid after repeated attacks on its key-card system (guests were not locked in, contrary to some reports) and plans to return to physical keys.
- Antivirus criticism: browser developers say AV hooks and TLS interception break security features such as ASLR and sandboxing and can add vulnerabilities; Microsoft's built-in Defender is considered acceptable.
- Copy-paste trap: CSS can hide extra text in a snippet so that pasting into a terminal runs more than what was visible; Steve advises pasting into a text editor first.
- Passwords: Steve clarified that last week gave the calculation method, not a recommended target; the strength depends on how a site hashes, salts and stretches passwords, which users cannot control. Pronounceable or memorable passwords mean lower entropy; adding material to a high-entropy base never reduces entropy. Algorithmic recipes risk revealing patterns.
- Google's security team clarified that Chrome only fills the card number field after the user types the card's security code, which limits the autofill attack. Quantum entanglement cannot send messages faster than light but can distribute one-time-pad keys.
- Development teams should have both security awareness across all developers and a dedicated full-time security owner.
- SQRL: Steve is back on the project; because SQRL identities are tightly bound to a person, he designed managed shared access so several people can use one account (for example, a family bank account) without sharing a single identity.
- SpinRite story: a user who ran CHKDSK with the recover-bad-sectors option destroyed files that SpinRite might have rescued.
- Printers ("traitors in our midst"): researchers tested 20 models from HP, Brother, Lexmark, Dell, Kyocera, Samsung, Konica and OKI with an open-source toolkit and found every one vulnerable to at least one attack, some to a dozen. Weak points include printer languages such as PJL and PostScript (a full programming language with file access), many network protocols, and physical access via USB. Attackers could cause denial of service, steal print jobs and files, or even use cross-site printing from a webpage to port 9100; printers could serve as long-lived footholds.
