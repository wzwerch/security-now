# Summary

Recorded on the day of Apple's iPhone 6 and Apple Pay announcement, the episode begins with Steve noting that Apple Pay's tokenised design looks promising and promising a deeper look once a whitepaper appears. September's Patch Tuesday was the quietest in a long time: one critical Internet Explorer remote code execution fix plus 36 less severe IE issues, an ASP.NET denial of service and a Windows 8 Task Scheduler privilege escalation. The big story is the Home Depot breach, caused by a variant of the BlackPOS malware used against Target, running on unpatched Windows XP Embedded terminals; stolen card data plus customer details let criminals reset debit PINs through bank phone systems and withdraw cash, with one bank losing about 300,000 dollars in two hours. Steve also covers Comcast injecting JavaScript notices into pages over its public Wi-Fi, and announces that Google will begin flagging SHA-1 certificates in Chrome in November 2014, which will be next week's topic. The Q&A includes the Ethernet ground-potential dispute (transformer coupling gives isolation), ATA Secure Erase versus Enhanced Secure Erase, why Apple's built-in SSDs lack the feature, how rogue base stations downgrade phones to 2G, how to install XP safely in a VM, flash wear, security questions and how Diffie-Hellman key exchange gives forward secrecy.

# Key points

- Patch Tuesday (September 2014): a single critical IE flaw (publicly disclosed, not yet exploited), 36 other IE fixes, one important ASP.NET denial of service, and a Windows 8 Task Scheduler elevation of privilege.
- Home Depot breach: a new variant of BlackPOS (the Target malware) on unpatched XP Embedded point-of-sale systems; PIN data itself was not stolen, but enough card and personal data was taken for fraudsters to reset PINs through automated bank phone systems and cash out at ATMs. Steve criticises using full desktop Windows in payment terminals.
- Comcast XFINITY public hotspots injected JavaScript into visited pages to show notices; critics saw this as tampering, and Steve notes it only works on plain HTTP unless the user accepts a rogue certificate, another argument for HTTPS everywhere.
- Google will mark SHA-1 certificates with a warning indicator starting November 2014, well ahead of Microsoft's 2017 cut-off, which angers certificate authorities.
- Steve corrects himself about USB, which is not simple single-ended signalling but uses a bidirectional data pair.
- SpinRite is useful on empty or newly wiped drives because the drive only learns about weak areas when forced to read them; quick format does not touch the surface.
- Ethernet is transformer-coupled, so the isolation transformers block ground-potential differences up to their breakdown voltage (such as a lightning strike); fiber remains the safest choice between buildings.
- ATA Secure Erase and Enhanced Secure Erase are firmware commands that are fast because no data is transferred; Enhanced reaches hidden regions, and firmware could in principle wipe remapped sectors, but vendors document little and one must trust them.
- Apple's soldered SSDs do not implement Secure Erase; for any SSD the better practice is to enable full-disk encryption before storing data so that stale flash blocks hold only noise.
- Threema and similar messengers solve crypto but not key-authentication plumbing or metadata; Steve again suggests leaving email alone and using new messaging systems with forward secrecy (Off The Record is open source).
- A 3G security designer explains that 3G and later networks authenticate the network to the phone, but phones fall back to 2G, which a fake base station can force by advertising only 2G; phones rarely display the required indicator that encryption is off.
- Installing XP in a virtual machine: apply all updates up to the end of support (Service Pack 3 plus all patches); only skip patching if the VM has no network access at all.
- Flash write endurance of roughly 10,000 cycles plus wear leveling make wear on a 64 GB tablet from daily podcast downloads a non-issue.
- Security questions: do not tell the truth; use per-site fabricated answers recorded in a password manager; phone-call-back verification is better.
- Diffie-Hellman: two parties each raise a public generator to a private random exponent modulo a public number, exchange the results and independently derive the same secret, giving ephemeral keys and perfect forward secrecy.
- CAcert is the free certificate authority that was dropped by Firefox, which Steve had been trying to remember; StartSSL is separate and is trusted.
- Zip-code prompts at gas pumps are a useful anti-fraud second factor even though they only suit US cards.
