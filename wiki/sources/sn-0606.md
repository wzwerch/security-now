# Summary

Steve opens with the aftermath of the US repeal of ISP broadband privacy rules, promising a full "proactive privacy" discussion that runs out of time and is deferred to the next episode. News items include iOS 10.3.1 patching a WiFi chip code-execution flaw, a Swiss researcher's over-the-air attack on Samsung Smart TVs, and the Z-Wave Alliance's Security 2 specification. The main technical story is the exact cause of Tavis Ormandy's shower revelation about LastPass: the extension used the "undefined" state of JavaScript variables as an on/off switch, and a web page could define those names through the shared DOM. Steve and Leo debate whether that was sloppy or idiomatic, and whether to keep using browser-integrated password managers. Further items cover the EU's plan to propose measures giving police access to messaging apps, Snowden's tweet about offense versus defense spending, Samsung's easily fooled face unlock, the Noiszy noise-generating extension, the 40th anniversary of the RSA paper that introduced Alice and Bob, listener feedback, and an update on SQRL and SpinRite 6.1.

# Key points

- iOS 10.3.1 fixed a stack buffer overflow in the WiFi chip allowing code execution by a nearby attacker, reported by Project Zero, with few details released.
- Researcher Rafael Scheel showed that fully patched Samsung Smart TVs could be compromised by a malicious DVB-T broadcast signal, reaching a web server running as root; Steve extrapolates to all TVs and standards and urges segmenting IoT gear, even keeping a scrubbed spare phone for IoT control.
- Z-Wave announced S2 security: DTLS-style secured datagrams, per-device public and private keys, elliptic-curve Diffie-Hellman key agreement, and mandatory use of the updated SDK for certification, though many older devices remain.
- LastPass flaw explained: browser extension content scripts run in an "isolated world" but share the page's DOM; LastPass relied on whether certain variables were undefined to enable code, and a page could set DOM properties that defined them. Over 3,000 instances had to be changed. Steve calls this ordinary JavaScript practice; Leo thinks it is sloppy, removed the browser extension, and prefers not to rely on JavaScript autofill, while still recommending password managers to newcomers. Steve keeps using LastPass because it is heavily vetted, and notes that site spoofing protection is lost if you use an external vault such as KeePass or Pass.
- LastPass's vault is encrypted client-side (PBKDF2 and salting), so the cloud copy cannot be cracked without a client compromise.
- The EU Justice Commissioner said the European Commission would propose measures by June, binding or voluntary, to speed police access to data from messaging apps; Germany and France backed it. Steve expects per-company, warrant-based access obligations rather than a golden key, with open questions about outlawing non-decryptable tools; Leo recalls 1990s export-grade 40-bit crypto as a warning.
- Border policy: reports that visitors may be asked for social media passwords.
- Snowden tweeted that US cyber offense is funded nine times more than defense; Steve disagrees that parity would help because defending everything is far harder than attacking one target, though he agrees critical infrastructure defense is underfunded.
- Samsung Galaxy S8's face unlock could be fooled by a photo; Steve says mixing toy security with real security muddies the message. Leo notes his banking app asks for a blink.
- Noiszy is a Chrome extension that generates fake browsing traffic to dilute tracking data; Steve is skeptical and prefers proactive steps.
- Mikko Hypponen marked the 40th anniversary of Alice and Bob from the 1977 RSA paper on public-key cryptosystems and digital signatures.
- Listener items: ISPs cannot force a certificate on a browser silently but could require an installable app, which IoT devices might not accept; libsodium adding Random.org as an entropy source worries Steve; no trustworthy IoT security rating site exists; Firefox `media.autoplay.enabled` can disable autoplay but may also block manual play; companies prefer SMS two-factor to collect phone numbers; GiftGhostBot affected a listener's gift cards.
- Project status: SQRL's server side is done and installer and self-update work is under way, after which Steve returns to SpinRite 6.1 and plans to offer it first to existing supporters.
