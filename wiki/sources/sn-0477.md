# Summary

Steve renames the planned "Apple Pray" topic to payment tokenization after digging into the background of Apple Pay. October's Patch Tuesday fixes a zero-day in the Windows OLE package manager (packager.dll), exploited by a Russian group that iSight Partners calls the Sandworm Team in spear-phishing attacks using PowerPoint files against NATO, Ukrainian and European government bodies, Polish energy firms, telecoms and a US academic organisation. The flaw exists from Vista SP2 onward, not in XP. Steve warns that disclosure and patch reverse-engineering will widen exploitation, so patch quickly. Firefox 33 downloads Cisco's open-source H.264 codec and halves memory for JavaScript strings. A rumour that a new SSLv3 flaw will be announced the next day is flagged; Leo reports an OpenBSD patch suggests use-after-free memory problems. Hundreds of Dropbox credentials appeared on Pastebin with a claim of nearly seven million; Dropbox says it was not hacked and the passwords came from other services. Steve describes work on a titanium dioxide nanotube battery anode for fast charging, then explains the main topic: EMVCo (Visa, MasterCard, American Express, Discover, JCB, UnionPay) defined a token scheme in which a token service provider keeps a vault mapping a token that looks like a card number to the real account number, so merchants and card-on-file stores hold only domain-bound tokens, and Apple's addition of Touch ID and the secure element gives high confidence and cheaper card-present processing.

# Key points

- Sandworm Team: Russian-linked group (Dune references in its infrastructure) used a Windows OLE packager flaw that runs arbitrary code via INF files, delivered through weaponised PowerPoint files; patched on October 14, 2014. Vista SP2 through Windows 8.1 and Server 2008/2012 were affected.
- After disclosure, attackers who knew of the bug will race to use it before systems are patched, so the window after Patch Tuesday is risky.
- Firefox 33 fetches Cisco's licensed open-source H.264 codec at runtime, since Mozilla cannot bundle it, and uses one-byte characters for JavaScript strings where possible (Gmail tab memory fell from about 11 MB to 5.5 MB).
- Rumored SSLv3 vulnerability (announced the following day) with an OpenBSD patch indicating memory corruption or use-after-free.
- Dropbox credentials on Pastebin: Dropbox says the usernames and passwords were stolen from other sites and reused, and had expired them; Steve thinks the claim of about 6.9 million accounts was a come-on for payment. Steve's phrase for the situation: the "Internet of Other People's Things."
- Fast-charging lithium-ion variant using titanium dioxide nanotubes reportedly reaches 70 percent charge in two minutes with 10,000-cycle life, because it modifies a well-understood chemistry.
- SpinRite: a listener asks about the DOS look; Steve says 6.1 and 6.2 stay in DOS, while SpinRite 7 will move to its own native-booting environment with a GUI, multi-drive operation, cloning and file-system awareness.
- Payment tokenization concept: a payment token stands in for the Primary Account Number (PAN), looks like a card number (13 to 19 digits, passes the Luhn check) and flows through existing networks unchanged.
- A Token Service Provider runs a Token Vault mapping tokens to PANs; tokens are random, not derived by encryption, and one real card can have many tokens, so breaches can be contained by cancelling a particular merchant's tokens.
- Tokens are domain-restricted (for instance usable only by a specific merchant or device), which adds a protection layer card numbers never had; Amazon-like card-on-file merchants could swap stored card numbers for tokens to cut compliance burden.
- Apple Pay: the card number is not stored on the phone or Apple servers; the phone holds a device token, a secure element and Touch ID provide a verifiable user binding, and a cryptogram (details not yet public) accompanies each transaction. Strong user binding lets Apple negotiate lower fees than card-not-present rates.
- The scheme originates from EMVCo's years-old specification, not from Apple; Steve expects Android phones with NFC and Samsung's similar announcement to benefit, along with the US move to chip-and-PIN terminals in 2015.
