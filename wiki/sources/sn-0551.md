# Summary

The episode is dominated by the escalating encryption dispute. A Justice Department filing hinted it could demand Apple's source code and signing key, officials were debating a court fight with WhatsApp over wiretapping end-to-end encrypted calls, and a Burr-Feinstein bill was about to be unveiled. Steve praised a John Oliver segment, and argued in his blog that technology can enable secure per-device access, so opponents should argue "we should not" rather than "we cannot". Other news covered Mozilla's chart showing HTTPS adoption growth quadrupled since Let's Encrypt, Cisco Talos research on Trane ComfortLink thermostats with hardcoded login credentials and installable malicious software, BleepingComputer being sued over a negative review, roughly 600,000 exposed TFTP servers offering a roughly 60-fold UDP amplification factor, and Microsoft folding a Windows 10 upgrade prompt into an Internet Explorer security update, with reports of unrequested upgrades. In the Q&A he discussed PCI delaying TLS 1.0 removal to 2018, multi-layer VeraCrypt encryption, localhost servers (as used by Jupyter notebooks), a trojaned all-purposes root certificate left by a recording program, user-agent header fingerprinting, SMART data and SpinRite, why blogs should use HTTPS, who invented public-key cryptography, and drive redundancy.

# Key points

- DoJ filing suggests it could compel Apple's source code and signing key; Steve calls the escalation silly. The New York Times reported a standoff with WhatsApp where a judge-approved wiretap was blocked by encryption; the Burr-Feinstein encryption bill was expected that week. Leo expects trouble passing Congress but a presidential signature.
- Steve's essay: separate the question of what technology can do (secure per-phone escrow is feasible) from what society wants; the case for strong encryption is better made on policy than on claims of impossibility.
- Mozilla chart: rate of HTTPS adoption quadrupled after Let's Encrypt launched, though the graph axis is non-zero-based. Apple's podcast servers reportedly reject Let's Encrypt certificates, likely due to an old client lacking the cross-signing root.
- Trane ComfortLink II: Cisco Talos reported hardcoded credentials with default remote login and two flaws allowing installation of persistent malicious software; Trane took long to respond. Steve again advises an isolated IoT network and wants router vendors to offer easy segmented networks with separate passwords.
- BleepingComputer is sued by the maker of SpyHunter after a negative review and asked for donations.
- TFTP (trivial file transfer, UDP port 69): about 599,600 reachable servers, 60-times amplification factor, no authentication; Steve wonders what the devices are.
- Microsoft's KB for IE11 security update included functionality to promote or start Windows 10 upgrades; Microsoft's official Windows 7/8.1 block remains the cleaner fix; Windows Server 2008 R2 is listed as eligible, which alarmed Steve. Reports of automatic upgrades without consent were circulating.
- A Windows Update client update (nicknamed Windows Update Update) is needed on fresh Windows 7 SP1 installs.
- PCI Council moved the TLS 1.0 and SSL migration deadline from June 2016 to June 2018. Steve moved his own XP to Service Pack 3 to handle SHA-256 certificates.
- Multiple cipher layers (AES, Twofish, Serpent) in VeraCrypt are fine; Steve says the weak link is storing the long random password in the password manager, so keep it on a thumb drive or printout.
- Jupyter notebooks run a localhost web server; same-origin policy includes the port, so the concern is small; Microsoft threatened to restrict localhost servers in Edge, which complicated SQRL's design.
- A recording application had installed an all-purposes root certificate in the system store, which Steve calls an abuse of the root store; the Sysinternals sigcheck certificate-store comparison could be wrapped in a monitor.
- User-agent headers add little fingerprinting risk compared with other data points.
- SMART data is non-standard and short-term; SpinRite uses its changes during a run.
- Blogs should use HTTPS to protect visitors from injection (Verizon supercookie example). Public-key cryptography was first conceived at GCHQ but invented independently by the RSA authors.
- Drive advice: no single drive is dependable; Steve uses an NVMe SSD kept mostly empty plus mirrored hard drives with nightly images, and RAID 6 at GRC.
