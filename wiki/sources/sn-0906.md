# Summary

Steve first checks whether LastPass's claim of extra server-side PBKDF2 rounds softens the low-iteration-count problem and concludes it does not: the server only hashes the login token further (about 100,000 more rounds plus scrypt) to protect that stored token, while the vault itself remains encrypted only with the client-derived key. A listener also explains that changing the iteration count re-encrypts old ECB entries as CBC, which resolves why Steve and others saw almost no ECB. Gen Digital (formerly Symantec/Norton LifeLock, also owner of Avast, AVG, Avira and CCleaner) disclosed roughly 6,450 customer accounts accessed through credential stuffing, which Steve suspects reflects missing login throttling and slow detection; he notes high client-side key stretching also slows login guessing. Google Chrome joined Mozilla and Microsoft in distrusting the TrustCor roots. The Chromium project announced support for third-party Rust libraries, tied to Google's "Rule of Two", and CrowdStrike reported Scattered Spider deploying a signed but vulnerable Intel Ethernet diagnostics driver, which Steve uses to argue that Microsoft is not proactively blocking known vulnerable drivers and that a third party should fill the gap. The episode's main section explains the Rule of Two: code should combine no more than two of untrustworthy inputs, an unsafe implementation language and high privilege, with mitigations such as sandboxing, normalising inputs into simple formats and keeping unsafe code small, encapsulated and documented.

# Key points

- LastPass whitepaper: the client derives the vault key via PBKDF2 and sends a login hash one round further; the server adds about 100,000 PBKDF2 rounds plus scrypt to that hash only. Vault encryption is unaffected, so the "iteration count of 1" risk stands. The explanatory help page appeared in the Internet Archive in July 2022, but the whitepaper statement dates from 2019.
- Key hierarchy note: the password-derived key usually decrypts the actual vault key, which allows password changes without re-encrypting everything; 1Password's secret key adds a high-entropy second secret at the cost of convenience.
- ECB versus CBC: changing the iteration count causes the client to re-encrypt all entries as CBC, so frequent users show no ECB; one listener still had 28 ECB items (mostly secure notes).
- Gen Digital: about 6,450 Norton LifeLock accounts, including stored credentials, compromised via credential stuffing starting 1 December, detected about 12 December; the statement that 925,000 accounts were "secured" is vague; Steve suspects slow, throttled bot logins and weak rate limiting.
- Chrome and Android removed TrustCor roots, following Mozilla and Microsoft.
- Google announced production support for third-party Rust libraries in Chromium within about a year; the goal is simpler satisfaction of the Rule of Two.
- Scattered Spider (also called Roasted 0ktapus, UNC3944): phishing and MFA fatigue for initial access, then legitimate remote-management tools; CrowdStrike saw a bring-your-own-vulnerable-driver attempt using a 2015 Intel Ethernet diagnostics driver; Microsoft's 2021 promise to block known vulnerable drivers by default has not been realised.
- Rule of Two (Chromium docs): of untrustworthy inputs, unsafe language (C, C++, assembly) and high privilege, pick at most two; safe languages include Rust, Go, Java, Kotlin, Swift, JavaScript; Rust code with `unsafe` must be small, encapsulated and documented.
- Chromium mitigations: run parsing in sandboxed or site-isolated low-privilege processes, defang complex formats (such as PNG) into simple bitmaps before handing them to privileged code; Chrome's many processes exist for containment. Known violations include JSON parsing in the Omnibox and an unsandboxed Windows network process.
- Statistic cited: around 70% of Microsoft-patched vulnerabilities are memory-safety issues; in Chromium only about 5 of 130 public critical bugs (as of March 2019) were not memory corruption.
- Listener observation: real words almost never appear by chance in truly random strings, illustrating how little entropy words carry.
