# Summary

The episode, recorded on a new Restream-based setup as Leo prepares to close the TWiT studio, begins with an urgent patch note: CVE-2024-30078, fixed in the June 2024 Patch Tuesday, lets an unauthenticated attacker within Wi-Fi range run code on any Windows machine using the native Wi-Fi stack, with no user interaction; it scored only 8.8 because of the proximity requirement and a public proof-of-concept already existed. Steve uses it to argue that Windows is too fragile to hold a Recall-style history, and then reports that Microsoft pulled Recall from the 18 June Copilot+ launch and moved it to Windows Insider testing first. He discusses Matthew Green's positive but cautious analysis of Apple's Private Cloud Compute, dismisses press claims of a CVSS 10.0 in WGET as a minor URL-parsing bug, and covers a Paris court order forcing Google, Cloudflare and Cisco to DNS-block about 117 pirate sports domains. After GRC email updates and listener notes, the main topic explains DNS CNAME records and how dangling CNAMEs to deleted cloud resources enable subdomain takeover, the class of problem behind last week's code.microsoft.com story. Steve urges anyone managing DNS to audit what their CNAME records point to.

# Key points

- CVE-2024-30078 (CVSS 8.8): a Wi-Fi driver remote-code-execution flaw affecting all supported Windows versions, needing only radio proximity, no authentication and no user interaction; a firewall does not help. Risk is highest in hotels and trade shows. Patch immediately.
- Recall: the 18 June general release was cancelled; it now goes first to Windows Insiders. Steve's point is that Recall changes the risk in kind, not degree, and that a certificate or private key displayed on screen would be captured by it.
- Apple Private Cloud Compute (analysed by Matthew Green): Apple-built servers with secure boot and Secure Enclave keys, tamper-sealed and imaged at manufacture, stateless nodes that re-key and wipe on reboot, attestation of the running software image, a public transparency log with a research VM, anonymous single-use credentials (RSA blind signatures) and a third-party OHTTP relay hiding IP addresses. Green's worries: users cannot opt out or see when data leaves the device, and flaws will be hard for outsiders to find. Steve warns of "me too" vendors imitating the idea without the rigour.
- WGET up to 1.24.5 mishandled semicolons in the userinfo part of a URL; reports claimed CVSS 10.0, but Red Hat rated it 5.4 and no exploit or remote vector exists.
- A Paris court ordered Google, Cloudflare and Cisco public DNS to block about 117 pirate sports streaming domains for Canal+ under Article L333-10 of the French Sports Code; Google's lawyer estimated roughly 800 people nationwide would be deterred. Steve notes a HOSTS-file entry or VPN bypasses it and argues the hosting operators are the true target.
- GRC email system: bounce handling nearly finished, pre-check of the domain part of addresses, plus-sign addresses supported; nothing has been sent yet.
- Listener notes: MailStore Home as a free local email archive (Steve's setup archives all mail and BCCs sent mail to a separate account); a former vendor employee doubts the New York Times' "leaked token" explanation after the company ignored security advice in 2010; Steve uses a reMarkable 2 tablet daily.
- Subdomain takeover explained: an A record maps a name to an IP, a CNAME maps it to another name (for example bingobango.azurewebsites.com); if the target service is deleted but the CNAME remains, an attacker can register the same cloud name and serve content that appears inside the victim's domain, enabling cookie theft, OAuth abuse and phishing.
- Data points: RedHunt Labs (2020) found over 424,000 subdomains with misconfigured CNAMEs, 139 of the Alexa top 1,000 potentially affected, with Shopify the most-implicated service and "www" the most commonly vulnerable name; a 2016 paper already described dangling DNS records. Advice: inventory your CNAMEs and remove those whose target is gone.
