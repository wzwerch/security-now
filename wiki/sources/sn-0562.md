# Summary

The Burr-Feinstein encryption backdoor bill effectively died, with Reuters reporting the CIA and NSA were ambivalent, the White House was split and legislators were reluctant to fight the tech industry in an election year. A jury unanimously found Google's use of Java APIs to be fair use, and Oracle vowed to appeal. Bloomberg's report on Android update fragmentation shows only 7.5% of Android devices on the newest release versus 84% for iOS; Google is ranking vendors by patch currency and shipping new features as standalone apps that work on old Android versions. Symantec had issued Blue Coat an intermediate CA certificate, raising concern that any trusted CA could mint interception-capable certificates; Steve notes any CA, including state-controlled ones, could do the same. Duo Labs found every one of ten laptops' preinstalled OEM updaters had a remote-code-execution weakness (unsigned manifests, plain HTTP, system privileges). Steve gives a detailed SQRL update (identity rekeying with up to four previous keys, a paper-recovery format with check characters, Wine compatibility issues) and then a first "meta" part on IoT: devices from vendors such as WeMo, LIFX, GE and MUZO leaving open bootstrap hotspots or weak crypto, and vendors that ignore reports, with Rapid7's baby monitor study promised for next week.

# Key points

- Burr-Feinstein bill: no sponsors, no path to passage; intelligence agencies feared interference with their own encryption use.
- Oracle v. Google: jury found fair use; Stanford Law's definition used to explain; Oracle intends a federal-circuit appeal.
- Android updates: Google's vendor ranking list, carrier testing burden (Verizon said it costs hundreds of thousands of dollars), and Google's strategy of decoupling features such as Allo and Instant Apps from OS versions.
- Blue Coat/Symantec intermediate CA: the intermediate's private key necessarily sits with the holder, so statements that Symantec kept full control are misleading; Steve stresses the weakness of trusting hundreds of root CAs.
- Duo Labs: every vendor updater (Acer, Asus, Dell, HP, Lenovo and others) had at least one flaw; manifests fetched over HTTP, unsigned, run with system rights; advice is to remove OEM bloatware or reinstall Windows (Microsoft's own update path is considered sound).
- Never10 passed 783,000 downloads at 35,000 per day; warning against bundled copies on third-party download sites.
- SQRL: identity stores current plus previous keys so websites can silently ratchet to a new key after rekeying; the paper identity is entered in groups with per-line check characters; base-56 alphabet drops confusable characters; Linux/Wine issues are being worked around; Steve says it is nearly done, then returns to SpinRite 6.1.
- Reader feedback: a sysadmin cut malware events by moving users from Internet Explorer to Chrome with uBlock Origin; Windows Update cannot be filtered by API because malware could abuse that.
- CVE/MITRE: explosion of IoT-related requests overloaded the CVE assignment process.
- Bitdefender IoT study: WeMo switch with weak static-key encryption, LIFX bulb bootstrap hotspot that could be spoofed to steal the Wi-Fi credentials, a GE hub sending configuration in clear, and a MUZO audio receiver with an open hotspot and default admin telnet; vendors unresponsive for six months.
- Steve's framing: IoT devices pretend to be single-purpose appliances but are general-purpose computers that need patching; isolate them on a segmented network and keep them off the internet.
