# Summary

Kaspersky's data shows mobile ransomware growing, dominated by screen-locking "blockers" (Fusob and Small families) rather than file encryption, and Steve repeats sideloading and patching advice. A researcher extracted Android full-disk-encryption keys from a Qualcomm-based phone by exploiting two already-patched TrustZone flaws, and Steve contrasts this with Apple's hardware-fused, never-readable device key. Google's Tavis Ormandy disclosed wormable, kernel-level remote-code-execution bugs in the unpacking engine common to Symantec and Norton products, which parse files through a filter driver, showing how security software enlarges attack surface. Brazil froze about $6 million of Facebook's funds over WhatsApp's inability to supply messages. TP-Link let a legacy router-setup domain expire, which is less dangerous than it sounds because routers answer the name locally. A one-star Amazon review exposed a Wi-Fi smart plug controlled through an unauthenticated server in China, and the maker pressured the reviewer. The main topic is Computest's findings on StartCom's StartEncrypt, an automated certificate tool whose validation could be tricked into issuing certificates for major domains such as Google and Dropbox via attacker-chosen paths and redirects.

# Key points

- Kaspersky: Android mobile ransomware affected about 136,000 users by April 2016, nearly quadruple a year earlier; blockers overlay the UI; Fusob avoids post-Soviet users and targets Germany, UK and US; Small targets Russia, Kazakhstan and Ukraine; payments via gift cards and vouchers.
- Advice: install apps only from official stores, keep unknown sources disabled, update promptly; Steve and Leo doubt the value of mobile antivirus.
- Android FDE uses dm-crypt, but keys managed through Qualcomm's TrustZone could be extracted using two earlier flaws (patched January and May 2016); about 37% of audited enterprise devices were still vulnerable; Hashcat's author offered to speed brute force; Apple's hardware UID with entangled passcode and fixed-cost key derivation is not extractable.
- Symantec/Norton: unpacker engine runs in the kernel via a filter driver, so emailing a malicious file can compromise a machine with no interaction; some components were old open source with long-known bugs; Steve stresses the attack-surface cost of security products.
- Lenovo/UEFI SMM issue deferred to next week.
- Brazil froze roughly $6 million of Facebook funds over unfulfilled WhatsApp orders; Steve sees the episode as reputational gold for end-to-end encryption.
- TP-Link's tplinklogin.net lapsed and was offered for sale, but routers intercept the name locally; Michael Horowitz's RouterSecurity.org recommends a business-class Peplink Pepwave Surf SOHO.
- IoT story one: a returned multicamera system was resold and sent alerts to the former owner; camera feed identifiers were enumerable.
- IoT story two: an AuYou Wi-Fi plug based on ESP8266 had broken setup, no real crypto, and cloud commands keyed only by MAC address; the vendor asked the reviewer to remove his critical review; the listing was later pulled.
- StartEncrypt flaws: client chose the validation path, allowing certificates for domains hosting user files (Dropbox, GitHub); the API followed redirects, so open redirects at OAuth providers enabled issuance for Google, Facebook and others; the client did not verify the server certificate; avatar uploads could serve as proof; private keys were saved world-readable (mode 0666).
- Steve defends independent security research and warns against laws that would chill it.
