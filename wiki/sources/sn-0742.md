# Summary

Steve opens with Google's apparent plan to return Android to a generic Linux kernel, since the stack of vendor and chip-maker patches on top of the LTS kernel makes security updates slow and error prone. He then covers a Kryptowire report finding well over a hundred CVEs in pre-installed apps and firmware on brand-new Android phones, concentrated in vendor "value add" software rather than stock Android. Kaspersky's audit of four open-source VNC implementations turned up 37 flaws, mostly client-side, with TightVNC 1.x abandoned and left unpatched. Twitter finally lets users disable SMS-based two-factor authentication after the SIM-swap compromise of its CEO. The Pennsylvania Supreme Court ruled 4-3 that compelling a computer password is testimonial and protected by the Fifth Amendment, rejecting the "foregone conclusion" argument. The main segment explains Microsoft's pre-announcement that Windows will support DNS-over-HTTPS, and why DoH rather than DNS-over-TLS is winning: it reuses HTTP/2 and could let a web server push pre-resolved DNS answers to the browser. Steve stresses DoH only hides the first hop from the ISP; DNSSEC is a separate signing protocol.

# Key points

- Android kernel: device kernels are the LTS base plus hundreds of out-of-tree changes (355 patches in early 2018), then SoC and vendor layers; Google appears to be moving toward an unmodified generic kernel with defined module interfaces, in line with Project Treble. Fuchsia remains a distant possible replacement.
- Kryptowire report: 146-147 CVEs in pre-installed apps and firmware across many Android brands; Samsung had the most, followed by ASUS and Xiaomi. Flaws allowed system property changes, command execution, app installation, audio recording. They cannot be removed and never passed an app-store scan, an argument for stock (Google) Android devices.
- VNC: Kaspersky found 37 bugs in LibVNC, UltraVNC, TightVNC 1.x and TurboVNC (UltraVNC had the most); mostly memory-handling errors on the client side. More than 600,000 VNC servers were visible on Shodan. TightVNC maintainers will not patch the abandoned 1.x branch.
- VNC advice: update, use strong random passwords, and restrict exposure by firewalling to known source IPs.
- Twitter now allows SMS 2FA to be disabled in favour of an authenticator app or hardware key, and the phone number to be removed; Leo explains the SMS short-code tweeting that enabled the Jack Dorsey SIM-swap hijack.
- A member of the group behind the Dorsey hijack was reportedly arrested.
- Pennsylvania Supreme Court (4-3): disclosing a password is testimonial (contents of the mind), unlike a biometric which is a physical act; the foregone-conclusion exception does not apply. Not settled nationally.
- Microsoft announced plans for native DoH in the Windows DNS client: automatically upgrade configured DNS servers that support DoH, block silent fallback once encrypted DNS is configured, and keep DNS decentralised.
- DoH design: ordinary HTTPS requests with DNS media types, same binary wire format, GET or POST, optional JSON form; browsers already support it (all major ones except Safari at the time).
- "Pushing DoH": a site that is also a DoH resolver could use HTTP/2 server push to pre-populate the browser's DNS cache with answers for all domains on the page, speeding page loads.
- DNSSEC signs records but gives no privacy; DoH gives privacy but only for the first hop. Firefox defaulted to Cloudflare under a no-retention pledge; ISPs such as Comcast lobbied against DoH.
