# Summary

Steve starts with GoDaddy's incident report: a September-to-January coding change made its domain-validation check accept error pages, so any web server that echoed the requested URL (including the random validation code) in a 404 page could pass, producing 8,850 improperly validated certificates plus about a hundred more from cached validations. He praises GoDaddy's rapid, transparent handling. Other items include whether a peace-sign photo can leak fingerprints, police use of connected-car telematics data, McDonald's website XSS and password-in-cookie design, the hack of phone-forensics vendor Cellebrite, Google's RAISR learned super-resolution, and a listener tip to avoid building RAID arrays from drives of a single manufacturing batch. He then states a formal test for a maximally strong password: any strategy that shortcuts brute force means it is not maximal, so only fully random characters qualify. The main topic is the Guardian's claim of a WhatsApp "backdoor." Steve explains that the Signal-based design offline-queues messages, and when a recipient's key changes WhatsApp silently re-encrypts and resends pending messages, a deliberate usability choice that a compelled server could exploit, but not a backdoor in the usual sense.

# Key points

- GoDaddy bug: validation compared content from any HTTP response regardless of status code, so a 404 page echoing the code counted; reported by a Microsoft customer, fixed the same day it reached management, affected certificates revoked within a day, and logged to certificate transparency. No known malicious exploitation. Steve contrasts this textbook response with WoSign.
- Biometric photos: high-resolution images could in principle expose fingerprints; Leo and Steve note successful past key and fingerprint reconstruction from photos.
- Cartapping: reporting showed police warrants have used satellite radio and telematics services to track or listen to vehicles for years, alongside smart-speaker and utility-meter data.
- McDonald's website: search results reflect user input into pages, giving cross-site scripting; an AngularJS sandbox escape allowed script execution that could reveal a user's password, which the site stored reversibly encrypted in a cookie with a static key. The researcher published after receiving no response.
- Cellebrite breach: about 900 GB of customer and product data obtained from the phone-extraction vendor, including indications of sales to authoritarian governments; verified by trying to register leaked email addresses.
- RAISR: a learned filter approach to enlarge and sharpen images quickly; Steve notes limits (cannot recover truly lost detail) but sees promise for bandwidth savings.
- Password definition: maximal strength requires every character to be random and independent; Diceware or word-based schemes, and Steve's own Haystacks idea, can be attacked with pattern-aware cracking. Podesta password anecdote: the widely quoted "password" claim was disputed; one email showed a temporary computer login.
- Drives in arrays should come from different batches because infant mortality clusters by production run.
- WhatsApp: pre-generated one-time prekeys allow asynchronous messaging. If a recipient reinstalls or changes SIM, Signal blocks and warns the sender, while WhatsApp silently asks senders' clients to re-encrypt unconfirmed messages to the new key and only notifies after the fact if the warning option is enabled. A researcher who reported it nine months earlier went public and the Guardian called it a backdoor. Steve says it is a design decision with security downsides, recommends turning on key-change notifications and verifying fingerprints, prefers Signal or Threema for high-risk users, and notes iMessage keys are managed by Apple.
- Telegram's homegrown cryptography is again criticised.
