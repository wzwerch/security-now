# Summary

Steve first dissects an IETF Standards Track draft that would shrink the IPv4 loopback range from 127/8 to 127.0/16 and make the remaining 16 million-plus addresses publicly routable. He considers it doomed because virtually every operating system, router and embedded stack hard-codes 127/8 as local and would silently drop such traffic, and he argues the real pressure relief would be IPv6 or reclaiming huge dormant /8 allocations. Microsoft's "Head of Deception" analysed 25 million brute-force attempts against an SSH honeypot, showing attackers favour very short passwords, while NordPass's yearly list again shows 123456 on top. GoDaddy disclosed that a compromised password gave an attacker two months of access to its Managed WordPress provisioning system, exposing data for up to 1.2 million customers. Netgear patched a pre-authentication UPnP buffer overflow (CVE-2021-34991) affecting 61 router models. The main topic explains HTTP request smuggling, where chained front-end and back-end web servers disagree about request boundaries because of conflicting Content-Length and Transfer-Encoding headers, allowing hidden requests to bypass front-end filtering.

# Key points

- IETF draft "Unicast Use of the Formerly Reserved 127/8" would keep only 127.0.0.0/16 as loopback and free the rest for general use. Steve notes RFC 1122 says such addresses must never appear on a network, some products (for example F5 BIG-IP) use other 127 subnets internally, and tweets from engineers pointed instead to legacy /8 blocks held by the DoD, IBM, HPE, Xerox and others (an IPv4 /8 was valued at over half a billion dollars, about $36 per address).
- Microsoft honeypot data (Ross Bevington): 77% of SSH brute-force guesses were 1-7 characters, about 30% were exactly six, only 6% exceeded ten characters, 7% contained a special character, 39% a digit and none contained a space. Steve concludes that long passwords (and passphrases with spaces) are rarely brute forced.
- Microsoft counted 14 billion honeypot attacks through September 2021: RDP attacks up 325% year over year, network printing services up 178%, Docker and Kubernetes up 110%. Advice: do not expose RDP to the internet; place it behind a VPN.
- NordPass 2021 list: 123456 (over 103 million hits), 123456789, 12345, qwerty, password; names, sports teams and "dolphin" are common choices. Leo recommends SSH key pairs (ssh-keygen) per machine instead of passwords.
- GoDaddy (SEC filing): a compromised password in a legacy Managed WordPress provisioning system exposed email addresses, customer numbers, original admin passwords, SFTP and database credentials and, for some, SSL private keys of up to 1.2 million customers; access lasted from at least 6 September to mid-November. It followed earlier GoDaddy incidents in 2019-2020.
- Netgear CVE-2021-34991 (CVSS 8.8): unauthenticated stack overflow in the UPnP daemon's handling of HTTP UNSUBSCRIBE requests, giving root code execution on 61 SOHO router models, reachable from the LAN (for example via browser script) and, where UPnP is exposed, the WAN. GRC's UPnP exposure test has recorded 55,166 exposed routers. Steve urges Netgear owners to update.
- HTTP request smuggling (desync): HTTP allows both Content-Length and chunked Transfer-Encoding to delimit a body, and the spec says Content-Length is ignored when both appear. If front-end proxy and back-end server treat them differently (CL.TE, TE.CL, or TE.TE with an obfuscated header), an attacker can embed a second request that the front end sees only as body data but the back end executes, bypassing firewalls and enabling cache poisoning, session hijack and similar attacks.
- Northeastern University and Akamai's "T-Reqs" paper used grammar-based differential fuzzing across ten server/proxy/CDN products (CloudFront, Cloudflare, Akamai, Varnish, Squid, HAProxy, ATS, Tomcat, NGINX, Apache) and documented which pairs are prone to smuggling. The technique was first described in 2005 but has become practical with multi-tier cloud architectures.
