# Summary

Steve and Leo mark the 500th episode, and Steve announces he turns 60 in two days. The news starts with a hardware box that could brute-force four-digit iPhone PINs on iOS up to 8.1 by cutting power right after each wrong guess, before the failed-attempt counter was saved; Apple fixed it in 8.1.1 by incrementing the counter before testing the guess. A second certificate incident follows the Live.fi case: Live.be was also abused via an administrative mailbox alias, and a worse case emerged where China's CNNIC had issued an intermediate signing certificate to Egypt's MCS Holdings, which put it into a traffic-inspection proxy. Chrome's built-in pinning of Google certificates exposed the forged Google certificate, and Chrome and Firefox (via a new OneCRL list in 37) distrusted it. Pwn2Own at CanSecWest paid out a bit over 440 thousand dollars in total, more than half to one Korean researcher who chained bugs to break Chrome, IE11, and Safari. The main topic is the evolution from the classic BIOS to UEFI and how Secure Boot and Measured Boot work, followed by the controversy that Windows 10 OEMs may omit the switch for turning Secure Boot off. Steve concludes that locking down boot is necessary against bootkits but that a non-removable lock turns a PC into an appliance.

# Key points

- iPhone/iPad PIN brute force: a hardware device with probes inside the opened phone tried a PIN and cut power before the retry counter was written, defeating the erase-after-10-attempts protection on iOS through 8.1. Apple's fix in 8.1.1 was to pre-increment the counter. Longer passcodes were not affected in practice.
- Live.be joins Live.fi as a domain where an attacker could obtain a certificate by registering an administrative mailbox name that Microsoft had not reserved.
- CNNIC issued an intermediate certificate to MCS Holdings, which was only supposed to be used for its own domains but ended up in a man-in-the-middle proxy. A Chrome user behind it triggered the alarm through Google's certificate pinning.
- Chrome added the certificate to its CRLSet (an 11-entry list of blocked non-expired certificates); Mozilla planned a similar OneCRL list in Firefox 37. Steve notes that standard revocation does not work, so browsers curate manual lists, and the system is brittle.
- Steve defends certificate expiry as the thing that keeps the revocation lists short.
- Pwn2Own 2015: bugs found in Windows, IE, Firefox, Adobe Reader and Flash, Safari and Chrome. The top researcher took 110k for Chrome (a race condition plus kernel driver bugs), 65k for IE11 64-bit (time-of-check to time-of-use), and 50k for Safari (use-after-free), with exploit chains of several bugs.
- Steve notes the Pwn2Own exploits relied on prior static code analysis and mentions Chrome Native Client as a future topic.
- BIOS history: the original IBM PC BIOS was a hardware abstraction layer (INT 13 disk, INT 10 video) that programs increasingly bypassed; by the mid-1990s it could not handle networking boot, inventory, thermal control and RAID, leading to EFI/UEFI.
- UEFI Secure Boot: a platform key burned in by the manufacturer verifies the first firmware; KEK, allowed-signature and forbidden-signature databases decide which signed modules or hashes may run; option ROMs and the OS boot loader are all checked; rollback to older firmware is prevented.
- Measured Boot logs each boot step into the TPM so a signed audit trail can be verified remotely; Secure Boot plus Measured Boot make "Trusted Boot." Windows hands over to the ELAM early-launch antimalware driver.
- The UEFI spec was close to 3,000 pages and amounts to a small operating system inside the motherboard.
- Controversy: Windows 8 logo rules required a user switch to disable Secure Boot, but Windows 10 desktop OEMs may omit it, and Windows 10 Mobile must not allow disabling. Without that option, Linux or other OSes cannot be installed.
- Leo contrasts this with the Chromebook developer-mode approach (Coreboot); Steve notes Linux can still use Secure Boot with signed components.
- SpinRite impact: Steve says that if Secure Boot becomes mandatory, a kernel-driver version of SpinRite signed with his Authenticode certificate could be an answer.
- Brief SQRL versus FIDO exchange: Steve argues FIDO lacks identity recovery and relies on hardware, whereas SQRL is software-only.
