# Summary

Steve begins with Chrome's 16th in-the-wild zero-day of 2021 (CVE-2021-4102, a V8 use-after-free fixed in 96.0.4664.110) and uses it to argue that software security barriers are merely porous: the closer attackers and researchers look, the more is found, as shown by Log4j's follow-up bugs. A Firefox misfire is explained: Microsoft dropped the SHA-1 hash from the certificate IDs in its OCSP-stapled responses, and Firefox had never enabled SHA-256 support there, so it refused Microsoft domains until 95.0.1. Mozilla also stopped Firefox from sending copied passwords and private-window content to Windows Cloud Clipboard. Two research papers follow: spoofable signal-strength reports in the cellular handover procedure (letting a rogue cell site, a Stingray, attract victims from farther away) and "coexistence" attacks in which a Bluetooth chip can escalate into a WiFi chip through shared hardware interfaces. The Log4j segment covers the incomplete first fix: CVE-2021-45046 (initially 3.7, raised to 9.0) fixed in 2.16.0, and CVE-2021-45105 (7.5, denial of service via recursion) fixed in 2.17.0. Google's open-source team found about 35,863 Maven Central packages (about 8% of the index) affected, mostly through indirect dependencies up to eight levels deep, so full remediation could take years. Ransomware (Khonsari, then Conti against VMware vCenter), initial access brokers, APT groups and cryptominers all moved within days; Steve expects Log4j fallout to run through early 2022.

# Key points

- Chrome: sixteenth zero-day of 2021 (CVE-2021-4102, V8 use-after-free); Steve prefers Microsoft's idea of dialing back Chromium optimisations to cut attack surface.
- Firefox could not open microsoft.com for about a day because of SHA-1 removal in OCSP stapled responses combined with OCSP Must-Staple certificates; fixed in Firefox 95.0.1. Lesson: tightly locked-down security needs every link in the chain to work (compare HSTS with long lifetimes).
- Windows Cloud Clipboard (Windows+V history synced to the Microsoft account, off by default) would have stored copied browser credentials; Firefox 94 now keeps about:logins copies local and excludes private-window content, but Chromium browsers do not.
- Paper "Don't Hand It Over": unverified signal-strength reports in cellular handover (2G-5G) let an attacker force devices to a rogue base station for denial of service or man-in-the-middle; it lowers the proximity needed for Stingray-style attacks. HTTPS limits the impact.
- Paper on wireless coexistence: Broadcom, Cypress and Silicon Labs combo chips let a Bluetooth chip extract WiFi credentials and run code on the WiFi chip, and WiFi can reveal Bluetooth keyboard timing; only partial fixes are possible without chip redesign.
- Log4j updates: 2.15.0 incomplete in non-default configurations; 2.16.0 effectively disables JNDI lookups; 2.17.0 fixes a recursion denial of service (Java 7 users need 2.12.2). Apache's maintainers concluded JNDI in logging was too risky to leave on.
- Affected vendor list now spans Akamai to Zscaler (Cisco, VMware, Ubiquiti UniFi, IBM, Okta and many more); about 10 attacker groups and 1.8 million exploit attempts were recorded within days; Check Point counted 60 variants of the exploit string.
- CISA ordered federal agencies to remediate by 24 December; Steve says full remediation is unrealistic. A new local attack vector via browser WebSocket to localhost services was reported by Blumira.
- Google's Maven analysis: 35,863 affected packages; only about 7,000 depend on Log4j directly; deep chains must be fixed bottom-up in sequence; under half of Maven packages hit by past critical flaws were ever fixed; 4,620 had been fixed within a week.
- Exploitation: Khonsari ransomware (low-quality .NET, Windows only) first seen on 11 December; Conti scanning and targeting vCenter from 13 December; Microsoft saw initial access brokers selling Log4j footholds; Dragos warned about industrial control environments.
- Practical doubts raised: deleting log4j jars is not viable because it can be compiled in; a "Never Log4j" detector would be useful; Leo notes Grype and Huntress' tester as scanners; Leo expects Zero Trust to gain momentum.
- Leo mentions Project Zero's analysis of the NSO FORCEDENTRY iMessage exploit (a fake GIF triggering a PDF decoder and a logic-gate-based virtual machine).

# Other segments

- Picture of the Week: Uncle Sam asking a media figure how to wrap "control of end-to-end encryption" with anti-terrorism and protect-the-kids paper.
- SpinRite: pattern emerging that new code works on modern hardware and fails on very old boards that the BIOS used to mask; several ASUS boards bought on eBay to reproduce.
- GRC now runs GitLab on an isolated FreeBSD server with outbound-only access for SpinRite problem tracking; StopForumSpam praised for eliminating fake forum registrations.
