# Summary

The Picture of the Week is a Shell poster that likens passwords to underpants, which prompts a reminder to use a unique password everywhere and a mention of NIST dropping forced password rotation. Troy Hunt praised Disqus for notifying and protecting users within about 24 hours of learning of a five-year-old breach of 17.5 million accounts (salted SHA-1 hashes). Apple's High Sierra supplemental update fixed an APFS bug where an encrypted volume's password hint stored the actual password, and Steve describes the burdensome cleanup. The proposed security.txt convention is presented as a brilliant robots.txt companion that tells researchers whom to contact. Microsoft backported TLS 1.1 and 1.2 for the XP-based POSReady line, and Firefox set June 2018 as its end of support for XP and Vista. After listener feedback on early Security Now series, Bitdefender BOX, RAID levels and NAS choices, the main topic is DNSSEC: 20 years after the first RFC, adoption is partial and ICANN postponed the root key-signing key rollover because newly available telemetry showed many resolvers were not ready.

# Key points

- Disqus breach (disclosed by Troy Hunt): contacted, verified, forced password resets and published within 23 hours 42 minutes; apologised and gave details. Steve says mistakes are forgivable but policies and response are what count.
- Matthew Green's remark: sufficiently advanced incompetence is indistinguishable from malice.
- APFS encrypted-volume bug in macOS High Sierra: the password hint field stored the real password in plaintext for newly created encrypted APFS volumes; fixed in the supplemental update, but affected volumes had to be backed up, erased and recreated. Leo notes it mainly affected secondary volumes. A Keychain weakness was fixed in the same update.
- security.txt: a text file in a site's root with Contact, Encryption (PGP key), Disclosure policy and Acknowledgment fields so researchers can report problems; voluntary, like robots.txt.
- Windows XP news: Microsoft backported TLS 1.1/1.2 to POSReady-line XP; Steve uses the registry trick to be treated as POSReady and plans to leave XP when Firefox support ends in June 2018.
- Rice University researchers reported an asphalt-derived additive for lithium metal batteries enabling five-minute charging and suppressing dendrites; still lab stage.
- Recommended early series: episodes 233 to 254 ("Let's Design a Computer" through "What We'll Do for Speed").
- Bitdefender BOX: a subscription home appliance; Steve is sceptical about inspecting encrypted traffic and IoT claims, but sees value with companion clients and its cloud bad-URL list.
- Netgear published a wave of security updates; owners should check for firmware.
- RAID: RAID 10 gives speed but only survives some two-drive failures, so RAID 6 is safer; monitor the array. NAS advice: Drobo for ease, or a self-built FreeBSD/Linux ZFS box (needs plenty of RAM).
- Trimming a large root trust store: Steve suggests passively logging the certificate signers actually seen on the network for a long period, then removing roots never used.
- DNSSEC: RFC 2065 (1997) was scrapped and redone (RFCs 4033-4035) because it would not scale. It would enable DANE and could reduce reliance on hundreds of CAs. Adding signatures enlarges small DNS packets and burdens servers; elliptic-curve keys help. ICANN delayed the root KSK rollover (2010 keys to 2017 keys) after Verisign's analysis of RFC 8145 trust-anchor signalling showed many resolvers unprepared.
- Adoption: about 89% of generic TLD zones and 47% of country TLDs are signed; .gov around 88%; only about 0.5% of .com zones, which is still about 600,000 zones. Last-mile validation by clients is still needed. Steve notes GRC is not yet signed and expects DNSSEC to spread like HTTPS did.
