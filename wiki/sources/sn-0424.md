# Summary

After a quiet news week, Steve unveils SQRL, which he pronounces "squirrel" and expands as Secure QR Login. His design goals are anonymity, no linkage between sites, no keyboard entry, no shared secrets, out-of-band authentication, no third party, low friction, simplicity and free adoption alongside existing logins. In the scheme, a site shows a QR code containing its login URL plus a fresh random nonce. The user's phone app keeps one lifetime 512-bit master identity key, combines it with the site's domain name using an HMAC to derive a per-site private key, derives the matching public key, signs the whole URL, and sends the public key and signature to the site. The public key becomes the user's identity at that site, so sites cannot correlate users and nothing secret is stored there. The app is guarded by a local password; exports of the master key as a QR code are encrypted with a deliberately slow, memory-hard Scrypt operation taking about a minute, which resists brute force. The app shows the target domain to defeat a relaying "evil domain" phishing attack. Steve covers multiple users, mobile login with a link or paste, and browser plug-in variants, invites attack review in a new GRC newsgroup, and says he will return to SpinRite. The news items include a blog arguing fingerprints are usernames rather than passwords, IE6 falling below five percent share, BitTorrent Chat's undocumented alpha, and the expired SSL certificate on a presidential campaign site.

# Key points

- Fingerprints as usernames: a biometric is a name that cannot be changed, so it suits identification but not secrets; it should be one factor of two.
- IE6's global share dropped below 5 percent, probably because people left IE altogether for Chrome or Firefox.
- BitTorrent Sync and the new BitTorrent Chat alpha lack protocol documentation, so Steve cannot recommend them; LastPass earned his endorsement by disclosing its design.
- Errata: the NSA is at Fort Meade, not Langley. The BarackObama.com certificate expired during a US government shutdown, which Steve uses to praise certificate expiry for keeping revocation lists short.
- SQRL requirements: no shared secrets, no third-party federation (federation is dead post-Snowden since third parties can be compelled), free, simple enough for one developer, able to run beside passwords, and usable on untrusted computers without typing credentials.
- Protocol: HTTPS request to the site's SQRL URL with the public key and a signature over the entire URL including the nonce, which blocks replay; keys derived deterministically per domain so each site sees a different identity. The master identity key never leaves the device except in encrypted export form.
- Cryptography: HMAC to derive 512-bit per-site private keys, Curve25519 elliptic curve signatures, Scrypt for password-based protection with about 60 seconds for exports and about one second for routine unlocking.
- Phishing defense: the app displays the full domain from the QR code in large type so the user can notice a code relayed from a different site; even then only a login session, not identity, is exposed.
- Practical: multiple identities per app, copy-paste or an sqrl:// link for same-device login, browser plug-in alternative that can compare domains automatically, and a printed paper backup of the master key for recovery. Users first link their SQRL identity to an existing account by one traditional login.
- Steve states he claims no ownership, there is no patent concern, and standards (interoperability) will be needed; discussion moves to the grc.sqrl newsgroup, with introduction pages under GRC's research section.
- Google's earlier QR login experiment only transferred a normal login to the phone, unlike SQRL.
