# Summary

Chrome 86.0.4240.198 fixed two more in-the-wild zero-days (a V8 flaw and a site-isolation use-after-free), bringing five in three weeks, which Steve uses to argue for fast autonomous update cycles for anything connected to the internet. Intel 471 counted more than 25 ransomware-as-a-service portals, with DoppelPaymer, Egregor, Ragnar Locker, REvil and Ryuk at the top, and Ragnar Locker used a hijacked Facebook account to run an ad pressuring Campari. November Patch Tuesday fixed 112 flaws, including the Windows cryptography driver zero-day and a 9.8-rated NFS remote code execution bug. NortonLifeLock research found Google Play accounts for most unwanted Android installs only because it accounts for most installs overall. Steve shares listener feedback and SpinRite/ReadSpeed progress. The main segment covers SAD DNS from UC Riverside and Tsinghua: an ICMP rate-limit side channel lets an off-path attacker discover the random UDP source port of DNS queries, shrinking the guessing space and re-enabling cache poisoning of the kind Dan Kaminsky exposed in 2008.

# Key points

- Chrome zero-days: both fixes were reported anonymously; update pushed within days. Steve's model: researchers report privately, vendor pays, quick patch push.
- Intel 471's RaaS report: 25+ portals renting ransomware; a few top players take most extortion revenue while many smaller players try to move up.
- Ragnar Locker compromised a DJ's Facebook account (no two-factor on that account) to run an ad threatening to publish 2 TB of Campari data; the ad reached about 7,150 users and Facebook caught it before further billing. Steve sees public shaming as a response to better backups.
- Patch Tuesday: 17 critical, 93 important, 2 moderate; 24 remote code execution fixes across Excel, SharePoint, Exchange, NFS, GDI+, print spooler and Teams. The NFS flaw matters mainly where shares allow anonymous write; Shodan showed about 38,900 hosts on port 2049. 0patch had not yet issued a Windows 7 fix for the crypto driver flaw.
- Android study (17 pages, 12 million devices, 7.9 million apps): 10-24% of devices met at least one unwanted app; Google Play accounted for 87% of installs and 67% of unwanted installs, alternative markets 5.7% of installs and over 10% of unwanted ones, bloatware about 6%; backup restore and web downloads also matter. Advice remains not to install apps just because they are there.
- Listener feedback: InitDisk helps reuse USB sticks after burning Linux ISOs; Steve explains why old Android devices cannot be forced to upgrade, with the Let's Encrypt root issue as context.
- SpinRite work: a bogus PCI register value caused drives to appear and disappear when an unused USB stick was present; a sanity check fixed it. ReadSpeed will be released via forums.grc.com, then SpinRite 6.1 betas for SpinRite 6 owners.
- SAD DNS recap: DNS replies must match the query's UDP source port and 16-bit transaction ID; the 2008 fix added source-port randomization (32 bits of entropy). SAD DNS uses the global ICMP error rate limit (50 per interval on Linux) as a side channel: spoofed probe packets from many source IPs plus a verification probe reveal whether any port in a batch is open, letting an attacker find the port first, then the transaction ID, for roughly 2^16 plus 2^16 guesses. Affected: BIND, Unbound, dnsmasq on Linux 3.18 to 5.10, Windows Server 2019, macOS 10.15, FreeBSD 12.1; about 35% of open resolvers, and public services including Google 8.8.8.8 were vulnerable at publication. The Linux fix randomizes the ICMP rate limit; Cloudflare reported mitigation. Steve notes certificate-based HTTPS reduces but does not remove the impact.
- Steve compares the divide-and-conquer trick to the WPS PIN weakness.
