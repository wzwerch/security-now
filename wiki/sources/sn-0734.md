# Summary

An evergreen episode recorded ahead of Steve's European trip, so it has little news. It opens with Mozilla's plan to roll out DNS-over-HTTPS by default to US Firefox users in stages, with fallback to system DNS when split-horizon heuristics trigger, automatic disabling when parental controls or enterprise policies are detected, and a canary domain for parental-control providers. The EFF welcomes DoH but warns about centralization and asks ISPs to offer DoH themselves. Steve reminds listeners of Cloudflare's WARP mobile VPN and Mozilla's new browser VPN. The main body covers his months-long search for a secure way to synchronize files across two locations under a "trust no one" (TNO) model. He settles on Sync.com for zero-knowledge cloud sync with web access and Syncthing for peer-to-peer LAN and device sync, mentions Cryptomator and Boxcryptor as encryption layers, and Leo adds pCloud as a Linux-capable option.

# Key points

- Mozilla (Selena Deckelmann): 70,000+ users already enabled DoH; in the experiment about 9.2% of users triggered split-horizon heuristics and 4.3% used OpenDNS parental controls or Google SafeSearch; rollout in the US begins late September at a small percentage, with opt-out and a fallback mode.
- A canary domain lets network-level parental-control providers signal Firefox to disable DoH; Mozilla says it will revisit if abused.
- EFF: encrypted DNS closes a major privacy gap alongside TLS 1.3 and encrypted SNI, but concentrating DNS in a few resolvers is a risk; it urges ISPs to deploy DoH and resolvers to adopt Mozilla's Trusted Recursive Resolver policy. UK ISPs had criticized Mozilla over DoH and content blocking.
- DoH hides lookups only; destination IP addresses remain visible; Cloudflare's WARP and Mozilla's VPN address that with centralization trade-offs.
- Steve's requirements: TNO client-side encryption, versioning (also helpful against ransomware), selective sharing, and cross-platform access.
- Sync.com: Canadian zero-knowledge service; RSA-2048 private key encrypted with AES-256-GCM under a PBKDF2-stretched password; per-file AES-256-GCM keys; bcrypt for authentication; web panel decrypts locally using the Stanford JavaScript Crypto Library; share links keep the password in the URL fragment; shared folders use key wrapping; email password recovery is off by default; pricing compared with Dropbox; no native Linux client yet (Synology client exists).
- Steve uses a Windows directory junction (mklink /J) so a folder stays at its original path while physically living inside the Sync folder.
- Syncthing: open source Go peer-to-peer sync with TLS device identities derived from certificate hashes, local discovery plus global discovery and relay servers (self-hostable), NAT traversal, block-level transfers, configurable versioning; runs on Windows, macOS, Linux, BSDs and Android (no iOS client at the time); SyncTrayzor suggested for Windows.
- Cryptomator is recommended as an open-source encryption layer over existing cloud storage; Boxcryptor's free tier is limited to two devices and one provider.
- Other options mentioned: ownCloud/Nextcloud, Cryfs, Syncovery, Duplicati, Tresorit, pCloud (Leo notes Linux support and optional encryption).
