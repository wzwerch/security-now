# Summary

Steve and Leo cover CanSecWest 2014, where Pwn2Own contestants broke every major browser (Chrome, Internet Explorer, Safari, and Firefox four times) plus Flash and Adobe Reader, and where researchers showed that iOS 7's "early random number generator", used before the system has good entropy, is a weak linear-congruential design, which undermines kernel address randomization and stack canaries should another bug be found. Steve explains vulnerabilities versus exploit mitigations such as ASLR. He then returns to Windows XP, arguing against the end-of-support panic with five steps for running it after April 8: use a limited account, remove Flash and Java, use Chrome or Firefox instead of Internet Explorer, replace or lock down Office, and stay careful (never use XP on open WiFi). Google's cloud storage price cut prompts a promise to revisit trust-no-one cloud storage, and a Wired ten-point plan against NSA surveillance is checked against the show's long-standing advice. The second half of the iOS security discussion covers the secure boot and update chain recap, Secure Enclave random number generation, locking behavior with and without Touch ID (keys discarded after 48 hours or five failed fingerprint attempts, and after reboot), four file data-protection classes, passcode strength, app signing and sandboxing, execute-never memory protection and the authenticated accessory chip program. A third part on jailbreaking is planned. SQRL translation volunteers have reached 48 languages and Steve has started coding.

# Key points

- Pwn2Own at CanSecWest: all major browsers fell to zero-day exploits; Firefox was beaten four times with fully patched builds; Mozilla cannot match 50,000 dollar bounties. Zero-days affecting XP will fetch premium prices after support ends.
- iOS 7 early random number generator: a linear congruential generator, which an attacker can run forwards and backwards once any state is known; pieces are reused across ASLR, canaries and kernel address randomization, so the weakness matters only when combined with an exploitable bug, but it shows no cryptographer reviewed the design. Steve notes hardware randomness from the Secure Enclave could be used.
- Vulnerability versus mitigation: ASLR, stack canaries and execute-never bits make bugs harder to exploit and depend on good randomness.
- XP: John Dvorak argued Microsoft is wasting revenue by ending XP support; Steve proposes five steps, including limited user account, no Flash or Java, no IE, and caution on open networks. He considers ATM and embedded XP alarmism overblown, noting Diebold's worry about small banks that lack extended support licences.
- Google cut cloud storage prices (100 GB from 5 to 2 dollars per month); Steve computes disk costs and plans an updated cloud-storage roundup focused on trust-no-one providers.
- Wired's 10-point plan (end-to-end encryption, friendly built-in encryption, HTTPS everywhere, HSTS, encrypted datacenter links, perfect forward secrecy, secure software downloads, shorter retention, replacing Flash with HTML5, funding open-source audits) matches themes Steve has covered. Taylor Hornby suggested browsers flag non-HTTPS sites.
- iOS data protection: Complete class discards keys at lock; Protected Unless Open uses per-file elliptic-curve key agreement for background writes; Protected Until First User Authentication keeps keys until reboot; No Protection class keeps keys in effaceable storage mainly for fast remote wipe. Each file has its own random AES key.
- With Touch ID the class keys are kept wrapped until the Secure Enclave discards them after 48 hours idle, five failed fingerprint attempts or a reboot, so a restart forces the passcode; Steve suggests powering a stored device off.
- Passcodes feed key generation and are strengthened with an iterative function tied to the device key; complex alphanumeric passcodes are far stronger than four digits.
- Apps must be signed with Apple-issued developer certificates, run sandboxed in randomly named directories and use hardware execute-never protection. Accessories must contain an Apple authentication chip.
- Leo recalls reports (Declan McCullagh) that Apple had a queue for unlocking iPhones for police; Steve thinks the Secure Enclave design may make that impossible for new devices.
- Mention of a VPN provider that accepts bitcoin so payments need not reveal identity.

# Other segments

- SQRL: translation volunteers now cover 48 languages; Steve is writing the first Unicode-aware code and sought a clearer squirrel icon for the system tray (the mascot logo rights were bought).
- SpinRite: a listener runs monthly Level 4 maintenance after an earlier recovery; Steve says regular maintenance should catch weak sectors before failure.
- Steve's experiment with a stubble beard on camera.
