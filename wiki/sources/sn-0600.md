# Summary

Episode 600 opens with Microsoft's February 2017 Patch Tuesday being cancelled outright and pushed to March, leaving known flaws unpatched, including a publicly disclosed Project Zero bug in a Windows graphics API. News items cover CyberX's "Operation BugDrop" (microphone-hijacking espionage against Ukrainian targets), an IBM researcher who could still control his old car via a phone app two years after trading it in, Chrome 56 hiding certificate inspection, and Mozilla's timeline for ending legacy Firefox add-ons by Firefox 57. A Windows lock-screen clipboard leak, NVIDIA kernel driver bugs, a free Stanford/NYU cryptography textbook and pfSense/Ubiquiti and miniLock follow-ups round out the news. The main segment explains the "ASLR Cache" (ANC) attack from Herbert Bos's VUSec group at the University of Amsterdam, which uses timing of shared CPU caches to learn memory layout from JavaScript. Steve stresses that the press got the details wrong but the concept right: it is an architectural design problem, not a chip bug, and cannot be patched for existing hardware.

# Key points

- Microsoft formally cancelled the February 2017 security update and said fixes would arrive on the March 14 Patch Tuesday; Steve suspects corporate blowback against out-of-cycle patches, while an SMB zero-day and other issues stayed open.
- CyberX Labs described "Operation BugDrop": malware that remotely switches on PC microphones, exfiltrates data via Dropbox, and hit at least 70 victims, mostly in Ukraine, in critical infrastructure, media and research. It resembles the earlier Operation Groundbait but is more sophisticated; no firm attribution was given.
- IBM's Charles Henderson showed at the RSA Conference that a connected car's phone app kept working after a trade-in, allowing location tracking, climate control, horn and remote unlock; four manufacturers were affected because only a dealer can purge the cloud-side association.
- Chrome 56 removed the direct certificate viewer from the padlock; the certificate is still reachable via Developer Tools, Security tab, and Ctrl-Shift-I jumps there.
- Firefox is replacing its legacy add-on API with WebExtensions: no new legacy add-ons from Firefox 53, incompatible add-ons disabled with multiprocess on, and legacy add-ons end entirely with Firefox 57 (November 14).
- A Windows 10 and 8.1 lock-screen flaw (found by Oddvar Moe) lets someone with physical access read the clipboard via the Narrator help pane; Microsoft declined to treat it as a security issue. Mitigations are Group Policy or the ClipTTL clipboard wiper by Firas Salem.
- Project Zero published a Windows GDI enhanced-metafile bug (bad bitmap size checks in SetDIBitsToDevice and related calls that leak heap contents) after its 90-day deadline passed without a Microsoft fix.
- Project Zero also reported 16 bugs in NVIDIA's Windows kernel drivers; NVIDIA fixed them quickly. Steve reiterates that graphics code belongs outside the kernel.
- Free draft cryptography textbook by Dan Boneh and Victor Shoup (about 580 pages, version 0.3) recommended as a hierarchical read where proofs can be skipped.
- Follow-ups: the Ubiquiti EdgeRouter can restrict UPnP by IP address via the CLI; the Netgate SG-1000 is a small two-port pfSense appliance; EdgeRouter X and pfSense both support network segmentation with VLAN-aware switches.
- miniLock (Nadim Kobeissi, audited with Matthew Green's involvement) is a Chrome add-on using Curve25519 for short shareable IDs for file encryption.
- Main topic: the MMU side-channel (ANC). ASLR was added after DEP and return-to-existing-code tricks; the memory management unit walks four-level page tables stored in DRAM and caches them in the same L1/L2/L3 caches as program data, so cache timing from untrusted code reveals where memory is mapped.
- The researchers defeated the coarse five-microsecond browser timer using tick alignment and a shared-memory WebWorker counter as a high-resolution clock, and tested the approach across 22 CPU architectures, Linux ASLR in Firefox and Chrome included.
- Steve's conclusion: nothing can fix native code on existing CPUs; browsers can only further blunt timers. It weakens ASLR rather than making drive-by exploits "nastier."
