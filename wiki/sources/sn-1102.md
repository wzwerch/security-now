# Summary

On 21 October, PHP released fixes for PHP2Shell (CVE-2026-109618 and 109619), a pair of out-of-memory "interruption" flaws allowing unauthenticated remote code execution against default PHP configurations since 5.4 (March 2012), behind roughly 70% of the web. Calif found them on 1 August with GPT-5.6 Sol through OpenAI's Patch the Planet program, and Wiz independently; the related memory-limit bug class had been known since Stefan Esser's 2004 work and a 2020 bug report but was never fixed because exploitation was unproven. CVE numbers leaked on 20 October, Calif accidentally posted a demo video, and Chainguard broke the embargo by publishing fixed images early, so PHP moved the release up one day. Many European organizations temporarily took services offline. OpenAI proposed a five-stage framework for coordinating such fixes and committed $1 billion in subsidized Daybreak access.

VulnCheck counts 2.6 million exposed PHP hosts, nearly all vulnerable and 42% on end-of-life branches, with active exploitation and many fake PoCs. The Atlantic called it possibly the worst week in cybersecurity history ("Black October"), alongside Node.js flaws and breaches at Quest Diagnostics and Railway; Cloudflare's Matthew Prince says more such embargoed bugs exist and they will soon feel weekly. Steve shares listener reactions to his flash alert, argues LLMs are a polished simulation without understanding, and closes with eMudhra, an Indian CA whose intermediate certificates (also cross-signed by Sectigo) used P-384 private keys of 3 to 8 bits, letting anyone sign trusted certificates.

# Key points

- PHP is everywhere: WordPress, Drupal, Joomla, MediaWiki, Moodle, Nextcloud, phpMyAdmin, cPanel, Plesk, Laravel and forum software like XenForo; Steve isolates GRC's PHP forum, mailer and link shortener on a separate firewalled server.
- PHP Foundation timeline: leak at 15:00 UTC on 20 October (with a wrong CVSS of 10.0; the real score is 9.2), release moved to 21 October 14:00 UTC, Chainguard's images seven hours early. VulnCheck built a reliable RCE on 8.4.x with ASLR; 469,000 WordPress and 124,000 Laravel hosts run vulnerable PHP.
- OpenAI's stages: validate and fix upstream with adversarial AI testing, give affected organizations time, coordinate with government (including the White House "Super Intelligence Force", ONCD and CISA), prepare downstream updates, then publish guidance; it shares a Codex skill to check PHP versions.
- Cloudflare quietly deployed WAF protections in advance. Others quoted: Palo Alto's Sam Rubin ("valley of pain"), CrowdStrike's Adam Meyers (a new agentic adversary every two hours), Alex Stamos (until billions of lines are rewritten), Trail of Bits' Dan Guido (take unneeded services offline).
- Steve's views: open-source fixes reveal themselves via diffs, so only browsers can update fast enough; he floats "stealth updating"; AI can be told to write Rust; he dislikes advice to move everything to big cloud providers and warns against Internet centralization. Criminals want money, so expect more extortion, not a worm.
- Listeners: war-room patching, a sports forum on PHP 5.6 shut down, and a Plesk VPS with 25 PHP handlers whose own embedded PHP was still vulnerable. Claude initially dismissed "1,000 Patch Tuesday fixes" as a joke and apologized.
- eMudhra: a reporter signed "We have a problem here - Wayne" with an intermediate key; Filippo Valsorda calls the cleanup bigger than Heartbleed because embedded devices with static root stores will trust those certificates indefinitely. Browsers blocked the intermediates (except, briefly, Edge on Windows 10); apps like Signal and WireGuard were unaffected. Steve notes attackers can impersonate any site or sign code, not just intercept traffic. Resource: getrff.com.
- Steve's personal advice: freeze (not "lock") your credit.

# Other segments
