# Summary

Steve opens with the follow-up on the CrowdStrike outage: listeners report that Falcon has repeatedly saved them from real intrusions, so most plan to stay, while a Reddit post describes a cloud-side remediation that quarantines the bad channel file on reboot, and a listener shows how to reach Safe Mode without a BitLocker recovery key. CrowdStrike's own root-cause account explains Rapid Response Content, Template Types and Instances: a new inter-process-communication template had passed testing in March, but one of two instances released on 19 July was malformed, slipped past a buggy Content Validator and crashed the in-kernel Content Interpreter on an out-of-bounds read. Planned fixes include staged canary deployment, more testing and customer control over content rollout. Marcus Hutchins' video blames Microsoft's kernel-access history, Entrust's webinar explains its SSL.com arrangement, and Steve reports that Firefox's "Strict" mode does not appear to block all cross-site cookies. A security awareness firm discovers it hired a North Korean impostor, listeners discuss Google's cookie retreat and car-data brokering, and the main topic is Binarly's PKfail: around 850 device models ship with an AMI test Secure Boot platform key labelled "DO NOT TRUST", whose private half leaked.

# Key points

- Listener view of CrowdStrike: Falcon EDR monitors extensively and its support is excellent; the main alternative, Microsoft Defender for Endpoint, is judged weaker. Steve would still choose CrowdStrike and notes the real risk comparison is against ransomware that Falcon blocks.
- Recovery tips: CrowdStrike offered opt-in cloud remediation (over 500,000 endpoints already fixed), working best over wired connections; a listener detailed a Windows Recovery path (Startup Settings, skip BitLocker prompts, set safeboot minimal via bcdedit) to reach Safe Mode without recovery keys.
- CrowdStrike root cause: sensor 7.11 (28 February) added an IPC Template Type for named-pipe abuse; template instances shipped in March, April and 19 July; the faulty instance passed validation due to a bug in both the Content Validator and interpreter. Promised changes: broader testing (fuzzing, fault injection, rollback), extra validation, better error handling in the interpreter, staggered and canary deployment, customer-selectable timing and release notes.
- A school IT director who had picked CrowdStrike to replace Kaspersky (after losing a $12,000 renewal) cancelled the day before the outage. Marcus Hutchins argues third-party AV needs kernel access because Microsoft's own APIs are inadequate and that EU rules required parity, not kernel exposure; he blames Microsoft.
- Entrust webinar: SSL.com will issue certificates but customers must prove domain control to SSL.com, and an Entrust intermediate will be chained in so browsers still display Entrust as issuer.
- Firefox: Enhanced Tracking Protection "Strict" did not stop cross-site cookies in GRC's cookie-forensics tests, whereas Custom with "All cross-site cookies" did; Steve suspects heuristic "tracker" lists or legacy-profile behaviour and says the UI is misleading.
- KnowBe4 hired a remote software engineer who was a North Korean operative using an AI-altered stock photo; the company's Mac shipped to a US "IT mule laptop farm" and began loading malware immediately, and was contained with help from the FBI and Mandiant. The US warned that North Korean workers used over 60 real US identities.
- Listener threads: Google as a monopoly motive for killing third-party cookies (Steve disagrees: the process was open), the data-brokering industry as too big to stop, an FTC finding that ISPs collect browsing data, and Senator Wyden's report that GM, Honda and Hyundai sold driving data to Verisk (Hyundai data from 1.7 million cars for about $1.04 million) using dark patterns.
- GRC DNS Benchmark runs correctly under Windows 11 ARM in a VM on Apple Silicon; small hand-written x86 assembly suffers little emulation overhead.
- PKfail (Binarly, advisory BRLY-2024-005): AMI's sample Platform Key, with subject and issuer strings "DO NOT TRUST" and "DO NOT SHIP", was found in nearly 850 devices from Acer, Dell, Fujitsu, Gigabyte, HP, Intel, Lenovo, Supermicro and others; 22 unique untrusted keys, over 10% of scanned firmware images (8% for the past four years), spanning May 2012 to June 2024. One private key leaked in a GitHub repo protected by a four-character password. With the key an attacker can sign a rogue KEK and bypass Secure Boot to install bootkits such as BlackLotus. The issue echoes CVE-2016-5247. Check: efi-readvar -v PK on Linux or Get-SecureBootUEFI PK in PowerShell and search for the strings; fix is vendor firmware updates or re-keying.
- Steve ties PKfail to Recall: a PC ecosystem with such gaps cannot guarantee protection for a complete history of user activity; he stresses users must have an honoured choice.
