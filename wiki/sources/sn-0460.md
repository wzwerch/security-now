# Summary

After chat about amusement parks, Steve covers a quiet news week. The Bitcoin mining pool GHash.io briefly passed 51 percent of the network's hashing power, which undermines the decentralised-trust assumption (Cornell researchers called it Armageddon, others said the risk was overstated); GHash promised to back off and Bitcoin's price dipped. A teenager discovered that putting a Unicode heart at the end of a tweet disabled TweetDeck's cross-site-scripting filter, and someone turned it into a self-retweeting script. Microsoft explained that Azure customers in the US were being given non-US IPv4 ranges because US space ran out. Brian Krebs reported a stolen-card batch tied to P.F. Chang's restaurants, which went back to paper imprinters. The main topic is authenticated encryption: encryption alone is brittle against active attackers (for example bit flipping through CBC initialisation vectors), so integrity must be added; the agreed rule is encrypt then MAC and refuse to decrypt unauthenticated data. Steve reviews NIST and community competitions (AES, eSTREAM, the Password Hashing Competition, and CAESAR for authenticated encryption, ending in 2017) and explains why single-pass modes are attractive. He had planned to use patented OCB for SQRL but switched to GCM (Galois/Counter Mode, an NIST standard in TLS 1.2, IPsec and OpenSSL, helped by Intel's carry-less multiply instruction) and wrote a public-domain C implementation validated with 47,250 NIST test vectors.

# Key points

- GHash.io hit 51 percent of Bitcoin hashing power; consequences discussed include blocking transactions and enabling double-spends; the operator pledged to avoid staying above that level. Peter Todd sold half his holdings; the proposed long-term answer is a hard fork. Leo is tired of Bitcoin and the Newsweek "Satoshi" story.
- TweetDeck XSS: a heart emoji after a script made the filter fail; a tweet-sized script retweeted itself with no user action. No credential theft, only propagation; shows the danger of mixing code and content.
- Microsoft Azure reported US IPv4 addresses exhausted, so new US services use non-US-registered space, which confuses geolocation.
- P.F. Chang's: Krebs saw the "Ronald Reagan" batch of newly stolen cards (about 5,000 listed at 18 to 140 dollars each); the chain stopped electronic card processing across locations. Leo and Steve note signature authentication is meaningless.
- Steve was pleased by Time's "Eat Butter" cover and says carbohydrates, not fat, drive arterial plaque.
- Encryption without integrity is malleable; CBC lets an attacker flip chosen plaintext bits via the IV; ECB-style leakage (penguin image) shown as the reason for modes.
- Encrypt-then-MAC: verify authenticity before decrypting anything, so attackers cannot exploit the decryption code.
- Counter mode turns a block cipher into a stream; nonce or IV values must never repeat with the same key.
- Competition history: AES contest (announced 1997, Rijndael chosen 2000), eSTREAM stream-cipher contest, Password Hashing Competition (24 submissions, winner expected 2015), CAESAR (authenticated encryption, 57 entries, final portfolio due December 2017).
- Authenticated encryption (AE) does both jobs in one pass with one key, many modes are "online" (length not needed in advance), and AEAD adds authenticated but unencrypted headers.
- OCB is the best and fastest AE mode but patented; Phil Rogaway granted Steve permission, but Steve chose a license-free solution for SQRL.
- GCM combines counter-mode encryption with a GHASH over a Galois field; with a 96-bit IV the 32-bit block counter limits a key and IV to about 4 billion blocks before rekeying; Intel added a carry-less multiply instruction (2010) and AES-NI to speed it up.
- Steve's portable GCM implementation (about 5 KB) passed 47,250 NIST test vectors and is public domain; a master's student writing an Android SQRL client prompted the change.
- SpinRite: a Level 4 scan fixed a crashing Vista PC without reporting errors because it rewrites every bit, refreshing the surface.
