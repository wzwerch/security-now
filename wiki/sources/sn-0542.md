# Summary

The episode opens the eleventh year of the show with a Q&A format. The lead story is Tavis Ormandy of Google reporting that Trend Micro's Windows antivirus bundled and auto-started a Node.js-based password manager component that listened on local HTTP RPC ports and exposed about 70 APIs. Any website could use these local endpoints to launch programs and even pull out the stored passwords. Trend Micro patched individual calls one at a time, while Steve argued the whole architecture was broken and that users should remove the product. Next, Symantec admitted it issued five SHA-1 certificates after the 2015 cutoff because a date check was missing in an approval step for enrollments that straddled New Year. Firefox's own attempt to reject post-2016 SHA-1 certificates broke connections through corporate TLS-intercepting proxies that still sign with SHA-1, forcing a quick rollback. Steve also noted malware being hosted over HTTPS using free Let's Encrypt certificates, the end of Windows XP Embedded support, and how LastPass 4.0 emergency access stays "trust no one" by escrowing vault keys encrypted to each contact's public key. Listener questions covered how disk drives read tracks versus sectors, hardware versus software random number generation, null-cipher TLS suites, what ShieldsUP! actually tests behind a router, the size of the space of AES permutations, TCP/IP OS fingerprinting, and the safety of clicking links in webmail.

# Key points

- Trend Micro Maximum Security's bundled password manager ran by default and opened local RPC endpoints; Ormandy found a call mapping to a shell-execute function within about 30 seconds, so any web page could start programs on the machine, and the product even installed a self-signed localhost certificate into the trust store.
- Trend Micro fixed only the specific calls reported; Ormandy then showed a second route via a bundled "Secure Browser" (an old Chromium build run without its sandbox) and an API that let a page read and decrypt all stored passwords. He urged disabling the feature and commissioning an outside audit. Same-origin enforcement added later was reportedly bypassable. Steve's advice: remove the product.
- Symantec issued five SHA-1 certificates after 31 Dec 2015 because the post-cutoff block was missing in an enterprise portal approval path; they were revoked and a patch released.
- Firefox 43.0.3 rejected SHA-1 certificates with a not-before date in 2016 or later, which broke users behind enterprise man-in-the-middle proxies that sign on-the-fly certificates with SHA-1; 43.0.4 removed the rule. A stopgap for vendors would be backdating the certificate.
- Malware has begun to be served over HTTPS using free Let's Encrypt certificates on compromised sites; Steve called this inevitable and not a Let's Encrypt flaw, since domain-validated certificates only assert the domain, which is why higher-validation certificates still have a role.
- 12 Jan 2016 ended extended support for Windows XP Embedded SP3, which Steve had been using to keep XP machines patched; he plans to stay on XP then move only to Windows 7.
- LastPass 4.0 emergency access works by encrypting the user's vault key to each emergency contact's public key and escrowing the blobs; LastPass can only release them after a waiting period and can never read them.
- Sysinternals SigCheck 2.4 can list unsigned files and can compare the system certificate root store against Microsoft's published trusted-root list.
- Errata: WiFi uses CSMA with collision avoidance, not collision detection, because a radio cannot listen while transmitting.
- Q&A: modern drives opportunistically read ahead on a track but do not report errors for sectors nobody requested; SpinRite switches off read-ahead for precise recovery.
- Q&A: hardware random sources use physical noise such as reverse-biased diodes, whitened (for example by XORing pairs); software generators are seeded from pools of entropy from timing events and re-seeded periodically.
- Q&A: TLS defines cipher suites with a null cipher that gives authentication and integrity without encryption.
- Q&A: ShieldsUP! can only test the single public IP, i.e. the router; a DMZ host answering pings makes the whole network fail the stealth test.
- Q&A: AES-256 has far fewer keys (about 78 decimal digits' worth) than possible block mappings (128-bit factorial), so a key selects a vanishingly small subset of all permutations.
- Q&A: TCP/IP stack fingerprinting (TTL, window size, window scaling and similar defaults) can reveal the operating system even when browser-level leaks are blocked.
- Q&A: the problem with malicious links is the link itself, not the mail client, so webmail is not inherently safer than Thunderbird.
- Listener tip: Firefox's browser.urlbar.trimURLs setting can be turned off to show the full URL. Steve's five-to-ten-year outlook: mobile is in evolution, plugins like Java and Flash decline, IPv6 and IoT grow.
