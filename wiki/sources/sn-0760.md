# Summary

Remote work has pushed exposed RDP endpoints up about 41 percent according to Shodan data (roughly three million to 4.4 million on port 3389), and enterprise VPN servers up by a third; consumer VPN use also rose. Steve repeats that RDP must sit behind a VPN with multifactor authentication. ProtonVPN found that iOS 13.3.1 and 13.4 leave pre-existing connections outside a newly started VPN tunnel. Browser news covers Chrome testing an option to always show full URLs, Firefox working on an HTTPS-only mode, and Chrome 81 rescheduled with 82 skipped. The technical deep dive explains how Intel's CET hardware shadow stack, now in Windows 10 Insider builds, defends against return address overwrites. Also covered: an OpenWRT package manager that never verified downloaded package hashes (fetched over HTTP), a KPMG audit of Cloudflare's 1.1.1.1 resolver, and Folding@home as the new home for donated CPU cycles after SETI@home.

# Key points

- Shodan data (via ZDNet): exposed RDP on port 3389 rose from about 3 million to 4.4 million since January; port 3388 also up; VPN protocol servers (IKE, PPTP) up from 7.5 to nearly 10 million. Steve worries about credential stuffing against RDP and urges VPN plus MFA.
- iOS VPN bug (ProtonVPN, found with Wireshark): connections open before the VPN comes up are not reset and stay outside the tunnel. Workaround: toggle airplane mode after connecting; Apple's suggestion is an always-on VPN through MDM supervised mode. Steve expected a quick fix.
- Chrome has hidden "www" and "m" since version 76; a Canary build (83) adds a context-menu option to always show full URLs on desktop.
- Firefox 76 experimental "HTTPS Only Mode" (Bugzilla entry) will try HTTPS first, with a fallback page offering HTTP on timeout; Steve has long argued browsers should not default to HTTP.
- Chrome 81 moved to 7 April, Chrome 82 skipped, 83 expected mid-May; Edge follows Chrome, and Microsoft paused optional Windows 10 cumulative updates from May. Mozilla did not pause Firefox but rolled back the TLS 1.0/1.1 block.
- Shadow stacks: Intel CET keeps a separate, programmer-invisible stack of return addresses and compares it on return, catching stack overwrites and overflows with near-zero overhead. Windows 10 support is in Insider preview; GCC and glibc already support it; CPUs without CET ignore it. Steve gives a history of stacks (PDP-8 return-address kludge versus true stacks).
- OpenWRT (CVE-2020-7982): found by Guido Vranken of ForAllSecure while using the Mayhem fuzzer; the opkg package manager did not check SHA-256 hashes since 2017 and downloaded over plain HTTP, so a man-in-the-middle or DNS tampering could deliver malicious packages. Fixed in 18.06.7 and 19.07.1 (early February); Steve also warns of recent router DNS-changing attacks.
- KPMG audited Cloudflare's 1.1.1.1 public resolver commitments for February to October 2019 and found management's assertions fairly stated.
- Folding@home: after SETI@home wound down, Steve urges donating idle CPU cycles for COVID-19 protein simulations; the network had reached about 1.5 x86 exaflops with a flood of new volunteers; Leo is skeptical about electricity use and tangible results.
- Marriott disclosed another breach of about 5.2 million guest records via compromised employee credentials (raised by Leo).
