# Summary

The show opens with the iCloud breach in which private photos of many celebrities appeared online. Steve explains that a GitHub tool (iBrute) exploited the lack of rate limiting on Apple's Find My iPhone login interface; Apple fixed it immediately and said iCloud itself was not flawed but that targeted attacks on passwords and security questions occurred. Namecheap reported a wave of logins using credentials from a huge leaked database (from a Russian-sourced collection of about 1.2 billion unique accounts), underlining the danger of password reuse. Next, a new Wi-Fi Protected Setup flaw: on some Broadcom-based routers the PIN-negotiation nonces come from a trivially predictable linear congruential generator, and on another vendor's routers a shift-register generator starts from zero at power-up, letting an attacker crack the PIN in about a second; advice is to turn WPS off. Steve covers law-enforcement fake cell base stations ("Stingray"-style), a new unrelated ransomware borrowing the CryptoLocker name that uses Tor and charges 1.8 bitcoin, and the news that China is building its own desktop operating system. He reports progress on the SQRL client (QR code import via webcams), explains why SpinRite cannot be built into a drive, and argues that RAID 5 is becoming risky as drive error rates and sizes grow, so RAID 6 is preferable. The main topic follows Matthew Green's argument that PGP-style email encryption should be replaced: key management is painful, there is no forward secrecy, metadata is exposed, and new purpose-built messaging systems (DarkMail, SMIMP, Silent Circle's protocol) are the better path.

# Key points

- iCloud celebrity photo leak: Find My iPhone login had no failure lockout, and a public tool exploited that for password guessing. Apple added rate limiting at once and advised strong passwords and two-step verification; one researcher believed the data came from iCloud backups, which holds much more than photos.
- Namecheap saw credential-stuffing logins from a huge breached-credential database and blocked the source IP addresses; the company stressed that this was not a breach of its own systems and that only users who reused passwords were exposed.
- WPS history: the eight-digit PIN has a checksum digit and could be brute-forced in about 11,000 guesses because the protocol confirmed the first four digits separately (Reaver tool, episode 335 in 2012).
- New WPS attack: a Broadcom-based router class uses a 32-bit linear congruential generator, so the first public nonce reveals the generator state and the secret nonces; a second class initialises a feedback shift register to zero at boot, making a reboot enough to predict everything. Advice: disable WPS entirely.
- Fake cell base stations are widely owned by US agencies (a vendor product is described as a GSM interceptor able to read and alter calls and texts); concerns include weak baseband radio firmware.
- A new ransomware clone uses the CryptoLocker name, works through Tor, appends an extension to encrypted files, demands 1.8 bitcoin and at the time did not delete Windows shadow copies, so some recovery was possible.
- China's plan for its own operating system: Steve expects a Linux derivative and notes the engineering resources available.
- SQRL: Steve wrote webcam capture in assembly (via DirectShow) so the Windows client can import an identity shown as a QR code from a phone.
- SpinRite cannot run inside the drive because DynaStat needs large memory and heavy computation; it acts as the drive's brain extension. A future version might be built into an operating system. v6.1 benchmarked around two hours per terabyte.
- RAID 5 rebuilds on very large drives risk unrecoverable read errors with no remaining redundancy; Steve runs RAID 6. New 8 TB helium-filled drives are cited as the trend.
- Advice to think of "the cloud" as someone else's computer and to store only encrypted data there (Trust No One / pre-Internet encryption).
- JavaScript crypto concerns: little memory control, weak typing and crash dumps could leak secrets in Google's and Yahoo's browser-extension email encryption.
- Matthew Green's critique: OpenPGP and S/MIME are old, have bulky keys, painful key management, no forward secrecy and leave metadata exposed; modern elliptic-curve keys are tiny.
- Alternatives mentioned: DarkMail (Phil Zimmermann and Ladar Levison), Silent Circle's SCIMP, Adam Caudill's SMIMP with built-in proof of work against spam, and MailPile (which still uses OpenPGP). Steve favours new secure messaging systems alongside ordinary email.
