# Summary

Two big stories. First, the Phase 1 report from the iSEC firm for the Open Crypto Audit Project (organized by Matthew Green and others) on TrueCrypt: it examined only the bootloader and Windows kernel driver, found no backdoor or intentional malice but poor code quality (little commenting, deprecated functions, suppressed compiler warnings, a build chain that needs 1993-era Visual C++ 1.52) and a few weaknesses such as a header integrity check built on a fixed string and two CRC32 values, and memory-clearing that the compiler could optimize away. Steve stresses that this is a small slice of the code and that cryptographic review is still to come. Second, follow-up on Heartbleed: he describes how Google's Neel Mehta found the bug, Codenomicon found it independently, patches and secret disclosure rippled outward from Google to CloudFlare to OpenSSL, and the bug was committed by a researcher (Robin Seggelmann) and reviewed by an OpenSSL team member. He looks at the unexpectedly modest wave of certificate revocations (Netcraft), the CloudFlare challenge that proved private keys really can be extracted from a patched-late nginx server, the unsubstantiated Bloomberg claim that the NSA knew for years and an EFF report of a possible earlier probe, and a call from Dan Kaminsky for serious investment in auditing core open-source software. Steve also mentions the Perspectives notary project for spotting certificate changes, a FireEye finding that Android apps can rewrite home-screen shortcuts, and a coming show on "the revocation revelation".

# Key points

- TrueCrypt audit phase 1 (iSEC): no evidence of backdoors in the bootloader and kernel driver, but code that "did not meet expected standards"; recommendations include updating the build environment, improving code quality, and replacing memset with the intended secure-wipe function (burn) in sensitive paths. A theoretical low-memory paging attack was described. Matthew Green was not alarmed.
- TrueCrypt's volume header uses a TRUE marker plus CRC32 values and the XTS cipher mode; the assessment recommends better integrity checking. The documentation was praised.
- Excluded from phase 1: file-container parsing, rescue-disk paths and all cryptographic analysis (planned for phase 2).
- Lesson: complex security software, open source or not, is rarely audited; the NSA reportedly has many people reading open-source code while the public lacks the resources.
- xkcd cartoon 1354 sums up Heartbleed.
- Heartbleed timeline: Google discovered it by March 21 and fixed its own systems; CloudFlare was told on March 31; Google reported it to OpenSSL on April 1; Codenomicon found it independently on April 2 and told Finnish authorities; rumors circulated on April 4; public disclosure came on April 7. Steve sees the staged disclosure to ever-wider circles as realistic.
- Heartbleed code came from a university researcher's feature contribution reviewed by an OpenSSL developer and merged unnoticed.
- Netcraft saw no revocation tsunami: about 29,000 to 33,000 certificates revoked per day in the days after disclosure, within normal ranges, though policy requires revocation within 24 hours of key compromise; reissue without revocation is likely common.
- Detecting reissued certificates: the Perspectives notary network (and Certificate Patrol) can show certificate changes; Steve wants to build a faster front end.
- The CloudFlare challenge was solved by two hackers who extracted the server private key from a test nginx server after repeatedly hammering it, disproving claims that keys could not be taken.
- Bloomberg claimed the NSA had used Heartbleed for two years (unnamed sources); Steve is skeptical. The EFF reported a log from November 2013 showing a Heartbleed-style probe, which might indicate earlier use.
- Dan Kaminsky's response: the lesson is that "we can't even add Ping" safely; core libraries like OpenSSL need funded auditing. Android 4.1.1 contains vulnerable OpenSSL code and phones rarely get updates.
- FireEye found Android apps with ordinary-class launcher permissions could rewrite home-screen icons to point to phishing sites; the proof of concept affected all tested versions.
