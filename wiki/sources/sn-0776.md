# Summary

Steve apologizes for last week's dismissive remarks on technology terminology changes. He then covers the previous week's Twitter breach, in which high-profile accounts promoted a bitcoin-doubling scam through an internal admin tool; Leo relays an unconfirmed New York Times account that credentials were found in an internal chat channel. Check Point's SIGRed is a 17-year-old wormable heap overflow in Windows Server DNS, fixed in July Patch Tuesday (123 flaws, about 30 remote code execution). A single bad BGP configuration in Atlanta caused a 27-minute Cloudflare outage. A Zoom vanity-URL spoofing issue, seven "no-log" free VPNs with exposed logs, and Apple updates are covered quickly, with SpinRite R&D notes. The main story is a correction: C-Data says the telnet "backdoor" credentials reported last week came from counterfeit devices or serial-console-only factory accounts, then Steve examines F-Secure's analysis of counterfeit Cisco Catalyst switches.

# Key points

- Twitter incident: 130-plus accounts targeted, bitcoin double-your-money tweets, verified accounts temporarily blocked from tweeting. Steve argues critical admin actions should need multi-person approval (threshold secret sharing) so one socially engineered employee is not enough.
- SIGRed: Windows DNS Server mishandles a large SIG record in DNS replies; a 16-bit versus 64-bit size mismatch gives a heap overflow of about 64 KB, giving unauthenticated SYSTEM-level code execution, wormable. Fix: July 2020 patch; workaround is limiting the maximum TCP DNS message size via a registry value and restarting the DNS service.
- Patch Tuesday July 2020: 123 flaws across 13 products with none known exploited; Steve laments Windows complexity (a Disk Cleanup boot bug handled by an auto-run troubleshooter) and says he will move SpinRite to UEFI booting after 6.1.
- Cloudflare outage: a router config error in Atlanta advertised all backbone traffic to Atlanta, taking out many data centers for 27 minutes; not an attack. Steve praises their transparent write-up.
- Zoom vanity URL flaw let attackers make invitation links appear to come from any organization's subdomain; fixed after Check Point reported it. Steve again objects to calling fixed-before-public bugs zero-days.
- VPNmentor found a database of about a billion log entries for 20 million users from seven white-labelled free "no-log" VPN apps, including cleartext passwords and personal data.
- Apple pushed security updates; Firefox Send stays offline longer than expected.
- SpinRite R&D: SSDs seem to hide extra recovery margin; the read-verify command lets a scan run at 800+ MB/s on honest drives, so SpinRite will test whether a drive cheats.
- C-Data replied courteously: the reported panger/suma account belongs to counterfeit units; the debug/root accounts only work on the local serial console on first-generation units; newer models use per-device debug passwords. So the researchers' disclosure was inaccurate, though counterfeit buyers had a real remote backdoor.
- F-Secure Labs examined counterfeit Cisco Catalyst 2960-X switches: near-perfect board copies running genuine firmware, one with add-on circuitry that exploits a boot ROM race condition to bypass Secure Boot checks, another with a redesigned board; they found no backdoor, and the fakes were exposed after a firmware update broke the bypass.

# Other segments

- Picture of the week: real versus fake Cisco router front panels (white versus gray port ink).
- Joe's listener story of SpinRite Level 2 repairing a Windows profile problem; the GRC shortcut for the F-Secure PDF.
