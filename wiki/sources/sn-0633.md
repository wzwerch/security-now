# Summary

Two major disclosures landed on the same Monday. Steve first covers ROCA, a flaw in an embedded RSA key-generation library in Infineon chips (since 2012) that yields public keys which can be factored far faster than normal, affecting TPM 1.2 modules used with BitLocker, some YubiKey 4 on-device PGP keys and many keys found online; vendors such as Yubico, Microsoft, Google, HP, Lenovo and Fujitsu had already shipped fixes and testing tools exist. He then discusses AdGuard's survey of cryptomining scripts on popular sites and floats consent-based mining as a replacement for ads. A demo of lookalike iOS password pop-ups shows how easily Apple ID passwords can be phished. Google's Advanced Protection Program goes live, requiring physical security keys. Listener feedback precedes the main topic: KRACK, the Key Reinstallation Attack against the WPA2 four-way handshake. Steve explains the stream-cipher background, why replaying handshake message 3 resets the nonce, and why the client side, not access points, is what must be patched, adding that VPN, TLS and HTTPS keep most traffic protected anyway.

# Key points

- ROCA (Return of Coppersmith's Attack): keys from the Infineon library can be tested for weakness almost instantly; worst-case factoring estimates were under about three CPU-months for 1024-bit and roughly 100 CPU-years for 2048-bit keys (about tens of thousands of dollars of cloud time), versus effectively impossible for healthy keys. Researchers found Infineon TPMs in 10 of 41 laptop models checked. Remedy: apply firmware updates, regenerate keys (BitLocker with TPM 1.2) or generate keys in software; check keys with the keychest.net tool and Yubico's key check page. The researchers criticise closed-source, secret designs.
- Cryptomining prevalence: AdGuard found 220 of the top 100,000 sites with mining scripts over three weeks, reaching about 500 million users and an estimated $43,000 of earnings. Steve and Leo propose an opt-in "ethical mining" model, noting uBlock Origin and Adblock Plus already block it.
- iOS password-dialog spoofing (Felix Krause): an app can show a lookalike Apple ID prompt; pressing Home dismisses a real system prompt but not a fake. Steve notes his SQRL client uses a darkened-screen dialog like Windows UAC that a web page cannot imitate. Leo notes Android's draw-over-other-apps feature poses a similar risk.
- Google Advanced Protection Program is live: needs Chrome and physical security keys (two, one with Bluetooth LE for iOS), disables SMS and authenticator-app fallback, blocks third-party app access to Gmail and Drive, and slows account recovery. Leo orders keys to test it.
- Listener items: IPLeak.net shows what a browser leaks; DANE versus self-signed certificates differ in how securely the key is distributed through DNSSEC; security.txt should link to a CAPTCHA-protected form rather than an email address; SQRL clients may choose their own local unlock method.
- KRACK explained: stream ciphers XOR data with a keystream and must never reuse a keystream. In WPA2's four-way handshake, an attacker positioned between client and access point (on a different channel with the same MAC address) can replay message 3, which makes the client reinstall its key and reset the nonce, enabling keystream reuse. Android 6.0 and later could end up with an all-zero key. The fix is a small check to not reset the nonce on a repeated message 3.
- Who is exposed: clients (phones, laptops, IoT) and access points that act as clients in repeater or mesh mode; iOS and Windows were largely unaffected because of how they implemented the spec, though Microsoft patched it on the previous Patch Tuesday and iOS 11.1 betas carried fixes. Ordinary access points mostly need no patch, and the research FAQ says to prioritise client updates.
- Impact is limited because VPN, TLS and HTTPS still protect content; the main risk is unencrypted traffic and IoT devices that will never be patched. The 802.11 specification is paywalled, which Steve criticises.
