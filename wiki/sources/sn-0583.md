# Summary

Steve covers the previous week's DNS outage: a Mirai botnet of compromised IoT devices attacked managed-DNS provider Dyn, taking many large sites off the air; he explains how cache-busting random subdomain queries defeat caching, why record time-to-live settings matter, and how the outage hit GRC's e-commerce gateway lookups. He then covers Dirty COW, a nine-year-old Linux kernel copy-on-write race condition discovered through exploitation in the wild, and a Google engineer's data showing Linux kernel security bugs live about five years on average. After errata and miscellany (Dennis Ritchie death hoax, a CO2-to-ethanol catalyst discovery, SpinRite on a BitLocker-encrypted drive), the main topic is Drammer: researchers from VU Amsterdam and UC Santa Barbara showed that Rowhammer works on ARM phones and, using DMA and a controlled memory layout, can flip bits that give an unprivileged app control of kernel page tables and root in about 30 seconds, with no software flaw and no good fix for existing hardware. Steve and Leo run the researchers' tester app live.

# Key points

- Dyn attack: tens of millions of source addresses, partly Mirai-infected DVRs and cameras; authoritative-DNS outsourcing meant a single provider's failure disrupted many big sites; Steve's e-commerce server could not resolve its payment gateway until he added a hosts-file entry.
- Mirai-style cache bypass: querying made-up subdomains forces recursive resolvers to ask the authoritative server (the same technique GRC's DNS Benchmark uses carefully); long TTLs would have softened the outage, short ones help planned migrations.
- Source-address validation (BCP 38/RFC 2827, "SAVE") would help against spoofed floods but not against valid-looking requests from real bots; Bruce Schneier is quoted that neither buyers nor sellers of IoT gear care; maker XiongMai threatened to sue Brian Krebs; BullGuard's IoT scanner checks Shodan for your IP; network segmentation is Steve's advice.
- Dirty COW: a race condition in the kernel's handling of copy-on-write allowed writing to read-only mappings; exploited in the wild, found by a developer who logs web traffic; any Linux system with an exposed service was affected; patches issued; embedded Linux devices may never be updated.
- Kernel bug lifetimes (Kees Cook): across 557 CVEs since 2011, critical bugs lasted about 3.3 years, high about 6.4, medium 5.2, low 5; overall roughly five years, unchanged from the 2010 analysis.
- Errata: Dennis Ritchie died in 2011; social media recirculated an old obituary after a prominent tweet.
- AT&T/Time Warner merger concerns about carriers owning content.
- Oak Ridge National Laboratory reported a copper-carbon-nitrogen catalyst that converts dissolved CO2 into ethanol at room temperature with about 63 percent yield.
- Drammer background: Rowhammer on DRAM; earlier work needed x86 cache-flush instructions and VM page deduplication; on ARM the cache flush is privileged, so the attackers used DMA, which bypasses caches and supplies physically contiguous memory.
- Drammer method: template memory to find flippable bits, release and fragment memory so kernel page-table pages land on those vulnerable locations, hammer to flip a bit so a page table maps into user space, then use it to edit the process credentials and gain root; needs no permissions and no software vulnerability.
- Impact: many tested phones (including older Nexus models) have flippable DRAM; Google was told a month earlier; no clear mitigation because it is a hardware weakness; adaptive refresh in newer DRAM helps, but existing devices remain exposed.
- Steve and Leo sideloaded the researchers' tester (flip-detection only, no exploit); Steve's old Samsung tablet and Leo's Pixel gave inconclusive or crashing results; the app triggered Android's strong install warnings.
