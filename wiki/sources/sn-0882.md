# Summary

The show opens with Atlassian's "Questions for Confluence" add-on, which created a built-in account named "disabled system user" that was not actually disabled; Atlassian patched it on July 20, a self-styled "annoyed researcher" posted its credentials the next day, and exploitation followed quickly, so Steve (echoing Kevin Beaumont) urges keeping such servers behind a VPN or authenticating reverse proxy. Next is TLS-Anvil, a combinatorial test suite presented at USENIX Security that exposed 239 deviations across 13 TLS libraries, including exploitable bugs in MatrixSSL and wolfSSL. Google again delayed removing third-party cookies from Chrome, now to the second half of 2024, while Proofpoint data show macro-enabled malware attachments fell by about two thirds before Microsoft's block, with attackers shifting to ISO, RAR and LNK containers that evade the Mark of the Web. After a long digression on why SpinRite 6.1 stays 16-bit with 32-bit data access and why more bits are not always better, plus listener mail and TV talk, Steve explains Half-Double, a Rowhammer variant that turns the Target Row Refresh mitigation against itself and gives root on up-to-date Chromebooks in under 45 minutes.

# Key points

- Confluence: the Questions for Confluence app installs a hard-coded "disabled system user" account; Atlassian patched on July 20, 2022; credentials were published a day later and exploitation was seen by GreyNoise and Rapid7; disabling the app does not remove the account, so apply the fix or disable the account; CISA urged action.
- General advice: do not expose anything publicly that does not strictly need to be; put admin and collaboration servers behind a VPN, overlay network or authenticating proxy. Steve's own DNS uses zone transfers only to two large secondary providers.
- TLS-Anvil (Ruhr-University Bochum style combinatorial testing, tls-anvil.com, Docker images): tested BearSSL, BoringSSL, Botan, GnuTLS, LibreSSL, MatrixSSL, Mbed TLS, NSS, OpenSSL, Rustls, s2n, tlslite-ng and wolfSSL; found 239 issues, including two exploits in MatrixSSL and one in wolfSSL, five handshake-crypto issues (clients accepting parameters they never offered), 15 interoperability issues, 116 alert-handling deviations and 100 other deviations. Developers justified some deliberate deviations, leading the authors to drop 18 tests.
- Google Privacy Sandbox: Chrome third-party cookie phase-out delayed again, to no earlier than the second half of 2024; Topics API trial to millions of Chrome users from September 2022, launch targeted for Q3 2023. Steve says industry will only move when forced and that outlawing other tracking will need regulation.
- Proofpoint: macro-enabled attachments in campaigns down about 66% between October 2021 and June 2022; attackers moved to ISO, RAR, ZIP, IMG and LNK files, which bypass Mark of the Web tagging because contents of containers are not marked (techniques described by Outflank). Steve suggests Windows should propagate the mark to extracted files.
- Bit-width theory: unnecessary bits cost power, memory bandwidth and code size; SpinRite 6.1 stays 16-bit real mode but uses a long-known 286-and-later quirk to address the first 4 GB; a second 64 KB code segment is needed; after 6.1 Steve plans a 32-bit rewrite on a small embedded protected-mode RTOS bootable via BIOS or UEFI, enabling parallel drive operations and NVMe.
- Listener: an account lockout that blocks indefinitely would let anyone deliberately lock out all users, which explains Microsoft's temporary lockout design; Headscale is an open-source Tailscale control server; Microsoft's USB printer "Copy" bug confirmed by another listener.
- Rowhammer history: original Rowhammer, DRAMmer, RAMBleed, SPOILER, TRRespass and Blacksmith. Half-Double (Google researchers, USENIX Security 2022): hammering a distance-2 row plus a few accesses to a distance-1 row flips bits in the victim; Target Row Refresh itself supplies the near-aggressor accesses. The end-to-end chain used a DRAM timing side channel, "blind hammering" to defeat ECC, a new page-table spraying method and a Spectre oracle, reaching kernel read/write on a fully updated Chromebook with ECC and TRR LPDDR4 in under 45 minutes. Steve's moral: mitigating is not fixing, the cure became the disease, and DRAM density is the root cause.
