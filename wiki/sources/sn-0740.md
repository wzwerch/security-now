# Summary

Steve and fill-in host Jason Howell start with the first public betas of the checkra1n jailbreak (macOS only, A5-A11 devices) and what it means for Apple's secure boot guarantee and for reverse engineering of iOS patches. The Light Commands research showing that MEMS microphones respond to amplitude-modulated lasers, letting voice assistants be commanded from far away, is presented as an oddity rather than a major risk. BlueKeep follow-up: Microsoft warns of worse attacks to come, the Metasploit exploit has been fixed so it no longer crashes Meltdown-patched hosts (the cause of the earlier honeypot crashes), and Marcus Hutchins argues that a worm is unnecessary because compromised servers enable ordinary network-wide ransomware. Steve then recounts Mozilla's open letter rebutting Comcast, a survey showing all six major browsers are adding DoH, removal of Downloads from Windows Disk Cleanup, and a libarchive code execution flaw on Linux/BSD. The main segment explains TLS Delegated Credentials, a TLS 1.3 extension allowing short-lived (up to seven days) delegated keys without revocation, already testable in Firefox.

# Key points

- checkra1n beta 0.9.2 on checkra.in: tethered, macOS only, experimental for some devices; reboot clears it; Steve advises a full restart if a device was out of your control. Security researchers gain permanent ability to analyze Apple patches on supported old devices.
- Light Commands (University of Electro-Communications and University of Michigan): laser light modulated with audio drives MEMS microphones; commands were injected into Echo, Google Assistant, Facebook Portal and Siri devices from up to 110 meters, allowing smart locks, garage doors, purchases or vehicle unlock if the account authorizes it; a light-blocking coating inside the mic port would be a cheap fix.
- Microsoft again urges patching BlueKeep (700,000+ exposed systems); the early Metasploit module crashed systems patched for Meltdown (KVA Shadow) but was reworked and is now reliable.
- Marcus Hutchins: BlueKeep affects mostly servers, only about a few servers are needed for scanning, so a WannaCry-style worm gains little; the real risk is attackers pivoting from one server with standard tools to push ransomware; advice: firewall servers and practice credential hygiene.
- Mozilla's letter to Congress lists ISP abuses (selling location data, DNS ad injection, supercookies, paid opt-outs) and states its resolver requirements (limited retention, no secondary use, public privacy notice); Steve jokes about "Concast".
- ZDNet survey: Brave, Chrome, Edge, Firefox, Opera and Vivaldi all support or will support DoH (flag-based in most; Firefox on by default for US users in stages); Apple did not comment. ISPs are expected to deploy their own DoH resolvers.
- Microsoft is removing the Downloads folder from Disk Cleanup because users were deleting their archives.
- libarchive (CVE-2019-18408): a flaw found by Google fuzzing tools allows code execution when a malicious archive is extracted; fixed in 3.4.0 (June); distribution updates were coordinated.
- Delegated Credentials (IETF draft by Facebook, Cloudflare, Mozilla and others): the client advertises support in ClientHello; the server presents a short-lived public key signed by the long-lived certificate key, which stays at headquarters; validity capped at seven days and no revocation is needed; useful for large providers with many edge servers; enabled in Firefox through an about:config setting and testable at a Facebook demo site. Steve reviews why CRLs, OCSP, stapling and 90-day ACME certificates each fall short.
