# Summary

Following up on role confusion, Steve stresses that a neural network memorizes rather than computes and has no mode or state, so conditional instructions like "ignore commands until the closing tool tag" exceed what it can do. Research such as BERT segment embeddings, Princeton's Instructional Segment Embedding and the German ASIDE work has tried "architectural instruction-data separation" without a breakthrough. Steve's proposal: instrument the model as the role-confusion researchers did and let the deterministic dialogue manager (harness) abort whenever the model's perceived role disagrees with the role tag it actually sent.

VulnCheck found that routers built by Shenzhen Zhibotong (ZBT) and sold under many brands ship with phone-home backdoors (ENDLESSDOORS, SPEAKINGSTONE, DARKLANTERN) giving root shells. Listener Taylor Hornby's SpinRite graph shows a 4 TB WD SSD's slow regions repaired. Listener feedback covers random hashes in tags, harness-level defense, objections to saying AI "thinks", security basics ignored by AI designers, and the term "rotating credentials". The main topic is "Frontier Models' Vulnerability Patches are Often FLAWED" from 1Password's new Off-by-1 Labs: only 26% of AI-generated patches fully fixed a vulnerability without side effects.

# Key points

- Steve's role-monitoring idea: since the dialogue manager always knows which role it last tagged, real-time probes of the model's role perception could detect a mismatch (for example command-following inside tool text) and kill the session before an injected command takes effect.
- ENDLESSDOORS (Zbtlink AX3000): two fake userland `kworker` processes running a customized 2015 `rctl` tool phone home to a hard-coded server and execute anything as root, or open a reverse shell on port 7001; outbound connections pass NAT. An older "DeepOrange" router bought on Amazon held SPEAKINGSTONE (phone-home, UDP, written in Nim) and DARKLANTERN (unauthenticated WAN backdoor). ZBT hardware is sold in the US, Canada, Australia, the Philippines, Germany and Russia. Steve's advice: stick with name brands.
- SpinRite: Taylor Hornby's 4 TB WD SSD showed many slowdowns that disappeared over the 70% SpinRite level 3 covered; Firefox stalls and system freezes stopped. Steve attributes it to charge drift, worsened by heat.
- Listener ideas such as per-session random hashes in tool tags fail because the network cannot track state; only the harness can. Claude itself said it infers who is speaking partly from phrasing. Steve thinks harness quality (as AISLE showed) may be where defenses and proprietary value lie.
- Tim Spellman lists security basics the AI industry ignored (RBAC since 1992, credential vaults, separating code and data, intrusion detection); Steve answers that researchers never had adversaries until AI went public, like the early Internet or Spectre-era CPUs.
- "Meat proxy": a person who just relays AI output, popularized by Niklas Gruhn's August 2026 essay "Don't be a meat proxy".
- FLAWED tested GPT 5.5 (Trusted Access for Cyber) and Opus 4.8 (Cyber Verification Program) via Codex and Claude Code on six 2026 CVEs: a Chrome sandbox escape, Spring AI RCE, the Linux "Copy Fail" privilege escalation, Apache ActiveMQ RCE, Exim RCE and a Gemini CLI prompt injection (CVSS 10). Modes: one-shot, iterative ("Ralph loops") and exploratory, with a cheat checker.
- Results: 26.0% fixed cleanly (S1), 20.1% fixed but changed behavior, 49.3% left an exploit path open, 2.3% fixed but added a new vulnerability, 2.2% both failed and added one. Correct versus wrong guidance moved success from 65% to 15.2%; more context helped far less; mode mattered under 10%. Models patch only the path the proof of concept touches and do not push back on wrong premises.
- Recommendations: human domain experts must review patches, and reviewing may cost as much as writing the fix; give no guidance rather than possibly wrong guidance. Other studies: Georgia Tech's Vibe Security Radar, the Cloud Security Alliance (AI-assisted developers introduce flaws at 10 times the rate) and Veracode (nearly half of AI-generated code contains known vulnerabilities without security guidance).
