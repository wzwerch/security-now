# Summary

Steve starts with a big Patch Tuesday in which almost every major Windows component carried a critical remote-code-execution fix, and with Craig Wright's final retreat from his Satoshi claim, which Steve treats as the end of a con. A Microsoft reclassification of an update (removing Secure Boot support from Windows 7) left Windows 7 machines on ASUS boards, where Secure Boot was enabled by default, showing a "Secure Boot Violation" at boot. Lenovo's Solutions Center and an old Qualcomm Android network daemon both had privilege flaws, and the FCC and FTC began asking mobile vendors about patch policies. A follow-up on the curl-pipe-bash topic shows how a malicious server can serve different content when the script is piped into bash rather than displayed. After a lighter segment (an airline's overreaction to a mathematician's notes, a router-power-cycling plug, a mug and sleep-supplement updates) the main topic is SmartThings: research on 499 SmartApps found over-privilege and weak event protection, and ZigBee Home Automation 1.2 has a well-known default link key and an insecure rejoin mode that SmartThings must support for compatibility. Steve's advice is to treat consumer home automation as a toy until ZigBee 3.0-style out-of-band joining arrives.

# Key points

- Patch Tuesday (May 2016): critical RCE fixes across Internet Explorer, Edge, JScript/VBScript, Office, graphics components, Windows Journal and Shell; Windows Update felt sluggish.
- Craig Wright's final post apologised and retreated instead of producing a signed transaction; considered closed.
- A Windows 7 update reclassified as recommended removed Secure Boot support, breaking boot on ASUS boards with Secure Boot on by default; ASUS issued a BIOS patch. Leo advises turning off "recommended" updates.
- Lenovo Solutions Center had a flaw allowing arbitrary code execution with full privileges (fixed).
- Qualcomm netd (Android, 2011 code) had a local privilege-escalation issue patched in the May Android bulletin but unlikely to be fixed on Android 4.3 and older; FCC and FTC queried vendors about patching policy.
- GWX/Get Windows 10 update reappeared for some; Never10 users reported no issues; Microsoft's free upgrade deadline was July 29.
- Curl-bash attack variant: timing differences (e.g., a leading sleep command) let a server detect that a script is being executed rather than viewed, so inspecting by curl alone is not safe; download to a file, inspect it, then run it.
- A passenger's note to flight attendants led to an American Airlines flight being delayed because an economist was writing a differential equation.
- ResetPlug: a $60 smart plug that power-cycles a router/modem when connectivity drops; Steve notes hardware watchdog timers would be the clean fix.
- SmartThings research (University of Michigan and Microsoft Research): 55% of SmartApps were over-privileged, apps got full device access, sensitive events such as lock codes were poorly protected; demonstrated attacks included adding backdoor lock PINs, sniffing PINs, disabling vacation mode and triggering a fake fire alarm.
- ZigBee: the Trust Center Link Key is well known so a device can join and receive the network key; insecure rejoin lets an attacker trigger the network key to be sent; ZigBee 3.0 introduces per-device install codes; SmartThings promised an option to disable insecure rejoin; jamming of ZigBee can also go unreported.
- Steve's conclusion: not a SmartThings-only problem; avoid consumer ZigBee for door locks and alarms for now, expect hardware replacement later.
