# Summary

The episode opens with the show's 19th-year milestone and a Picture of the Week about a key hidden under a mat full of holes. Steve describes the "Sitting Ducks" DNS hijacking class (Eclypsium and Infoblox, about one million exploitable domains, 30,000+ hijacked since 2019), noting that Matthew Bryant described the same weakness in 2016 and that the fix is to avoid pointing a registrar at third-party nameservers where you no longer hold an account. Next is CVE-2024-38077 "MadLicense", a CVSS 9.8 pre-authentication remote code execution bug in the Windows Remote Desktop Licensing service, with about 170,000 exposed servers and a public proof of concept. Then AMD's "Sinkclose" flaw (IOActive, DEF CON), which lets code with kernel access reach System Management Mode and plant a bootkit that is extremely hard to remove. He covers Fortra's CVE-2024-6768, a reproducible Windows crash via the CLFS driver that Microsoft declined to fix. After an IsBootSecure? update (a real GUI, English Windows first), the main topic is certificate revocation: why revoked.grc.com suddenly started failing in browsers (OCSP stapling expiry after about six days), the history of CRLs, OCSP and stapling, and Let's Encrypt's intent to end OCSP in favour of CRLs consumed centrally by browsers.

# Key points

- Sitting Ducks: domains whose registrar points at a managed DNS provider where the zone was deleted or never verified can be claimed by anyone creating the zone; Rackspace said migrating correctly is the customer's job. Safe practice: set up DNS at the new provider first, then repoint registration; never leave nameservers pointing to a service you no longer use.
- Leo clarified his own setup (Hover registrar, Fastmail or Cloudflare DNS): the risk appears only if the DNS-hosting account disappears while registration still points to it.
- MadLicense (CVE-2024-38077): heap overflow in Windows Server RDL service, all versions from 2000 to 2025; patched in July Patch Tuesday although first rated "exploitation less likely". Advice: patch, or disable the service, and never expose Microsoft services directly to the Internet.
- Sinkclose (AMD): abuses the TClose memory remapping feature to run code in System Management Mode; affects chips back to about 2006; needs kernel access first; AMD released mitigations for EPYC and Ryzen with embedded to follow; researchers withheld proof-of-concept code for months.
- Windows CLFS bug CVE-2024-6768 (CVSS 6.8): malformed Base Log File metadata crashes the system; Fortra reported it in December 2023, Microsoft could not reproduce it, closed the case, then Defender began flagging the PoC; a later GitHub report suggested it could become privilege escalation.
- Steve contrasts Microsoft's refusal here with its Recall plans.
- IsBootSecure? now a GUI dialog showing BIOS vs UEFI, Secure Boot state and the Platform Key certificate; about 3,300 downloads; mailing to 8,145 listeners went out that morning.
- revoked.grc.com behaviour explained: the server stapled a valid seven-day OCSP response obtained before revocation, so browsers accepted it until the server refreshed its staple, after which browsers showed a revoked-certificate error.
- OCSP issues: privacy leak to the CA, slow or unreliable responders, browsers fail open; stapling and caching (typically seven days, GoDaddy four) are a compromise, and an attacker holding a stolen certificate can keep stapling the old good response.
- Let's Encrypt (about 60% of certificates) announced on 23 July 2024 its intent to end OCSP; CRLs were added in 2022 in 128 shards; CA/Browser Forum ballot SC-063 made OCSP optional (23 CAs for, 1 against; Google, Mozilla, Apple for). Microsoft's root program was the remaining holdout.
- Browser-summarised revocation lists (Mozilla CRLite using filters, Chrome CRLSets) are pushed to browsers; shorter certificate lifetimes (398 days now, 90 days for Let's Encrypt) keep lists small.
- Steve plans to blackhole DigiCert's OCSP host locally to see how browsers behave without stapling; both hosts expect fail-open.
