# Summary

After housekeeping about repaired podcast download links, Steve covers two big vulnerability stories. University researchers presented XARA attacks on Apple platforms, where a malicious sandboxed app that passed app store review can read other apps' data via keychain, inter-process channels, URL schemes or by claiming another app's bundle identifier, because apps lack mutual authentication; a very high share of scanned apps were exposed, Apple had been given months and said it had made a server-side store update, and Steve plans more coverage. The second concerns the Samsung-bundled keyboard (SwiftKey-licensed) on Galaxy S4 through S6 models, which fetched its language update over plain HTTP with an integrity hash also fetched in the clear, letting a network man in the middle run code as the system user; the keyboard cannot be removed. Steve then uses a security researcher's GPU benchmark to show LastPass password guessing is extremely slow for strong passwords, discusses the WebAssembly bytecode effort by Google, Apple, Microsoft and Mozilla, and notes the Let's Encrypt launch date of mid-September. Listener questions cover caching distortion in his measurements, how HTTPS hides URLs, sending sensitive data to non-technical recipients, whether to change a LastPass password, HSTS on a sold domain, IPv6 and NAT, buffer overflows, and whether LastPass truly satisfies Trust No One.

# Key points

- XARA research: cross-app resource access attacks on OS X and iOS exploited weaknesses in the Keychain, WebSocket, NSConnection, URL schemes and sandbox directory identifiers (bundle IDs); researchers scanned 1,612 OS X and 200 iOS apps and found 88.6 percent exposed. Chrome had removed iCloud keychain support. Apple had been notified in October 2014 and asked for delays; its statement said a server-side update was implemented to block apps with sandbox configuration issues from the Mac App Store with more fixes in progress. Steve notes that Apple apparently never told developers to add stronger authentication and that the fix may require coordinated changes.
- Samsung/SwiftKey: over 600 million devices potentially affected (Galaxy S4, S4 Mini, S5, S6 across carriers); NowSecure's Ryan Welton found the keyboard checks for language-pack updates over HTTP at restart or periodically; an attacker who can alter that traffic can inject code that runs with system privileges, with proof-of-concept code public. Cellular-only use avoids casual Wi-Fi attackers; a state-level actor could still intercept. Samsung said it had given patches to carriers, and a status page tracks fixes.
- LastPass math: Robert Graham tested a GPU on 100,000-iteration PBKDF2 and got about 2,577 guesses per second; Steve notes ASIC hardware reaches roughly 9,000 and that his Haystacks page uses the correct 95-character alphabet. Markov-chain and dictionary attacks make human-pattern passwords weaker, so use long random passwords.
- WebAssembly: Google, Apple, Microsoft and Mozilla joint plan for a compact binary format for browsers, initially aimed at C and C++, with claimed speedups; it follows asm.js and Native Client approaches.
- Let's Encrypt was scheduled to launch the week of 14 September 2015, with free automated domain-validated certificates.
- Miscellany: an Apple iTunes joke from a cryptographer, a Raspberry Pi PDP-8 kit order status, a puzzle game recommendation (Infinite Loop), science fiction series Dark Matter, Killjoys, Humans, and Mr. Robot's IMDb rating.
- Listener SpinRite story: an Irish CCTV technician recovered a recorder's drive so the owner could retrieve footage.
- Q: did cache effects distort the Firefox tracking numbers? Steve disabled caching and the researchers averaged ten cache-flushed runs.
- Q: HTTPS hides URL paths because the encrypted tunnel is established before the request; observers still see the destination host and IP.
- Q: for sending sensitive documents to non-technical recipients, Steve and Leo suggest a password-protected zip with the password shared by phone, since zip encryption is reasonably implemented.
- Q: a LastPass user with a long random master password, two-factor and a custom iteration count need not worry, according to Steve.
- Passenger-side break-ins from key-fob relays are explained by thieves targeting the glove box; antenna expert Spencer Webb showed a mylar shielding bag works only when its opening is folded over several times, since a Faraday shield is only as good as its smallest opening.
- Q: HSTS with a very long duration persists in browsers that visited; if a domain is sold, new owners are bound until expiry, so lower the value before transfer; the includeSubDomains option is optional.
- Q: IPv6 removes the need for NAT, but Steve expects home routers to keep filtering unsolicited traffic and translating for legacy IPv4 devices.
- Q: buffer overflows become exploits because the stack mixes return addresses and data; overwriting a return address lets an attacker choose where execution jumps, so crashes can be weaponised.
- Q: is LastPass truly Trust No One? Steve concedes strict TNO would require guess resistance of 2^256 and that any cloud system with a password-based pipeline is weaker; Leo argues LastPass is effectively TNO if the master password is strong.
